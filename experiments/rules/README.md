# 规则索引对照

`index_bench.cpp` 构造 16、512 和 4000 条交替域名后缀与 IPv4 `/24` 顶层谓词，另把每个谓词放在单子节点 `and` 内，以强制走表达式顺序求值；每种输入先逐项比较结果，再以混合命中/未命中的域名和地址执行 20,000 次匹配。各规模三轮、第二轮反转执行顺序；不计编译规则或解析配置。以根包的 `test-rules-bench` feature 构建 `rules-index-bench`，该功能只生成独立程序。

2026-10-31，本机 i9-13900H、GCC 16.2.1 release、CPU 4 绑核，各轮整数平均耗时（纳秒/次）：

| 条数 | 顶层索引 | 单子节点 AND 顺序解释 |
| --- | --- | --- |
| 16 | 104、109、106 | 110、112、111 |
| 512 | 161、167、166 | 1844、1846、1874 |
| 4000 | 187、193、189 | 13245、13425、13137 |

该对照使用固定 64 个域名/IP 组合和 `/24` 前缀，线性一侧每条规则多一层 AND，并非旧版本二进制；未隔离系统负载或频率，数据不代表所有规则组合、预判路径、并发、真实网络或尾延迟。它验证此合成工作量下的首命中结果和平均耗时，不能推断通用加速倍数或内存分配行为。

## 域名索引存储实验

`memory_bench.cpp` 构造 16、512、4000 条长域名、IPv4、混合或双子节点逻辑谓词，分别编译单个 `Matcher` 和每条一个谓词的 `RouteProgram`，源规则在编译前后仍保持存活。每次用独立进程采集 glibc `mallinfo2` 的已用堆与独立 mmap 字节之和；差值包含分配器分块、构建临时对象残留的线程缓存，不包含所有进程内存或峰值。构建使用 `test-rules-bench` release，数据在 `memory-before-2026-10-31.txt` 和 `memory-after-2026-10-31.txt`。

2026-10-31、本机 GCC 16.2.1/glibc 2.44，4000 条的编译前后差值（字节）：

| 布局 | 谓词 | 原始 | 索引借用文本 |
| --- | --- | ---: | ---: |
| Matcher | 长域名 | 1,109,056 | 786,224 |
| Matcher | IP | 529,296 | 529,296 |
| Matcher | 混合 | 820,352 | 659,824 |
| Matcher | 逻辑 | 1,968,912 | 1,968,912 |
| RouteProgram | 长域名 | 2,082,928 | 1,762,976 |
| RouteProgram | IP | 1,698,960 | 1,698,960 |
| RouteProgram | 混合 | 1,890,912 | 1,730,912 |
| RouteProgram | 逻辑 | 2,979,184 | 2,979,184 |

此布局不去重规则源或逻辑子节点，降低顶层域名索引重复字符串的成本。短字符串、其他分配器和规则分布的效果会不同。`index-domain-comparison-2026-10-31.txt` 是原程序与借用文本版本交错运行的单线程索引合成样本，频率波动明显，只证明固定输入结果一致，暂不能确定性能差异；须另用真实代理与更稳定负载验证。

## 动作程序共享谓词

`program_bench.cpp` 为每条指令构造一条交替的域名或 IPv4 谓词，包含命中和漏匹配，执行 4000 次 `next`；两版 checksum 均为 9,918,619。`program-comparison-2026-10-31.txt` 记录 CPU 4 交错前后样本，4000 条原布局约 50–75 微秒/次，共享布局约 22–28 微秒/次；频率波动明显，只代表此合成样本。共享布局让一组指令引用同一个 `Matcher` 的规则范围，短范围直接求值，长范围用索引寻找区间内的最早结果。不同来源、动作、规则序号及恢复游标仍由指令保存。动作程序尚未用于生产代理。

`memory-program-flat-2026-10-31.txt` 可与上节 `memory-after-2026-10-31.txt` 的 program 行比较。4000 条域名、IP、混合及逻辑规则的分配增量分别从 1,762,976、1,698,960、1,730,912、2,979,184 字节变为 951,568、694,640、825,152、2,134,144 字节，仍受上节列出的分配器测量限制约束。这不测加载峰值、不同指令组大小、连续动作或真实网络。

## 真实代理负载

`cli-512-2026-10-31.jsonl` 和 `cli-4000-2026-10-31.jsonl` 使用 `compare_cli.py --rule-count`，真实组合 release，两个 SOCKS TCP、两个 SS UDP、固定 sing-box revision，在隔离网络命名空间的回环上以 400 请求/秒运行 hot、uniform、disjoint、expiry 四场景，正反顺序各一轮，每个样本测量 4 秒。规则集的前 64 条覆盖部分实际域名，其余为不匹配的长域名；动作均为 direct。四场景每版各 12,800 请求，512 和 4000 两种规模总计 51,200 个均完成且无漏投。512 条原版与新版每样本代理 CPU ticks 分别为 12–18、13–19；4000 条分别为 14–22、13–23；TCP0 服务时间 P99 分别为 1089–1777 与 1150–1545 微秒（512），1026–2115 与 1047–1522 微秒（4000）。进程 RSS 范围见原始数据，受解析、分配器与网络缓存影响；不能将差值归因于某个对象。此短时同机低负载对照没有观察到稳定的大幅 CPU 回退，不能证明跨机、高并发、各种规则或尾延迟无回退。

## 紧凑节点实验

两种 `std::variant` 原型的数据保留在 `memory-entry-compact-2026-10-31.txt`、`memory-entry-tagged-2026-10-31.txt` 和对应 `entry-*-comparison` 中；单标记方案的顺序逻辑样本明显变慢，因此没有采用。当前试验把节点的 IP、端口、网络和逻辑范围放入平凡联合体，域名字符串仍直接持有；逻辑子节点编号存到整个 Matcher 的连续数组。编号窄化依靠 16,384 节点上限，编译期断言限制及最大节点测试检查边界；复制时复制数组并重新绑定域名索引。

在 4000 条样本中，相对动作共享后的布局，`memory-entry-arena-2026-10-31.txt` 的 Matcher 长域名/IP/混合/逻辑分配差值由 786,224/529,296/659,824/1,968,912 字节变为 657,296/400,288/530,816/1,331,520 字节；空 Matcher 固定大小增加 24 字节。`entry-arena-comparison-2026-10-31.txt` 的交错合成测试没有显示稳定的大幅回退，但 CPU 频率波动明显，仅用于筛选方案，不替代真实网络性能验证。`mallinfo2` 及样本的限制同上。

最终节点布局又以相同方式与前一组合程序做了真实代理对照：`cli-arena-512-2026-10-31.jsonl` 和 `cli-arena-4000-2026-10-31.jsonl`。4000 条时，两版各 12,800 个请求均完成、无漏投，代理 CPU 每样本为 12–22 与 14–19 ticks，TCP0 服务 P99 分别为 969–2238 与 1097–1570 微秒。512 条时旧版完成 12,800，新版完成 12,776，另外 24 个因驱动调度延迟未投放；已投放请求均完成。`cli-arena-512-hot-repeat-2026-10-31.jsonl` 是该热点场景正反顺序额外两轮，两版各 3200 个请求均完成且无漏投，CPU 每样本为旧版 14–15、新版 15 ticks。保留首次漏投结果，不能用复测擦除。以上仍为同机低负载和有限场景，不证明所有规则路径无性能回退。

## 集中域名存储

另一试验将节点域名放在预留的字符串数组，节点通过 `string_view` 借用；复制整个 matcher 时重绑视图，匹配不增加分配。前期用窄索引的版本在顺序样本慢约一成以上，未采用；两种原始样本保存在 `memory-domain-pool-2026-10-31.txt`、`domain-pool-comparison-2026-10-31.txt` 及带 `-view-` 的对应文件。直接视图版在 4000 条长域名/IP/混合/双子逻辑 Matcher 样本的分配增量分别为 650,208/265,136/459,744/871,312 字节；前版分别为 657,296/400,288/530,816/1,331,520 字节。它增加 24 字节 Matcher 固定大小，域名全为长字符串时收益很小；仍适用前述 glibc 计量限制。顺序和索引合成样本存在频率波动，不能据此确定普遍性能。

最终组合程序与前版的真实 CLI 对照分别记录在 `cli-domain-pool-512-2026-10-31.jsonl`、`cli-domain-pool-4000-2026-10-31.jsonl`。前者旧版/新版分别完成 12,784/12,800 个请求，漏投 16/0，CPU 每样本为 14–18/13–19 ticks；后者完成 12,728/12,792，漏投 72/8，CPU 为 14–20/13–19 ticks。所有已投放请求均完成。另以 `--logical-rules` 将 4000 条域名后缀各包入与端口范围的 AND，测顺序表达式路径：`cli-domain-pool-logical-4000-2026-10-31.jsonl` 的两版各 12,800 次全部完成，无漏投，CPU 为 13–29/15–27 ticks。每版均为四场景正反各一轮、同机 4 秒 400 请求/秒，两个 TCP 和两个 SS UDP；测试程序、进程和网络调度并未隔离。新程序同时包含新增规则类型，但这些负载只使用既有域名和逻辑类型。样本不能证明所有规则分布、负载、硬件或尾延迟没有回退。
