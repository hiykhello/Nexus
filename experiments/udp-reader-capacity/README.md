# SOCKS UDP 空闲关联资源基线

`baseline.py` 对同一二进制分别配置 0、1、4、16 个未使用的 SS UoT 代理出站。当前生产代理出站总上限为 16（`Server::add_tunnel_outbound`）；不增加任何公开配置项。每个出站由不同目标端口规则合法引用，实际测试仅访问本地随机高端口，匹配 direct。受控代理监听器必须从未收到连接。

每个配置只有一个 worker，依次记录零关联、16 个活动关联和关闭全部控制连接后三个状态。每个关联仅发送一次 UDP 请求并验证 direct 往返；每个状态观察 1.25 秒空闲 CPU ticks。脚本读取进程 `/proc/<pid>/smaps_rollup` 的 RSS/Anonymous/PSS 与 private 页面数、`stat` 的 user/system ticks 和线程数、`fd` 的文件描述符数。关闭控制 socket 后，FD 数必须在五秒内回到零关联基线并在最终观察期间保持。RSS 不要求回落，因为分配器可能保留已释放内存。

```sh
python3 experiments/udp-reader-capacity/baseline.py \
  target/continuation-20261111/datagram-bin/nexus \
  --output target/continuation-20261111/udp-reader-capacity-before.jsonl
```

后续对新二进制使用同样参数和另一个 `--output` 路径复测。输出文件独占创建，避免覆盖旧证据；每行含二进制与驱动 SHA256、完整配置和摘要、关联数、两个采样时刻、原始计数及实际观察时长。动态端口与临时密钥文件路径可能不同，其余语义输入保持一致。固定测试密钥仅供本地实验。

可指定 `--associations 32`，以及 1–2 秒的 `--idle-seconds`；`--outbounds` 仅允许 0–16。默认配置每种仅执行一轮，不作吞吐测试。结果是当前进程在本机的轻量观察，不能精确分解协程帧大小、证明单个出站的内存成本或宣称性能/容量上限；页粒度、分配器、启动历史和其他系统负载都会影响数值。

## 2026-11-11 基线

上述命令退出 0。原始记录在 `target/continuation-20261111/udp-reader-capacity-before.jsonl`，运行日志同名 `.log`。每场 16 个 direct 关联，实际空闲观察约 1.251 秒，`SC_CLK_TCK=100`。下表内存取观察结束时的值。

| 未使用代理出站 | 零关联 RSS / Anonymous KiB | 16 关联 RSS / Anonymous KiB | 活动期 CPU ticks | FD 零 / 活动 / 关闭 |
| --- | --- | --- | --- | --- |
| 0 | 9376 / 516 | 12368 / 3156 | 11 | 8 / 56 / 8 |
| 1 | 9920 / 520 | 13028 / 3372 | 14 | 8 / 56 / 8 |
| 4 | 10952 / 1460 | 14092 / 4408 | 23 | 8 / 56 / 8 |
| 16 | 11076 / 1508 | 17360 / 7600 | 64 | 8 / 56 / 8 |

四场代理监听均未收到连接，控制连接关闭后 FD 均恢复基线。该轮中，未使用出站较多的配置伴随更多活动期匿名内存和空闲 CPU ticks；单轮观察仅为后续实现提供对照，尚不能把差异归因为某个帧或计算稳定性能比例。

## 按需启动 reader 后的同输入观察

对 `target/continuation-20261111/lazy-bin/nexus` 使用同一脚本、16 关联、0/1/4/16 出站和 1.25 秒观察参数，输出 `target/continuation-20261111/udp-reader-capacity-after.jsonl` 和同名 `.log`，退出 0。前后驱动 SHA256 相同；after 二进制为 `ba37805109e49c5ba354ed5d4ee0baa8f695726297a6260d48e63850509a1ff7`。本轮测量期间没有另开编译或网络检查。

| 未使用代理出站 | 活动 RSS KiB，前 → 后 | 活动 Anonymous KiB，前 → 后 | 1.25 秒活动 CPU ticks，前 → 后 | FD 零 / 活动 / 关闭，前后相同 |
| --- | --- | --- | --- | --- |
| 0 | 12368 → 12524 | 3156 → 3152 | 11 → 4 | 8 / 56 / 8 |
| 1 | 13028 → 12824 | 3372 → 3156 | 14 → 6 | 8 / 56 / 8 |
| 4 | 14092 → 12520 | 4408 → 3160 | 23 → 5 | 8 / 56 / 8 |
| 16 | 17360 → 12636 | 7600 → 3184 | 64 → 5 | 8 / 56 / 8 |

after 的四场 unused 代理仍没有连接，关闭控制连接后 FD 均恢复。零出站场景同样保留 dispatcher/event 等固定管理成本：本轮 active RSS 增加 156 KiB、Anonymous 减少 4 KiB；进程页统计不能单独分解新事件对象的成本，也不能将 RSS 差异全归因于它。零出站 CPU ticks 亦从 11 降至 4，提示前后单轮采样受负载/调度影响，不应将高出站场景的 tick 比值直接称作确定加速比。此次数据与“未使用 reader 不再逐出站预启动/轮询”的预期一致，尚未测量真实代理活动时的成本、完整容量上限或吞吐性能。
