# 前台与后台 DNS 任务的统一登记：实验设计

当前前台 `FlightGroup` 与后台 `RefreshBudget` 分别限制工作量。即使两者各自有界，也不保证进程级网络任务总数不超过某个共同额度；stale 失效后，仍在进行的后台刷新和新的前台 miss 还可能同时查询同一上游。本文只规定下一步实验的行为，不代表已实现或已启用的功能。

## 事务与键

一份不可变配置代次拥有协调器，并先于它所借用的缓存、执行器及任务停止；老代次取消排空后才销毁。可共享的事务键必须包括规范化名称、A/AAAA 类型、完整 DNS view、上游数值地址与端口、TCP/UDP 和 EDNS 选项，以及缓存政策。`view` 不能只由调用方随意编号；其来源必须保证所有影响应答的配置进入身份。明确禁用缓存时维持独立查询语义，不按键合并，但占同一网络任务配额。不同配置代次、view、目标上游和协议选项不共享。

目前代理使用 `server_index+1`，它只在共享缓存的各调用方使用同一 DNS 路由时有效；两个配置的同序号可以指向不同上游。事务键再比较 endpoint 无法补救此前的缓存命中。独立实验 `ViewRegistry` 在配置封存前按规范化后的完整解析链和策略去重，查询时再将实际数值 endpoint（包括 IPv6 scope）纳入身份，分配代次内不复用的整数 view；配置变更使用新 registry。策略数量、策略数据与 endpoint 映射数分别限额，耗尽时不得退回复用别的 view。映射不删除：否则旧缓存节点、慢读者或在途事务可能仍携带被复用的 ID；代次内大量上游地址变化会逐步耗尽额度，这种过载及内存成本仍待评估。该原型尚未绑定生产配置，也未覆盖未来新增的 DNS 语义字段。

后台刷新在 stale 答复仍可用时尽力登记一个有界任务；同键事务已运行、受退避或满额时，stale 请求立即返回旧值，不另外启动查询。若 stale 随后到期而刷新仍在途，前台请求可加入该事务并按自己的截止和取消等待。前台请求先启动时，后来遇到 stale 的请求直接返回 stale，后台不得启动相同事务。上游零 TTL 或缺少负 TTL 的答复只给已登记等待者，不供事务完成后的新请求使用。

## 所有权与停止

协调器以单一所有权持有稳定地址的事务；前台协程持有各自的侵入式等待节点，网络 owner 在其 executor 上拥有协程和 resolver。后台刷新注册一个后台意愿，但不伪造用户等待者。每个真实调用拥有独立 deadline；一个等待者取消或超时不得取消其他等待者的事务。若最后等待者离开但刷新意愿仍有效，后台任务继续到自己的截止；若刷新意愿已结束且没有等待者，标记取消并唤醒网络 owner。协程最后完成和所有借用者摘除后才销毁事务；无论提前取消、缓存令牌失效还是 owner 正在排空，名额只在任务实际结束后归还。

停止时禁止新登记，先在各执行器取消其调用及网络 owner，然后在对应执行器排空，最后销毁缓存、协调器和上下文。不得跨线程直接取消不支持跨线程取消的 timer；跨执行器通知必须验证所用 waker 的线程契约及 executor 生存期。单 owner 停止时，它拥有的网络任务取消并完成等待者；其他 executor 可在旧任务确实排空后重新登记。不能通过 `shared_ptr` 掩盖这些顺序。

## 发布、容量与锁

前台与后台都由相同事务负责一次缓存登记及发布；注册后重查缓存，关闭首次 miss 与其他事务填充之间的竞态。正负 TTL 以取得时刻为基础的绝对期限传递，锁等待不延长 TTL；晚恢复等待者若已过期，在自身原 deadline 内重新查询。旧配置、旧 revision、被淘汰记录及被取消事务不得发布。失败的缓存登记不丢弃网络结果，除非缓存实现为维护一致性关闭读取；失败答复的退避必须有界。

共同额度计入仍排空的网络事务以及未合并直通查询。完成后的答复若仍有慢等待者，另需有界的 retained 事务和等待者限额；两者不能被描述为网络任务数。后台与前台可有独立子配额或预留，但子配额相加必须受总量约束，满额不启动无界旁路。是否预留前台容量、满额返回错误还是排队、退避及公平策略尚未确定。缓存内存预算是另一约束，调用者、协程、消息、副本和内核 socket 内存不在快照预算中。

协调器完成与 waiter 摘除在同一锁内序列化。不能在持有协调器锁时随意调用可能重入协调器的缓存或唤醒回调；如需先验证令牌再发布，必须证明发布与最后等待者取消/停止之间的顺序，或设计明确的发布阶段和跨锁协议。当前实验在 group 锁内调用缓存发布，缓存不反向获取 group 锁；此限制、最坏持锁时间和异常安全仍需单独审查，不能假设以后所有调用都满足。

## 验证门槛

至少使用两个真实 executor 与 epoll/io_uring、真实 UDP 和 TCP DNS 对端，覆盖刷新先行后前台加入、前台先行后 stale 返回、不同 view/上游/选项隔离、后台超时、每个前台独立取消/期限、最后等待者、持有等待者时 owner 停止、配置重载与迟到回复、缓存满/分配故障、正负/零 TTL 和慢等待者。用 barrier 定点构造完成、取消、最后等待者摘除和停止的竞争，检查每个事务及总许可精确释放；保留失败、漏投和排空时限。再做完整插桩范围明确的 TSan、ASan/UBSan、启动/停止故障、最大 socket/协程/答复副本内存以及真实 SOCKS 与 SS UDP 代理负载。性能须与现有路径进行相同配置和可复现的固定投放对照；若有漏投，不能只比较成功请求的延迟。
