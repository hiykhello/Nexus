# 平台抽象与宿主集成

状态：Nexus 平台层设计规范，核心原则见 [核心架构原则](../design-principles/core-architecture.md)，Linux 专项见 [Linux 网络集成](linux/networking.md)，四端 OS 原语边界见 [跨平台 OS 边界矩阵](cross-platform-os-boundaries.md)。

## 三种不同边界

Corosio 的运行时适配负责异步 I/O、执行器、取消和句柄登记；平台后端负责 OS 特有的资源操作与环境观测；宿主适配负责嵌入程序提供的设备、权限和事件。这三层可以组合，不能都堆进一个 Platform 对象。

通用代理协议、自研 TCP/IP 和 TLS 状态机不 import Linux、Windows 或宿主 UI 类型。协议表达需要的能力，例如绑定出口或获取包设备，由装配选择原生后端或宿主提供者。首期优先研究 Linux，其他平台仅保留设计边界，不宣称支持。

## 按能力划分

| 能力边界草案 | 输出及责任 | 不承担的职责 |
| --- | --- | --- |
| socket 策略 | 出口绑定、保护/绕行、mark、原始目标/辅助数据与受控原生操作 | 业务域名路由与协议认证 |
| 网络观测 | 接口、地址、默认路径、网络代次与订阅 | 自动给每个连接决定代理出口 |
| 包设备 | 打开/接收宿主 TUN，MTU、多队列与卸载元信息 | TCP/IP 状态机与业务分流 |
| 宿主网络管理 | 路由、DNS、防火墙变更计划和租约/补偿 | 保证跨系统调用的全局原子事务 |
| 系统解析环境 | 系统 resolver、链路域与变化通知 | 普通 DNS 缓存与乐观刷新 |
| 连接归属观测 | 受权限限制的进程/用户信息及来源 | 将未知结果猜测为默认可信身份 |
| 凭据与目录 | 信任根、系统秘密设施、状态/缓存目录位置 | 暴露操作系统对象给协议热路径 |
| 服务与宿主通知 | 就绪、停止、权限交互及可选通知适配 | 在协议实现中弹 UI 或直接发送系统通知 |

系统随机数由密码适配边界明确管理，不同时存在几个来源不清的随机服务。BoringSSL libcrypto 已按[决策 0007](../decisions/0007-boringssl-libcrypto-and-ktls.md)选为密码底座，具体平台构建与原语覆盖仍需验证。

## 能力、权限与失败

能力描述同时区分编译启用、OS 支持、运行权限、宿主已提供以及当前可用状态。缺失可选优化可以按明确策略退回普通路径；用户要求的透明接管、出口隔离或 DNS 设置不可静默失效。

结果用 expected 表达失败，正常缺少观测值用 optional；例如无进程信息不同于系统接口错误，权限不足不同于不支持。平台错误带操作与阶段，映射到公共类别，原生错误码保留作诊断，不泄漏到每个协议分支。

能力发现结果可能变化：权限撤销、设备移除、宿主暂停都不是永久静态布尔值。组件声明必须能力，启动和实际使用时分别检查；并发变更仍需处理操作失败。

## 句柄与异步所有权

宿主交付设备或 socket 时声明转移、借用还是复制，并确定关闭、取消、nonblocking、队列和线程亲和性。核心不随意关闭借用句柄；需接管时先通过明确协议转换。包装一个 FD 不等于可以同时让 Corosio 与宿主事件循环读取它。

原生句柄只在平台/运行时适配边界访问，公共协议接口使用流、包设备或带所有权的能力对象。不能用统一 int 表示所有 OS 句柄，也不能让异步调用借用已经返回的栈参数。

对只能在专用线程操作的 namespace/宿主 API，由平台后端执行受控任务；不能切换执行器线程的网络 namespace 后直接挂起协程，让其他任务在错误环境运行。阻塞文件/系统管理任务走有界工作队列，超时后仍在执行的任务继续计入预算并跟踪清理。

## 事件与配置一致性

网络观测以版本化快照和变化事件提供，回调先转交指定执行器，再更新 DNS 视图、连接器和路由观察状态。避免从 OS/宿主回调线程重入核心；订阅对象关闭后不得继续访问已销毁的组件。

事件队列有界，允许合并可合并状态；检测丢失后重新获取快照，不能假设事件流永不丢失。一次网络切换只对受影响视图推进代次；旧查询/拨号完成后检查环境，不把结果发布到新视图。

系统配置采用探测、计划、准备、应用、核对和补偿阶段，返回拥有资源的租约/操作记录。设备与全局设置的唯一 owner 明确，释放只回收自身对象；SIGKILL 后仍可能残留的资源进入[恢复清单](../architecture/state-and-cache.md)。

## 原生程序与宿主托管

原生 Linux 模式可以由 Nexus 管理 TUN、路由、nftables 和 resolved 链路设置；宿主托管模式可以只提供包设备与网络信息，核心不再重复改宿主网络。谁负责什么必须可诊断，不能发现某个 FD 就推断剩余所有管理都由宿主完成。

若未来嵌入 UI、移动 VPN 或其他进程，边界使用显式、版本化的值类型和资源令牌；跨语言/进程不导出 proxy 对象、C++ 标准库对象或 Modules 内部类型。消息取消、事件线程、宿主断开与设备撤销另有协议；当前不提前创建 FFI 或特权管理进程。

Linux 的 nftables、NFQUEUE、策略路由与 systemd 仍留在对应后端/服务层。是否分离特权进程待验证，不为普通代理模式要求宿主网络管理权限。其他平台以后分别确认原生和宿主路径，避免大量平台条件进入每种代理协议。

Linux、Windows 和 macOS 的 TUN 接管、防环回与恢复机制分别见[跨平台专题](tun-routing-and-loopback.md)；平台能力缺失不能静默降级成会自环的接管。

## 模块与验证

建议 `nexus.platform` 提供窄能力契约/公共值类型，`nexus.platform.linux` 等实现后端，由 app 选择并注入；运行时边界与 `nexus.runtime` 协作，禁止二者反向循环导入。契约使用最小基础异步类型或经验证的返回类型；具体放置在依赖图验证后决定。

先实现内存/假平台，验证无真实权限时协议、路由、DNS 与网络栈核心可独立运行；随后逐项替换真实后端。验收覆盖：

- 平台缺失、权限不足、宿主拒绝及优化降级得到不同诊断。
- 借用/转移句柄各自只关闭一次，在途取消、设备撤销和停止后无残留访问。
- 网络事件重排、合并、丢失与订阅销毁可恢复，不跨回调线程错误访问状态。
- namespace/线程亲和操作不污染其他任务，阻塞队列和超时残留工作保持有界。
- 实例启动失败、宿主退出与崩溃后按所有权核对和清理，不删除其他服务资源。
- 编译依赖图确保协议核心没有平台后端导入；替换假/原生/宿主提供者不修改协议代码。

真实 Linux 行为还需通过 [验证体系与实机基线](../planning/validation.md#3-linux-系统集成验证)，不以抽象层单元测试代替接管、返回路径与服务停止验证。
