# 缓存与持久状态

Linux CLI 已接入四层持久化存储（selector、FakeIP 段预留 + WAL、多视图 DNS 缓存与规则集内容寻址缓存）。见 [配置规范](../configuration/spec.md)、[原生控制面](control-api.md) 与 [路由、DNS 与状态原则](../design-principles/routing-dns-and-state.md)。

具体对象、丢失后果、当前实现状态和选型次序见[持久化对象清单](persistence-inventory.md)。SS-2022 跨重启防重放是额外安全承诺，不是通用缓存的代表性负载。

## 按丢失代价分类

| 状态 | 权威来源与用途 | 保存及恢复草案 |
| --- | --- | --- |
| 路由结果、健康观测、连接池 | 当前配置、网络及实时探测 | 默认只在内存；按依赖代次失效，不从磁盘恢复为“仍健康” |
| DNS 应答 | 上游响应和本地策略 | 可选磁盘缓存；恢复保留原有效期与视图身份，具体见 [DNS](dns.md) |
| 远程规则内容 | 指定来源、格式及校验策略 | 可重建磁盘缓存，记录源身份、版本、内容校验和更新元数据；过期/离线使用需明确政策 |
| 用户显式选择 | 用户操作 | 与自动选择分开；持久失败必须返回，恢复后验证成员仍有效 |
| FakeIP 映射与分配元数据 | 已向客户端发布的地址归属 | 作为影响正确性的状态单独处理；范围、owner、游标、双向映射一起验证 |
| Linux 网络恢复清单 | 实例拥有的宿主网络对象 | 用于核对与补偿，实际内核状态仍需探测；不能当普通缓存随意丢弃 |
| TLS 票据、密钥等敏感材料 | 协议与凭据管理 | 单独评估；本设计不默认持久化会话秘密，也不与普通缓存混存 |

配置仍是声明式基线。动态选择作为有版本的覆盖层，不能反写 KDL；清缓存操作不得顺带抹掉用户选择、FakeIP 或网络恢复记录。磁盘缓存与持久状态应有不同清理入口；物理上是否分文件，待存储选型时验证故障隔离效果。

## 所有权与接口

每个部署实例具有稳定身份；同一逻辑存储由一个写入者拥有，锁文件保持稳定，不能只锁会被 rename 替换的快照 inode。组件重建时由实例级 owner 管理存储，避免候选与当前组件争抢同一文件。热重载是否实现仍待决定。

按缓存/状态能力定义窄接口，持久层负责事务、同步、配额与错误，不负责 DNS TTL 或路由策略。协议层验证语义，再发布不可变值或受控共享值；禁止缓存借用已结束事务的内存。

正常未命中用 optional；磁盘读取同时可能失败时用 expected 包裹 optional。错误携带状态类别、实例、操作阶段和提交结果。采用尽量无异常规范；不把序列化、磁盘或后台任务失败压成统一的“未命中”而丢失诊断。

## 写入语义

区分四个状态：已接受、读取可见、逻辑提交、持久性已确认。同步到介质的承诺还受 OS、文件系统及设备能力限制，按平台验证后说明。

- 可丢弃缓存允许异步合并，失败可放弃该批并计数；接口只承诺接受，不能宣称落盘成功。
- 用户显式选择若声明持久成功，则先完成保存再发布生效状态。失败报告是否已替换，允许使用请求身份和 revision 重试，避免让用户误以为错误意味着磁盘未变。
- FakeIP 的持久模式先确定崩溃承诺：可选每映射提交，或先提交地址段预留再异步 checkpoint。两者对延迟、写放大和丢失映射的保证不同，不预先冻结方案。
- 网络恢复清单与内核修改是跨系统步骤，需要操作阶段、意图与核对，不宣称文件事务可以原子提交 nftables、路由与 DNS。

若选文件快照，候选流程为同目录排他创建私有临时文件、编码并同步、原子替换、同步父目录。rename 的原子可见性与断电持久性是不同保证；替换后同步失败应标记结果不确定。若选数据库，分别验证事务、同步选项、锁、损坏恢复、压缩及依赖成本。SQLite 是[状态数据库设计](database.md)中的待验证候选，尚未选择或接入存储依赖。

## 批写与资源预算

允许同键合并，按字节、条目、最长等待时间与关闭期限触发提交；另设队列硬预算。将 pending、正在写入的批次、序列化副本、数据库工作集和清理峰值一起计量，不能以 payload 字节或 flush 阈值代替总内存限额。

达到硬预算时，可丢弃缓存允许丢弃/跳过保存；用户选择需要背压或明确失败；FakeIP 不得以“持久模式成功”应答尚未达到自身崩溃承诺的分配。文件 I/O 不在网络执行器上阻塞，工作任务、等待者和重试也要有界。请求取消或超时后，已发出的写入可能继续，必须跟踪完成并保持 buffer、锁与配额寿命。

停止流程先关闭写入入口，再按期限排空或报告丢弃；后台写入结束后才关闭数据库/锁。同步要求放在显式停止操作，析构与 RAII 承担资源回收，不能在无法报告错误的析构中伪造可靠提交。

## 失效、版本与损坏

磁盘记录包含格式版本、实例/逻辑 owner、数据类别、语义指纹及所需时间元数据。进程内 generation 适合隔离在途任务，但不能单独作为重启后复用依据；重启恢复使用稳定且版本化的语义身份，不能保存裸指针、ABI 布局或 Modules 产物。

清空/切换视图时同时推进 epoch，旧在途结果、writing 批次与后台刷新不得在清空后重新发布。删除 tombstone 和新值按 revision 排序，防止失败批次重试覆盖更新数据。过期判断由读取路径负责，后台 GC 只负责空间回收；磁盘压缩与条目删除分别测量。

可重建缓存损坏可隔离并冷启动，记录原因；用户状态、FakeIP 与恢复清单损坏保留证据并停止依赖它的能力，要求明确迁移/重置。未知版本不可静默覆盖。读取长度、条目数、字符串和解码工作量均有上限；迁移失败保留旧版本，回滚与降级需有独立策略。

## FakeIP 的特殊约束

FakeIP 是客户端持有的名字引用。DNS TTL 到期不证明客户端已不再使用该地址；LRU 淘汰也不能证明立即复用安全。要声明复用周期、旧连接 pin、地址隔离/预留及无法恢复时的行为，不能保证无限期防止客户端使用任意历史地址。

恢复时同时检查配置范围、排除地址、地址族、owner、容量、游标与双向唯一性。未知池内地址返回明确失败，不猜测为直连目标；普通 DNS 的 IP → 域名观测不能填补丢失的 FakeIP 归属。范围改变、容量缩小及 owner 更换需显式迁移或重置。

段预留可以避免崩溃后立即重用尚未 checkpoint 的地址，但不能保证这些地址仍可反查。若产品要求每个已应答地址可恢复，则需要逐映射持久提交或等价机制；这项保证与性能指标一起决定。

## 目录与诊断

Linux 建议将可丢弃磁盘缓存放入 `/var/cache/nexus/` 的实例目录，持久状态放入 `/var/lib/nexus/`，临时锁/运行信息按语义使用 `/run/nexus/`；替换快照所需的稳定存储锁不能仅因叫“锁”就跨重启丢失所有权设计。用户模式采用对应的用户目录，具体规则待 CLI 设计。

目录权限、私有文件、符号链接、属主、多实例冲突和离线清理范围需验证。DNS 域名、规则来源和用户偏好默认不逐条记录到日志，诊断以类别、revision、条目数、占用、待写字节、最老待写时间、最近成功提交和错误阶段为主。

验证见[DNS 与状态验证](../planning/dns-state-validation.md)，宿主网络恢复见[Linux 设计](../platform/linux/networking.md)。
