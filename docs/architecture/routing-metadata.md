# 路由元数据、反查与嗅探

状态：设计与验收计划。生产路径支持显式目标域名、候选 IP、端口和 TCP/UDP，以及来源地址/端口、入站名称和已认证的 SOCKS/VLESS 命名用户；缺失字段保持 unknown。FakeIP 仅在测试功能图中，普通 DNS 反向映射、嗅探和有序动作尚未接入生产；无 I/O 的有序动作核心及 HTTP/1 Host、TLS ClientHello/SNI 嗅探器已有局部测试，均未连接网络运行时。本文不把计划中的功能当作已有行为。

有序流量匹配前先还原 FakeIP，普通 IP 可按视图查 DNS 反向映射；规则动作中 `sniff` 和 `resolve` 继续扫描，route、reject 等终止扫描。DNS exchange 成功后为非 FakeIP 的 A/AAAA 答复按记录 TTL 建立受限 IP→域名反向缓存；嗅探区分流和数据报并跳过服务端先发协议。相关工程原则见 [路由、DNS 与状态原则](../design-principles/routing-dns-and-state.md)。

## 一次请求的状态

各入站适配为同一请求上下文，原始目标、源、网络、端口、入站和用户在整个请求中不可变；域名、地址列表、嗅探结果、规则选项和最终动作是分阶段产生的独立字段。域名标记来源：显式目标、FakeIP、DNS 反查或嗅探；记录实际 DNS 视图/代次、过期时间及是否来自不可信流量。不能用可变的单一域名字段覆盖原始目标，也不能把嗅探名称视为已认证身份。

1. 捕获原始目标及拥有它的会话、配置和 DNS 视图。目标落在 FakeIP 池时先查对应映射并固定 lease，缺失则拒绝；原地址仍可用于诊断，但不能直接发送或作为真实 IP 检查。池外 IP 可按配置查普通 DNS 反向映射；无结果或有歧义时域名未知。
2. 按配置顺序执行规则。条件对当前可用字段求值，动作明确分为继续（嗅探、解析、设置选项）和终止（选出口、拒绝等）。未知条件不得因 NOT 变成真；阶段结果变化后不能复用依赖旧元数据的匹配缓存。首个终止动作决定出口，继续动作只影响其后的规则。当前已有的规则集引用保持其语义，不擅自改变旧配置。
3. 嗅探通过独立协议解析器填充元数据；解析动作取得具体地址及视图，供后续规则使用。未显式请求时不额外执行嗅探或主动 PTR 查询。默认使用 `metadata-only`：原真实 IP 继续是连接目标；通过单独、显式配置才能将嗅探域名用于重新解析和替换目标。对替换后的每个真实候选地址重新执行应有的访问策略，保持原目标以供回包、诊断和 UDP 会话归属。
4. 对选中的出口建立连接或数据报通路。嗅探中已消费的流字节或完整数据报先按原顺序交给转发，再接入后续输入；发送地址、帧边界、半关闭、取消和排空不受嗅探改变。直到所有使用这些借用的方向排空，保持上下文、缓存、lease 和配置代次有效。

域名来源可能冲突。策略由显式配置决定可用于域名条件的来源，并对同一个请求固定；缺省沿用现有显式目标行为。显式目标、FakeIP、反查和嗅探均保留独立值及来源，不将同 IP 多个名称当成可靠身份，绝不静默改变既有路由语义。

## 条件组合的兼容边界

在常见外部规则集格式中，单条默认规则通常将源地址、源端口、目标地址和目标端口分别分组（组内任一命中、组间共同约束，目标域名与目标 CIDR 同属目标地址组），再由逻辑规则显式表达 AND/OR/invert。

Nexus 现有 v1/v2 规则文件的顶层谓词是顺序 OR，跨类型 AND 必须显式写成 v2 `and`。例如 `domain` 和 `ip-cidr` 两个顶层节点不是交集；需要交集时须放在同一个 `and` 内。外部格式导入转换时显式保留上述分组和规则集合并语义，并用混合域名/IP、端口范围、嵌套逻辑与三态 `unknown` 差分验证，不改变已有 KDL/BEVE 文件的含义。

## DNS 规则与流量规则的关系

独立 DNS 规则扫描与流量路由分离：可先修改查询选项、选择传输或返回拒绝/预定义答复，并支持按命名答复评估后续条件。这些机制严格独立于流量路由规则。

Nexus 的 DNS 策略应使用独立的类型化上下文和动作，至少区分问题名、查询类型、入站/请求来源、传输、响应状态与地址；请求条件和响应条件分别在取得答复前后求值。每一步固定实际选择的 DNS 视图、地址策略、超时及缓存选项，缓存键与合并键必须包含影响答复或共享安全性的参数。最终流量策略使用同一次解析得到的实际候选地址；禁止策略根据一个上游答案判断、却静默用另一视图的地址拨号。上游 DNS 所需连接的解析和路由需要显式 bootstrap 路径与循环检测，不能依赖无界的 DNS→出站→DNS 递归。

当前 Nexus 的 DNS 后缀选择、local 配置及共享缓存已经在生产路径，完整 DNS 规则、响应匹配、预定义答复、竞速和这些动作的配置尚未实现。先定义顺序语义、期限和失败/取消，再逐项实现与验证；多上游并发需明确胜出条件、晚答复隔离、等待者取消和对反查/缓存的发布规则，不能默认把不同策略的查询合并。

## 普通 DNS 反向映射

这是被动观察已被 Nexus 接受的 DNS 答复，并非 DNS PTR 查询，也不是 FakeIP 分配表。其写入应发生在答复已通过来源、视图、代次和语义校验之后，包括缓存命中返回的有效答复；旧代在途任务不得写入新代。选择与目标适用的 DNS 视图；不同视图或代次的结果不共享。以答复实际有效期为上限，考虑 CNAME 链以及剩余 TTL；零 TTL、过期、负答复和无法安全关联的记录不建立映射。现有 `dns::AddressAnswer` 提供原始至规范名的完整链、地址和链与地址记录的最小 TTL；反查仍须决定将原问题名或规范名暴露给规则，并验证缓存返回的剩余 TTL，尤其不能把乐观 stale 的短 TTL 当成新鲜认证。

同一 IP 常被多个域名、客户端或上游共享，单个最近名称无法证明请求身份。必须显式选择有界的歧义处理策略，例如多名称同视图且无法确定时返回未知；不能让不同视图、旧代或容量淘汰后的记录制造确定性命中。缓存容量、每 IP 名称数、总字节、淘汰、同步、失效与清理有明确预算；禁用、满额或分配失败时不产生误导性匹配。尤其不能只淘汰冲突中的一个名称后把剩余名称视为确定：需要保留有界的歧义标记直到相关观察过期，或让受影响视图在无法记录冲突时退化为未知；整体淘汰后再次接纳同一 IP 也不能忘记尚未过期的冲突。记录域名本身可能是敏感信息，诊断按现有日志策略处理。反查仅用于元数据规则，不改变真实地址或自动信任其归属。

### IP 目标的视图选择

视图的选择必须先于反查。现有显式 DNS 查询在 `query_server` 已将配置 profile 和实际上游 endpoint 一起绑定成 view；local 查询则将不可变本地快照和实际 endpoint 绑定成 view。IP 字面量没有问题名，不能执行现有的域名 DNS 规则，也无法知道调用方原先使用哪一个上游。因此不能从 `final`、最近一次请求或多视图查找自动推断其身份。

第一版候选方案是为入口或规则动作显式绑定一个 DNS view：仅当配置能指向一个确定的 profile、实际 endpoint 和当前代次时可查；动态域名上游的多个地址、本地配置的服务器轮转/search 和无法确定来源的外部 DNS 均保持 unknown，直到有明确策略。相同的配置 profile 不代表不同 endpoint 或本地快照可以合并；查询产生的 view 不得被旁路替换为流量入口推测的另一个 view。绑定必须在配置加载时校验，不能用运行时偶然先出现的地址决定策略。旧配置默认不查询反查缓存；未绑定、不存在、歧义或过期时继续保留 IP 目标，不暗中发 DNS/PTR。此段是设计约束，尚无配置或生产实现。

local search 返回的反查名应是实际发送的候选问题名，不能将无后缀的原始输入绑定到另一个候选答复；hosts 的来源和生命周期与 DNS TTL 不同，默认不写入被动 DNS 反查。连接取消、旧快照释放、视图 ID 非复用、多个监听器共享和 DNS 缓存关闭下的发布策略需要分别测试；某视图缓存满额的全局暂停是否可接受也必须经资源与负载评估后再定义产品默认值。

## 嗅探边界

协议解析器与 I/O 分离，以借用字节/数据报输入，返回识别、需要更多、非目标或畸形结果；执行器负责 deadline、预算、取消和缓冲交接。`nexus.http.sniff` 支持借用累积 HTTP/1 头，按分片识别 Host、检查字段和大小上限，数值目标不提供域名；CONNECT 和 HTTP(S) 绝对形式若有 Host，仅在其与目标的域名及端口一致时提供域名，冲突时保留未知。它不读 socket、不消费数据，也不执行路由。`nexus.sniff.tls` 使用调用方提供的有界 scratch 重组跨记录 ClientHello，支持无扩展的旧版握手并借出 SNI，不依赖 TLS 握手实现；局部测试覆盖分片、错误和 OpenSSL TLS 1.2/1.3 ClientHello，结果仍是不可信元数据。QUIC Initial 与 DNS 等数据报识别须各自实现并验证，不能把未解析或加密名称当成不存在。识别协议、名称和来源分别记录。HTTP 嗅探区分域名、数值目标、歧义及未支持的目标；TLS 记录是否出现 ECH 扩展，该扩展也可能是 GREASE，外层 SNI 不能证明内部目标。有序执行器暂将带 ECH 扩展的域名视为未知，保留原始嗅探结果供未来显式策略使用。 已识别的数值 HTTP Host 可明确标记该来源无域名，域名谓词为不匹配；未识别、冲突、超时、ECH 或 TLS 无 SNI 不推断内部名称不存在。应支持分片、截断、非法长度、多协议竞争及无名称；HTTP CONNECT 和已有代理预读数据需先进入同一有序输入。

显式代理的握手时序需要单独处理：当前 SOCKS CONNECT 与 HTTP CONNECT 都在拨号成功后才回复成功，很多客户端收到成功回复后才发送应用首包。若嗅探等首包却迟迟不回复，就会死锁；若提前回复成功，后续解析或拨号失败又不能再用原来的握手错误码报告。不得在既有配置中悄悄调整此契约。对于显式启用嗅探的入口，先规定是只使用已预读数据、限时后按原目标回退，还是明确允许提前成功及随后的连接关闭；然后分别验证等待成功再发包、客户端抢先发送、server-first、拨号失败和取消。HTTP CONNECT 现有预读尾部必须先参与嗅探并最终精确发送一次，普通 HTTP 正向代理、SS/VLESS 流以及 TUN 入站也须按各自握手边界审计。

每个连接有总字节、数据报数、时间及并发预算；UDP 多包识别保留每个报文及目标边界，任何丢弃或超预算策略必须显式。对服务端先发协议或配置排除端口跳过等待，超时、非匹配和畸形按配置继续或拒绝，取消和真正 I/O 错误独立处理；不无限等待、不丢失预读内容。默认关闭嗅探时不得引入额外读、分配、协程或调度。启用时测量缓冲、拷贝及延迟，并对 TCP 半关闭、背压、UDP 空包、会话轮转及停止排空做网络回归。

## 与当前实现的差距和步骤

`nexus.sniff.tcp` 现在组合 HTTP/TLS 解析并保留有界原始输入，`nexus.sniff.tcp_io` 可按绝对期限读取并区分超时、取消、EOF 和 I/O 错误。调用方负责保留未接收的预读尾部、决定回退或失败，并在建立目标后按顺序恰好重放一次；这些模块尚未连接入口或路由动作。epoll 局部 socket 检查已验证超时后可以继续读，完整并发、取消竞争及 io_uring 验证仍待。

当前 `MatchInput` 提供目标域名/IP/端口/网络及来源、入站和认证身份；`RouteMatcher` 实现规则集的首命中和 DNS 前置判定。独立的 `RouteProgram` 可按顺序返回嗅探、解析、选路和拒绝动作，规则可选择显式、FakeIP、反查或嗅探域名，由调用方完成继续型动作后携带更新的输入从下一位置恢复；内部 TCP 执行器已组合继续型动作、DNS 及拨号，但尚无配置入口或生产调用方；它在前置判断遇未知条件时暂停，调用方必须明确提供上下文或回退策略。单独的 `next` 只评估当前已提供的字段，未知条件不命中，也不会自动解析；旧 `RouteMatcher` 的 DNS 前置判定与自动候选地址匹配必须通过兼容层保留，不能直接替换成这套动作扫描。`src/dns/fakeip_request.cppm` 和代理的 FakeIP feature 是实验路径，不等于生产已启用。当前生产共享 DNS 的视图、代次和生命周期必须成为反查数据的边界，而不是新建一个无隔离的全局 IP→名称表。

先扩展无 I/O 的上下文与有序动作模型，建立旧配置兼容层，对旧规则作差分并核验 TCP/UDP 相同决策；再以真实 DNS 答复构造可控反查，实现视图/代次、TTL、歧义和预算测试。随后实现独立增量嗅探器及流/数据报缓冲交接，再接入不同入站。最后验证显式选择的目标重写、FakeIP 与 DNS 规则交互、故障注入、取消及性能。每一步保持已有生产行为，测试钩子不进入生产图；不存在或未接入的能力应在配置加载时报错，不静默忽略。
