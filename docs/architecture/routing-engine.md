# 路由匹配流水线与配置代次

状态：主配置可按顺序引用谓词规则集并选择出口；v2 谓词支持 AND/OR/NOT、目标端口和网络，并为顶层域名及 IP 前缀编译索引，详见[规则集互转](../configuration/rule-sets.md)。完整路由引擎、其他上下文字段、复杂表达式索引和热重载仍为设计草案。

规则引擎设计原则见 [路由、DNS 与状态原则](../design-principles/routing-dns-and-state.md)；不同生态的条件名称接近不意味着配置或语义等价。

[反查、嗅探和动作时序](routing-metadata.md)记录元数据来源隔离、规则语义边界与验收步骤。

[配置草案](../configuration/spec.md)展示有序主规则对具名谓词集合的引用；[控制面](control-api.md)负责显示已提交代次及 selector 操作，不改变本引擎的匹配顺序。

## 字段流水线与顺序

请求进入后经过以下**信息准备和索引筛选**，不是对不同规则类别分别做优先终止：

```text
入站/原始目标 → 进程或应用身份 → 入站标签 → 域名/GeoSite 索引
             → IP/GeoIP 前缀索引 → 端口与协议 → 有序规则判定 → 动作/默认出口
```

任一阶段可能缺失数据；进程信息可因权限、转发流量、PID 复用或平台不支持而不可得，必须表示 `unknown`，不能冒用其他进程身份。显式代理域名、Fake-IP 反查、嗅探域名和真实 IP 分别保留来源，条件声明自己使用哪种属性。若某规则需要 DNS 得到 IP，在独立异步阶段使用该请求的视图、预算和共同 deadline，不得在同步 matcher 内隐式阻塞、无限重试或绕开 DNS 路由。

每条规则分配单调 `rule_id`；索引返回可能命中的规则集合，再以原顺序执行完整条件和短路。不可让 GeoSite 命中自动优先于更早的进程规则、让更长 IP 前缀覆盖更早规则，或将“不确定/缺失”误删为不可能命中。域名可选反向标签 trie 支持精确/后缀；关键字和正则如启用需独立有界算法与预算。IP 可使用 IPv4/IPv6 前缀树或区间索引，最长前缀用于单一前缀表内查找，不覆盖不同规则的先后。多种条件索引相交、OR/NOT 和缺字段时必须保守地保留候选；简单顺序解释器是语义基准。

例：规则 1 为 `process=browser AND geosite=foreign → proxy`，规则 2 为 `geoip=local → direct`。即使目标同时命中本地更长前缀，也必须先判断规则 1；无法取得进程名时按该条件定义处理，而不是把浏览器归入其他用户进程。`default-outbound` 只在无规则命中后生效；目标出口不存在或不具备 TCP/UDP/L3 能力时返回错误，不隐式换出口。

## MatchContext 与所有权

每次决策创建轻量 `MatchContext`，包含网络类型、入站标识、目标端口、IP、域名来源、进程身份和当前配置代次；字段可用显式 optional，字符串/地址列表用只读 `std::span` 或 `string_view` 借用。会话或请求拥有这些字节，snapshot 拥有规则/索引；**二者须活到所有借用和异步等待结束**。嗅探缓冲复用、DNS 结果移动、热重载或协程跨线程恢复时，禁止留下悬空 view。

目标是已准备好输入后的同步查找不分配堆内存：使用调用方提供的固定容量候选缓冲、预分配位集或分片内 scratch；溢出时以有界回退路径执行顺序匹配，不能丢规则。域名规范化、DNS 查询、正则、日志、共享指针获取及其他阶段可能分配；`span` 本身不提供线程安全或“全生命周期零分配”保证，须实测不同规则集和高水位。结果携带 rule ID、动作、出口及配置 generation，确保诊断与实际决策可关联。

## 原子发布与回收

加载 KDL/BEVE → 校验版本、引用与能力 → 编译不可变规则和索引 → 比较语义/预算 → 原子发布整份 snapshot。失败保留旧代并回报错误；新请求一次性获取单个代次，不能把旧规则与新索引混用。存量连接按既定策略持有创建时的决策与 snapshot，除非显式提供可取消的重评估机制；控制面状态显示已提交 generation，而不是只报告“开始加载”。

优先评估由明确的 owner 管理快照和读者生命周期；必须满足[共享所有权规范](../development/cpp-guidelines.md#共享所有权)后，才考虑使用 `std::atomic<std::shared_ptr<const Snapshot>>` 做 release-store/acquire-load。C++ 标准不保证该原子特化无锁，引用计数及析构也有开销。也可评估 epoch/RCU 或 hazard pointer：每个读者必须注册，协程跨线程挂起仍是活跃读者，旧代仅在最后借用结束后回收。监控长请求阻塞回收、限制同时存活的代次数及内存，处理 ABA、热更并发和关闭时回收；不能只原子替换裸指针后立即释放旧表。

出站 selector 可有独立的原子选择状态；配置代次发布时核验选择对象与成员仍有效，明确已建立连接是否保持原出口。规则快照与 selector 更新的线性化范围要定义，不能暗示所有控制面与网络配置一次全局原子提交。

## 验收

用顺序解释器生成同一输入的对照结果，覆盖规则顺序、重复前缀、最长前缀、后缀/精确、AND/OR/NOT、未知进程、DNS 延迟/失败及 Fake-IP；随机生成规则集验证索引不会漏掉首命中。并发测试加载失败保留旧代、持续流量下切换、协程挂起跨代、慢读者与关闭、内存预算及 selector 变化；分别测同步匹配分配次数、延迟与回收开销，不把设计目标写成现有性能数据。
