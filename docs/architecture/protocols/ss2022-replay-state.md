# SS-2022 服务端重放状态：持久化设计草案

当前 TCP salt 表和 UDP session 表均驻留内存；同一进程内同密钥的 worker/入站共享 owner。进程退出后这些记录丢失，独立进程也不共享它们。UDP 响应的服务端 session ID 以随机起点分配，重启后不能保证不重复。当前实现不提供跨进程或跨重启防重放，本页是待实现的设计约束，不代表已有能力。

UDP 重放窗口提供逻辑快照和向空 owner 的恢复，拒绝最高序号、初始化标记和位图之间不可能的组合。版本 1 编码为 138 字节：版本、初始化位、8 字节最高序号和 16 个 8 字节位图字，整数按大端序；编码和解码均检查规范性并拒绝错误长度、未知版本和非法标记。该编码不验证状态的真实性或新旧；调用方必须提供可信来源。窗口还能生成不改变现有状态的提案；调用方持久提交后可应用，跨 owner 或窗口已改变的提案会被拒绝。调用方必须在提交期间串行化，并在写入结果不明或提交后应用失败时停止并恢复。完整会话集合、期限和响应 ID 的可信存储尚未实现；正式服务路径尚未使用提案。

实验性的 UDP 会话持久模式在认证和重放检查后同步提交窗口与墙钟水位，再重新采样时间，包仍在有效窗口才交付；响应也先提交水位并预留服务端 ID，再重新采样生成报文。水位预留至提交前墙钟的 60 秒之后；提交后采样超出水位、时钟回退或提交失败时关闭 owner。恢复要求当前墙钟不早于已提交水位，因此正常重启可能需要等待，时钟停滞或回拨会延长等待。提交回调须原子持久保存不递减的全局水位，接收回调还须将它与窗口一起提交；恢复的会话没有 peer，必须重新认证后才能回包。该模式尚不支持过期或真实可信存储，也未接正式服务；它依赖完整且不可回滚的状态、密钥独占和可靠时间源，尚不能声明跨崩溃安全。

持久接收的调用方须在每次产生外部副作用前调用 `authorize_durable`，以新时间校验令牌所属 owner、协议时间窗口及已提交水位；排队期间过期的包被拒绝，时钟异常或超出水位则关闭 owner。校验与副作用必须由同一串行 owner 紧接执行，且调用方不得修改认证报文或重复使用令牌；该检查本身不撤销已提交的异步 I/O，也不能消除调用后任意延迟或时钟变化。当前正式 dispatcher 尚未使用这个实验接口。

## 所有权和提交

每个服务端密钥必须有一个串行的重放 owner，覆盖该密钥下所有 TCP 和 UDP 监听器。多个进程或主机共用密钥时，必须通过有一致性保证的共享 owner 协调；只在本机加文件锁不能证明跨主机安全。若没有共享 owner，部署必须确保密钥独占，程序不能把不可验证的部署约定报告为全局防重放保证。状态服务不可用、所有权不确定或存储损坏时应拒绝受影响的认证请求，而不是创建新的空表。

认证、时间校验和重放检查之后，允许的 TCP salt 或 UDP session/packet 窗口更新必须先持久提交，再交付请求、更新客户端来源或产生外部副作用。提交失败时拒绝请求；提交成功而转发失败可保留记录。并发请求的检查与提交须在同一个串行事务中完成，不能先分别检查再批量写入。容量不足时拒绝新记录，不得提前删除未过期记录。

UDP 响应需要避免同一服务端密钥下重复 session ID 和 packet ID。为降低每个响应同步写入的成本，可以在持久事务中预留单调且永不回退的 ID 区间，提交成功后才能使用；崩溃会丢弃未使用的区间。区间耗尽、整数溢出、恢复到旧备份或无法确认提交时必须停止分配。随机起点只能提供概率保证，不能替代持久唯一分配；跨主机同样须共享分配器。

实验模块 `nexus.shadowsocks.udp_id_reservation` 实现该区间分配状态机：同步回调确认高水位后才发放，恢复从高水位开始并跳过旧区间余量，提交失败关闭分配器。它已接入实验会话响应，但未接入正式服务或真实存储，不检查可信存储、回滚和独占所有权。

AES UDP 两方向按相同的 PSK 和 session ID 派生子密钥，并以 session ID 和 packet ID 组成 nonce；同密钥下双方重用同一组 ID 会复用密钥/nonce。[SIP022](https://shadowsocks.org/doc/sip022.html)要求服务端 ID 不使用客户端 ID。当前 owner 在整个生命周期保留已见客户端 ID 和已发服务端 ID，避免两集合冲突；每类上限 65536，耗尽后拒绝，过期不释放。实验持久模式还拒绝未知客户端落入已预留服务端 ID 区间，依赖从零开始、不可回滚的水位及完整的客户端历史。现有正式服务在进程重启时丢失这些记录，尚不提供跨重启保证；持久回收和规模化方案待实现。

## 恢复、期限和时间

记录保留至少覆盖协议时间窗口及采样边界；恢复不得仅根据新进程的单调时钟推断旧记录已过期。持久化时间水位和有效期须在系统重启、墙钟回拨、墙钟前跳后再回拨、休眠及时间源不可用时验证；不能可靠判断安全过期时保留记录并拒绝超额请求。重新创建空状态、删除数据库或恢复旧快照可能恢复已接受的包或复用响应 ID，因此需要显式的密钥轮换或能证明旧状态不再有效的恢复机制。仅在启动后等待固定时长既不能解决并发 owner，也不能解决墙钟回拨和响应 ID 唯一性。

实现前须明确状态目录配置、私有权限、密钥身份标识与轮换、锁定和跨主机一致性范围，以及同步提交和性能预算；不能把未经认证的普通文件或任意回滚快照作为可信状态。避免将原始 PSK 写入状态文件或日志。密钥标识需要抵抗碰撞和离线泄露，具体构造须结合密钥生命周期单独审查。

## 验收

对两种 AES 和 TCP/UDP 分别验证正常重启、SIGKILL、提交前后崩溃、提交结果不明、磁盘满/同步失败、损坏及旧快照、锁竞争、容量耗尽、时间回拨及并发相同数据报。验证已提交请求重放被拒、未提交请求无外部副作用，以及预留的响应 ID 在崩溃后不复用；独立进程和多主机测试必须与实际采用的协调边界一致。另测持久化开销、故障后的恢复与清理，不能以进程内回环测试代替上述保证。
