# 性能与资源设计

状态：基于 sing-box/sing-tun 与 shoes 提取的设计草案，尚无 Nexus 性能数据。来源见[sing-box 性能分析](../references/sing-box-performance.md)与[shoes 分析](../references/shoes.md)。

## 设计目标

同时评估吞吐、尾延迟、公平性、常驻内存、空闲开销和资源耗尽行为。优化必须保留报文、错误、关闭、取消、计数和路由语义；任何加速路径都要有明确进入条件和可验证的普通路径。

实现继续使用 C++ Modules、Corosio、concept、ngcpp/proxy 和自研网络/TLS 能力，遵循[C++ 规范](../development/cpp-guidelines.md)。本轮不新增协议、解析格式或运行依赖。

## 机制与代价

| 机制 | 预期收益 | 主要代价或限制 | 采用优先级草案 |
| --- | --- | --- | --- |
| 握手与公共转发器分离 | 复用生命周期与拷贝策略 | 必须显式携带首包、成功响应和 flush 状态 | 首期设计 |
| 包视图与明确所有权 | 减少头部剥离和转发复制 | 小视图可能长期持有巨大底层存储 | 首期设计 |
| 每轮处理预算 | 避免大流饿死其他连接 | 过小增加调度成本，过大增加尾延迟 | 首期设计并测量 |
| RAII 配额与有界队列 | 控制资源峰值，失败可回收 | 明确等待、拒绝、丢弃或降级的不同语义 | 首期设计 |
| 不可变预编译规则 | 将排序、合并和匹配结构构建移出热路径 | 编译峰值、索引大小和重载重叠成本 | 路由实现时验证 |
| 按规模选索引 | 同时兼顾小集合与大型规则源 | 阈值依赖规则、CPU、内存布局 | 基准后选阈值 |
| 结果缓存 | 减少重复匹配 | 依赖遗漏导致错误结果，命中维护可能争锁 | 规则依赖明确后 |
| 批量 I/O 与 GSO/GRO | 摊薄调用、分帧及调度成本 | 小包延迟、报文边界、平台与 MTU 限制 | 普通路径稳定后 |
| 条件化 splice / 原生转发 | 减少部分复制与包装调用 | 平台资源、协议转换屏障与统计语义 | 有独立证据后 |
| 多引擎与流分片 | 提高多核利用，缩小热状态共享 | 跨队列路由、NAT、返回路径和迁移复杂度 | 单引擎基线后 |
| 时间轮、合并唤醒、空闲回收 | 降低定时、调度和空闲驻留成本 | 精度、竞态、回收后重新分配成本 | 随规模与空闲指标验证 |

## 公共转发契约

握手结果应区分字节流、数据报、带目标/来源信息的消息及长期任务。结果需携带已读取但尚未转发的字节、响应发送时机和 flush 要求，不能让公共转发器猜测协议状态。

双向转发独立跟踪读结束、待写数据、flush 与半关闭。读到 EOF 后先排空对应方向，再结束写侧；另一方向按协议继续工作。取消和停止需要等待在途操作结束，关闭期限与连接活跃寿命分别设置。

按每轮字节、包数或时间设置处理预算；一直就绪的操作不能无限占用执行器。具体 Corosio 让出方式需要验证，不假定其他运行时的协作调度会自动存在。

## 加速路径的进入与退出

进入加速前必须确认：

- 剩余数据是否仍需加密、解密、分帧、padding、限速或内容处理。
- 原有读写缓冲、初始响应和 flush 是否全部排空。
- 两方向是否仍允许切换，统计、取消及关闭处理能否保留。
- 平台能力、FD 所有权、优化所需配额是否满足。

优化资源不足时优先继续普通路径；协议错误和连接错误则保留原语义。降级需处理已经读取到 pipe、批缓存或其他中间存储的数据，不能直接重启读取导致丢失、乱序或重复。

动态能力通过窄 facade 暴露，避免要求每条包或每个字节重复类型探测。只有证明后续语义等价时才能缓存已选路径；协议状态变化应使能力重新判定。

## 规则与缓存

配置/规则源经过解析、规范化、校验与编译形成不可变执行模型。对精确域名、标签后缀、IP 与端口区间等选择专用结构，多关键字或正则能力仅在实际支持时加入；不因参考项目有某功能就默认为 Nexus 已支持。

规则集已确定使用 KDL 文本与指定 Glaze 分支的 BEVE 二进制并提供双向转换，详见[格式设计](rule-set-format.md)与[转换设计](../configuration/rule-sets.md)。序列化、解压和索引构建分别计时，二进制编码不自动加速匹配；预编译索引与可逆规则表示分别版本化。

首个命中与信息不足的语义优先于索引效率。缓存条件必须列出结果依赖；按代次隔离配置变化，DNS、嗅探、健康状态等变化分别规定失效或绕过策略。热点缓存读取是否更新淘汰顺序，是有同步成本的策略选择。

DNS 的 TTL、负缓存、同键合并及乐观后台刷新见[DNS 设计](dns.md)；批写阈值与硬预算、读取可见与持久提交的区别见[缓存与状态](state-and-cache.md)。同时测量响应延迟、旧答案年龄与上游/磁盘放大，不能仅以缓存命中率证明收益。

## 资源模型

预算至少覆盖连接、会话、协程/任务、包与字节队列、乱序与分片重组、优化 FD、缓存和规则编译。计量“保留的实际存储”与“可见载荷字节”时说明差异，不能仅用载荷大小宣称内存有界。

建议配额采用只移动 RAII 对象，绑定实际资源寿命；异步操作完成前保留配额。减少限制不抹去旧 reservation，新申请如何失败单独定义。池同时控制对象数、容量及空闲时间，对长期排队的小载荷允许紧凑复制以释放大存储。

未来若实现热重载，需要计算旧连接保留的配置代次、候选编译、当前索引和共享缓存的重叠内存；“发布指针已切换”不等于旧资源已经释放。

多线程的 worker 所有权、全局预算及迁移门槛见[并发与多线程架构](concurrency.md)。

## 运行时边界

Corosio 管理异步 I/O 和执行器，自研状态机管理协议。若使用原生系统调用，必须明确就绪/完成通知、FD 所有权和取消归属，避免重复管理相同描述符。暂不预选 epoll、io_uring、分配器或某种拥塞控制为唯一方案。

日志在会话层关联上下文，热路径使用计数和限频汇总，避免按包构建文本。监控开启前后都要测量，不能让优化路径悄悄绕过统计。

验收方案见[性能验证](../planning/performance-validation.md)。

Linux 专属的内核 bypass、conntrack 判定复用、策略路由与自动分流见[平台设计](../platform/linux/networking.md)。NFQUEUE、nftables 和系统服务的收益需按实际路径测量，不由上游推荐直接推导。
