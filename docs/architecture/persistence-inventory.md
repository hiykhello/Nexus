# 持久化对象与存储决策

状态：持久状态分级与需求梳理，工程原则见 [路由、DNS 与状态原则](../design-principles/routing-dns-and-state.md)。先确定业务保证，再按实际数据量和写入模式选方案；不把重放实验的逐包事务当作所有状态的负载。

## 产品对象

| 对象 | 重启或丢失的后果 | Nexus 方向与写入模式 | 状态 |
| --- | --- | --- | --- |
| KDL 配置、规则源和用户提供的密钥/证书 | 无法恢复声明的配置或身份 | 用户提供的文件是权威来源，不复制进普通缓存；现有规则转换的 BEVE 是规则文件格式 | 已有有限配置、规则与密钥文件；不是状态数据库 |
| selector 的显式选择 | 重启回退配置默认项，可能改变出口 | `control` 可将手动选择保存到独占私有目录，选择提交后再发布，恢复时核对成员 | Linux CLI 双后端通过写入、重载、重启和损坏校验，见[原生控制面](control-api.md) |
| FakeIP 映射、池身份和分配游标 | 客户端仍持有旧地址，可能无法反查或误关联 | 实现 FakeIP 时独立选择崩溃保证；至少保证未知地址失败及防止不安全复用；若要求每个已答复映射恢复，须逐映射提交或等价机制 | 设计；现有示例提出隔离恢复，尚未定最终保证 |
| 远程规则集内容、来源身份、ETag 和更新时间 | 离线启动可能无法加载规则，在线需重新下载 | 未来远程规则功能可选缓存，以来源身份校验并明确过期/离线策略；按下载更新，而非逐连接写 | 未实现远程规则加载 |
| DNS 应答、视图身份与绝对到期时间 | 缓存冷启动，增加查询和延迟 | 独立监听器正常关闭时写入有界快照，载入校验上游和策略，按停机时间扣除 TTL | 已接入数值 UDP/TCP 上游和内联策略的多视图。NXDNS2 可从符合原条件的 NXDNS1 快照迁移。外部规则集、加密和系统上游保留内存缓存。 |
| TUN/路由/DNS 宿主恢复 | 宿主规则与服务状态需要按所有权恢复 | Linux 严格路由的独立所有者保留设备、netlink 事务与 resolved 链路身份 | 独立所有者在代理退出或被单独 SIGKILL 后撤回自有设置。恢复依赖仍运行的所有者和系统实际状态。 |
| ACME 账户、证书、私钥及续期状态 | 可能需要重新签发，受限额或网络影响；私钥丢失会改变身份 | 若未来实现自动证书管理，作为独立敏感凭据状态，私有权限、生命周期和恢复单独设计 | 未承诺实现，不放入普通缓存 |
| 活动连接、健康探测、连接池及自动选择结果 | 重启后重建和重新探测 | 内存状态，不恢复成仍有效的连接或健康结论 | 按功能实现 |
| SS-2022 TCP salt、UDP 重放窗口、ID 和墙钟水位 | 现有进程重启后防重放记录丢失；时间窗口内旧包可能被再次接受，UDP ID 也无跨重启唯一性保证 | 属于额外的安全保证，不是普通缓存：只有明确要求跨重启防重放时才选择可信存储、独占、防回滚及提交方案；不以异步快照冒充此保证 | 正式路径仅进程内；已有 BEVE/SQLite 非默认实验，未接服务 |

业务数据各有不同的丢失代价、权限和清理范围；它们不必使用同一文件或同一后端。上表是当前产品设计的工作假设，不是已经实现的配置选项或对用户保证。

## 参考实现与具体差异

- **批量异步缓存模式**：将 DNS、FakeIP 与远程规则集元信息按批合并落盘，远程规则保留内容、时间戳、ETag 与摘要；但批写失败丢弃该批时不代表逐条强持久，且用户显式配置与可重建缓存必须分层隔离。
- **原子快照与预留区间模式**：显式 selector 选择使用带版本的原子快照并在保存成功后发布，与自动健康状态分离；FakeIP 使用带预留区间的持久化降低每次分配的同步写盘并减少崩溃复用冲突；ACME 密钥/凭据与抗重放状态则严格独立管理，不混同于普通缓存。
- 参考实现的选择不决定 Nexus 的安全承诺。尤其 FakeIP 异步保存、丢失后的地址复用，以及 SS-2022 重启重放的后果需分别决定；序列化格式或数据库均不能单独提供防回滚与跨主机独占。

## 当前决策与下一步

手动 selector 使用有版本的紧凑文件快照，每条保存一组名称和成员名称，最多 16 条。保存采用同目录原子替换和文件、目录同步。FakeIP 的容量、更新频率及每个已应答映射的崩溃保证需单独判断。大量 DNS/规则缓存可按数据规模、随机访问、批写和恢复目标比较增量 KV、数据库与文件方案。

暂停将逐包 UDP 重放存储作为通用状态后端的选型基准。保留实验作为证据，但跨重启安全是独立设计问题：先确定产品承诺与可接受的重启行为，再设计可信状态和多实例协调。已有两种后端的非等价基准不能用于决定 selector、FakeIP 或 DNS 后端。
