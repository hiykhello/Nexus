# 持久化对象与存储决策

状态：需求梳理与建议，不代表功能已实现或格式已定。以本地 sing-box `a6952ccf6907c18e18917fcb763a433e8e36937b`、shoes `739e2ea91ef6a892d646a4453102277003567b7c` 为参考，详见[源码分析](../references/dns-and-persistence.md)。先确定业务保证，再按实际数据量和写入模式选方案；不把重放实验的逐包事务当作所有状态的负载。

## 产品对象

| 对象 | 重启或丢失的后果 | Nexus 方向与写入模式 | 状态 |
| --- | --- | --- | --- |
| KDL 配置、规则源和用户提供的密钥/证书 | 无法恢复声明的配置或身份 | 用户提供的文件是权威来源，不复制进普通缓存；现有规则转换的 BEVE 是规则文件格式 | 已有有限配置、规则与密钥文件；不是状态数据库 |
| selector 的显式选择 | 重启回退配置默认项，可能改变出口 | 实现 selector 与控制面时可选持久化 group → member；选择提交后再发布，恢复时核对成员 | 设计，尚无 selector 持久实现 |
| FakeIP 映射、池身份和分配游标 | 客户端仍持有旧地址，可能无法反查或误关联 | 实现 FakeIP 时独立选择崩溃保证；至少保证未知地址失败及防止不安全复用；若要求每个已答复映射恢复，须逐映射提交或等价机制 | 设计；现有示例提出隔离恢复，尚未定最终保证 |
| 远程规则集内容、来源身份、ETag 和更新时间 | 离线启动可能无法加载规则，在线需重新下载 | 未来远程规则功能可选缓存，以来源身份校验并明确过期/离线策略；按下载更新，而非逐连接写 | 未实现远程规则加载 |
| DNS 应答、视图身份与绝对到期时间 | 缓存冷启动，增加查询和延迟；上游不可用时可能影响可用性 | 内存为基础；磁盘持久化可选，异步批写并允许丢失，恢复时验证视图和 TTL | 普通 DNS 有内存缓存；磁盘缓存未实现 |
| TUN/路由/DNS 宿主恢复清单 | 崩溃后可能留下宿主资源或无法确认所有权 | 仅真实系统接管实现时按实际平台步骤设计意图、所有权和重启核对；宿主状态仍是实际依据 | 未实现真实接管，当前不创建 |
| ACME 账户、证书、私钥及续期状态 | 可能需要重新签发，受限额或网络影响；私钥丢失会改变身份 | 若未来实现自动证书管理，作为独立敏感凭据状态，私有权限、生命周期和恢复单独设计 | 未承诺实现，不放入普通缓存 |
| 活动连接、健康探测、连接池及自动选择结果 | 重启后重建和重新探测 | 内存状态，不恢复成仍有效的连接或健康结论 | 按功能实现 |
| SS-2022 TCP salt、UDP 重放窗口、ID 和墙钟水位 | 现有进程重启后防重放记录丢失；时间窗口内旧包可能被再次接受，UDP ID 也无跨重启唯一性保证 | 属于额外的安全保证，不是普通缓存：只有明确要求跨重启防重放时才选择可信存储、独占、防回滚及提交方案；不以异步快照冒充此保证 | 正式路径仅进程内；已有 BEVE/SQLite 非默认实验，未接服务 |

业务数据各有不同的丢失代价、权限和清理范围；它们不必使用同一文件或同一后端。上表是当前产品设计的工作假设，不是已经实现的配置选项或对用户保证。

## 参考实现与具体差异

- sing-box 的 `experimental/cachefile` 用 bbolt 保存 selector、模式、UI 展开状态和远程规则；FakeIP、DNS 和已弃用的 RDRC 存储分别由选项控制。远程规则保存内容、时间、ETag 和 URL 哈希；启动时缓存不可用可读取初始文件或下载，初次获取失败则启动失败。DNS 与 FakeIP 走批写；其 `Flush` 失败丢弃该批，不能据此宣称每次成功答复均已持久化。详见 `adapter/experimental.go`、`experimental/cachefile`、`route/rule/rule_set_remote.go` 和 `dns/transport/fakeip/store.go`。
- shoes 的 `src/control/store.rs` 用带版本的 JSON 整体快照保存显式 selector 选择，`selection.rs` 在保存成功后发布，自动选择和健康状态分开。`src/dns/fake_ip` 为可选 FakeIP 状态使用独立 JSON 快照和预留区间；崩溃可能丢失最近映射，未知地址失败，不承诺每个已应答映射均可恢复。它的 `src/certificates/acme.rs` 另存账户密钥、证书私钥、订单及续期状态，不能混同于普通缓存。其 `TimedSaltChecker` 是内存结构；这一点本身不证明所有协议或全部重放实现的重启行为。
- 参考实现的选择不决定 Nexus 的安全承诺。尤其 FakeIP 异步保存、丢失后的地址复用，以及 SS-2022 重启重放的后果需分别决定；序列化格式或数据库均不能单独提供防回滚与跨主机独占。

## 当前决策与下一步

现阶段不选择 SQLite，也不把 BEVE 当成事务引擎。Nexus 已有 BEVE 编解码：对于低频、小而有界、整体恢复的用户选择，带版本的 BEVE 快照加安全原子替换是合理的**首个候选**；实际实现须结合 selector 功能、失败语义和基准验证。FakeIP 的容量、更新频率及已应答映射的崩溃保证尚未确定，不应预先断言整体快照适用。大量 DNS/规则缓存若确有持久化需求，再以对应数据规模、随机访问、批写和恢复目标比较增量 KV/数据库与文件方案；没有该需求时无需引入数据库。

暂停将逐包 UDP 重放存储作为通用状态后端的选型基准。保留实验作为证据，但跨重启安全是独立设计问题：先确定产品承诺与可接受的重启行为，再设计可信状态和多实例协调。已有两种后端的非等价基准不能用于决定 selector、FakeIP 或 DNS 后端。
