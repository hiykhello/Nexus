## 协议优先级支持矩阵

| 梯队 | 包含协议与模块 | 战略定位与目标 |
| :--- | :--- | :--- |
| **P0 (核心基石与 MVP)** | **TUN 模式**、**Shadowsocks 2022**、**VLESS + Reality**、**Mixed (SOCKS5/HTTP)**、**Direct / Block** | 首期最小可用系统，覆盖系统全局接管、专线极速低延迟与防 DPI 穿透 |
| **P1 (扩展目标)** | **WireGuard**、**Hysteria 2**、**Trojan**、**V2Ray HTTPUpgrade / gRPC** | 组网、条件性的 WARP 互操作、QUIC 承载与其他传输 |
| **P2 (特定生态补充)** | **TUIC v5**、**ShadowTLS v3**、**Snell** | 特殊客户端生态与替代方案 |
| **❌ 明确拒绝** | **VMess 协议** | 存在严重内层双重加密开销、阻碍零拷贝且历史缺陷多，Nexus 默认不提供 |

## 分离的职责

| 对象 | 负责 | 依赖边界 |
| --- | --- | --- |
| 协议核心 | 报文编解码、握手状态、认证结果与协议错误 | 基础类型、缓冲、所需密码能力；不查全局路由、不修改宿主网络 |
| 入站适配 | 接入生命周期、服务端握手、用户与目标提取、交给路由 | 监听/接入能力、协议核心、窄路由提交接口 |
| 出站适配 | 根据目标建立代理会话、客户端握手、返回传输能力 | 协议核心、注入的连接器、节点解析与身份配置 |
| 承载与连接器 | 建立流/数据报/复用子流，连接和安全层组合 | Corosio 运行时、TLS、平台 socket 策略等指定能力 |
| 路由与会话 | 选择出口、验证能力、公共转发、取消及统计 | 抽象能力，不依赖每种具体协议 |
| 平台后端 | 设备、socket 选项、宿主网络与系统事件 | OS/宿主 API；不识别代理认证报文或决定业务出口 |

client/server 是部署角色，inbound/outbound 是会话职责。SOCKS 入站可以经 HTTP CONNECT 出站，也可以经 direct 出站；组合成立与否由实际提供的流/数据报能力判断，无需两端协议相同。示例不承诺这些协议已实现。

## 单个协议的组织

每个协议独立形成 `nexus.protocol.<name>` 家族，最初可用同一命名模块下的内部 partition 区分 codec、client、server。只有确有独立编译、裁剪或导出需要时再拆为命名子模块；不为每个文件创建模块。

协议核心共享端点编码、版本、消息结构和必要密码逻辑，client/server 保持不同状态机、凭据与错误应答；不能为了复用强行制造万能握手函数。可复用 codec 仅导出需要的类型，不将协议私有消息塞入 core。

入站和出站的公开配置可不同；同一协议的端口、认证、版本、UDP 或 TLS 前提由各自校验器检查。协议局部配置在该家族定义，KDL 解码/注册适配放在显式配置集成模块，通用 KDL 读取器不 import 所有协议。必要时利用反射减少映射代码，但字段存在不等于语义自动正确。

核心可表达“需要读取/写出、已认证、已获取目标、完成/失败”等状态，具体异步驱动由角色适配负责。适合直接协程实现的协议也保留相同依赖边界；不强制每个协议都引入复杂通用状态机框架。

## 数据面能力契约

建议分别建模字节流连接、固定目标数据报会话、逐包携带目标的数据报关联、L3 包端口及长期隧道 endpoint。由 concept 表达静态组合条件，运行时选择使用 Git 版本 ngcpp/proxy 的窄 facade，不要求全部对象支持一个巨型接口。

数据报接口必须说明边界、来源/目标、最大负载、截断、顺序、可靠性及返回路径。UDP 经流封装需要明确编码与会话策略，不能直接把包写成连续字节；只有字节流能力的出口不能声称承接任意 L3 包。

握手结果与公共转发的交接应显式携带：

- 规范化目标、原始目标、身份与观察结果的来源。
- 已预读的业务数据及所有权，避免握手缓冲中首包丢失。
- 成功/失败应答所需操作、发送和 flush 时机，以及能否在目标尚未连通时提前确认。
- 连接已确认、可提前写入或仍需确认的状态；TLS/协议 early data 的重放限制不能被连接优化隐去。
- 半关闭、取消、deadline、会话寿命及必要的协议封装器。

普通转发器管理公平性、背压、计数和终止；协议 framing/加密包装器在其生命期继续工作。复用协议由 parent session 拥有承载、认证、池与预算，逻辑子流独立路由/关闭；不能把一条底层连接误算成单个业务会话。见[性能设计](performance.md)。

## 组合与依赖图

```mermaid
flowchart LR
    A[监听器或宿主接入] --> B[承载与安全层]
    B --> C[入站协议适配]
    C --> D[规范化请求与路由]
    D --> E[出站协议适配]
    E --> F[连接器与承载]
    F --> G[平台 socket 或下一跳出口]
```

图示表达运行请求方向，C++ import 依赖由契约反转：路由依赖出站 facade，由 app 注入具体实现，不能 import 具体 SOCKS/HTTP 协议。承载层也不能反向 import 使用它的代理协议。

TLS、WebSocket、HTTP/2、QUIC、复用不是任意顺序叠加的通用积木。每个有效组合声明前提、承载能力、握手顺序、消息边界、ALPN、认证及关闭语义；QUIC 原生流/数据报不简单当作“TCP 加 TLS”装饰器。模块允许扩展不等于首期实现全部组合。

出站明确区分业务目标、代理服务器目标和下一跳。detour 注入下层连接器，节点 hostname 通过指定 bootstrap/DNS 视图解析；不要让出站重新调用顶层路由而产生自循环。启动前检查出口链、DNS 引导和 endpoint 依赖图；运行时仍携带链路身份与深度限制，见[DNS 设计](dns.md)。

selector/健康策略输出当前目标出口的受控引用或快照，和实际协议出口分开；选择操作不创建新协议类型。设备/长期隧道若同时接收与发送，由一个 endpoint owner 管理状态，暴露相应能力，避免入出两实例各自启动同一设备。

## 注册、裁剪与生命周期

模块提供显式注册函数，app 的编译能力清单决定启用哪些 inbound、outbound、承载、DNS、endpoint 和平台后端。注册记录含类型、方向、配置构造/校验、组件工厂及能力要求；重复类型或方向冲突明确失败。工厂注册与流量分发分开，热路径不按类型字符串反复查工厂。

候选构造先解析/校验配置和引用，再检查编译能力、平台可用性与组合条件；不在反射或配置读取时打开监听、安装路由。缺失组件分别诊断未知类型、方向不支持、未编译、平台不支持、权限不足及参数冲突，不能用可选空对象静默退化。

依赖通过明确的构造上下文注入，按组件需要拆分 resolver、connector、route sink、logger、budget 等能力。避免可供任意查找/修改所有对象的全局服务容器，避免 callbacks 捕获生命周期更短的 registry/config。

入站先准备、依赖就绪后接入；出站可以按需连接但先验证依赖。停止时先停止接入和新子流，再排空/取消会话，最后关闭共享承载、endpoint 和平台租约。池与会话不能跨身份或配置代次误复用，具体规则与[组件生命周期](component-model.md)一致。

这里的“可插拔”指源码组件和显式注册。C++ Modules、proxy facade 不自动提供跨版本稳定 ABI，当前不设计加载任意共享库的插件系统。

## 验收要求

使用内存流、假监听/连接器与固定报文，验证同一协议核心可驱动两端；验证异协议组合、首包、应答时机、认证失败、半关闭、取消、逐包目标与资源回收。协议私有类型不得通过路由接口泄漏。

构建最小协议集合和完整候选集合，确认裁剪后未链接被排除实现与依赖；增加一种协议时应主要新增本家族、配置适配与装配声明，无需修改路由分发。增加一种承载或替换平台后端时，已有协议核心无需修改。

每个协议按方向/版本/传输/平台列出通过和未通过组合，附互操作与报文证据，不以模块编译成功代替线上兼容。[成对 KDL 示例](../configuration/examples/README.md)是未实现的结构草案，须完成真实解析及端到端验证后才能作为部署配置。
