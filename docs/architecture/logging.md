# 日志系统设计

状态：设计，尚未实现。当前程序仍直接向标准输出和标准错误写启动、退出及配置诊断。本设计覆盖本机客户端、服务和未来宿主嵌入，具体配置字段与默认预算需随实现验证。

## 输出选择和服务管理器

未配置日志路径时，默认使用**继承的标准错误流**，逐行输出带严重级别、组件、实例和事件的文本；标准输出留给命令结果。终端可按是否为 TTY 决定颜色，非 TTY 默认关闭颜色。管道、重定向、容器和没有 systemd 的启动方式均遵循同一约定，不探测或创建默认日志文件。关闭日志应是显式选项；启动早期在日志器可用前的错误仍尽力写标准错误。

systemd 通常把服务的 stdout/stderr 接至 journal，可由 `journalctl -u nexus.service` 查阅；具体收集、持久化、限速和转发由服务及 journal 配置决定。journal 默认流并不等于已实现原生结构化字段，也不保证每条记录持久保存。默认使用标准错误不依赖 systemd 环境变量。若未来只为颜色或显示格式检测 journal，需校验 `JOURNAL_STREAM` 对应 FD 的设备和 inode，而非仅检查变量是否存在。参考 [systemd-journald](https://www.freedesktop.org/software/systemd/man/latest/systemd-journald.service.html)、[systemd.exec](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html)。

显式路径选择文件 sink；打开失败应报告并使配置应用失败，不悄悄改写到其他路径。定义 `stderr`、`file`、`off` 等明确 sink，避免空字符串、缺省和禁用混为一谈。多 sink 若后续支持须明确是否复制、各自丢失策略和次序，不能对同一路径重复配置轮转。日志文件与数据库、配置和凭据路径不能重合。相对路径解释、权限和多实例隔离必须与配置解析规则一致。

## 异步管线与背压

调用方提交拥有的、大小受限的事件（级别、事件码、时间、组件及可选上下文）；网络热路径不等待磁盘、不得持有借用缓冲跨协程。单 owner 按单调序号串行消费有界队列并批量编码/写入；每条记录和每批有字节上限，明确排队、正在写入及格式化副本的总预算。队列满时低级别日志丢弃并计数，关键错误保留有限配额或通过受限的紧急 stderr 路径尽力报告；任何 sink 都不能无限阻塞网络线程。退出先关闭入口，再等待队列与在途写入，截止期限和丢弃数量要可观察；取消不等于写入已撤销。

标准错误可能是终端、管道、普通文件或 journal 的 AF_UNIX stream socket，不假设可 seek 或由 `stream_file` 操作。其阻塞和断开需在专用 sink/执行器与适配方案中验证；保序、部分写、EINTR、EPIPE 和 SIGPIPE 均需处理，不能改变宿主进程全局信号行为而不声明。journal 和外部接收器可能另行限速/丢弃。

## 异步文件 sink

使用固定 Corosio 提交 `70adbd5aff90569aac588e78a717fecbd5b7dedc` 进行验证：选择 `io_context(uring)` 时 `stream_file` 分派至 uring 文件服务，通过 `io_uring_prep_writev` 提交写入；epoll/POSIX 回退采用线程池执行阻塞文件操作。当前 Nexus 代理仍使用默认 epoll，因此不能因编译启用 liburing 就声称文件日志走了 uring。内核可能自行将操作交给工作线程；真正异步提交不代表零阻塞、零复制或设备已经持久化。

`stream_file` 共享对象一次只允许一个异步操作，日志 writer 负责串行化、处理短写和错误，buffer 存活至完成。该版本 `open`、`sync_data`、`sync_all` 为同步调用；打开、轮转、同步不能直接阻塞网络事件循环。写完成只表示操作完成，不等于 `fsync` 成功或断电持久。日志默认不逐条同步；显式持久模式须给出同步边界、性能预算、同步失败和停止保证。同步应置于适当的专用执行路径并测试。

文件以安全方式打开并验证普通文件、权限、所有权和符号链接策略；不能默认上游 `open(..., 0666)` 符合日志敏感性。单实例单 writer；多进程共享文件、外部截断和轮转不是自动安全的。初版选一种明确轮转策略：建议服务管理器管理 stderr；文件模式采用显式 reopen（例如管理命令或信号），先排空旧 FD，再安全打开新文件并确认成功后切换，失败保留旧 FD 并告警。rename 后旧 FD 仍指旧文件，禁止假设路径自动更新；copytruncate 可能丢数据，不承诺无损。大小轮转、保留数和文件名仅在实现并测试后配置。

## 内容、故障和验收

默认不记录密码、密钥、token、完整 payload、完整 DNS 查询/目标地址或用户身份；敏感诊断需显式开启并限时，字段长度和控制字符须转义，防止伪造多行。统计丢弃数、队列水位、sink 错误、最近成功写入与停止未排空数，告警避免递归写同一失败 sink。记录级别、格式和实例 ID 应稳定，但不承诺跨 sink 的全局顺序。

验收涵盖：无路径运行于 TTY、普通管道和 systemd journal；stdout/stderr 重定向与关闭；文件权限/符号链接/磁盘满/短写/轮转；并发生产、饱和丢弃、关停与取消；epoll 和 io_uring 两路径的实际 backend、数据顺序及故障注入；`sync` 失败与性能开销。审计实际使用的构建选项、核验日志无秘密及控制字符注入，并记录哪些模式尚未实现。
