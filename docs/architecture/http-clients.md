# 具名 HTTP 客户端设计草案

状态：设计草案，尚未实现。`http-clients` 中每个子节点的节点名直接作为客户端 tag；它不是节点类型，也不是另一个位置参数。此设计供远程规则集等后台用途使用，不代表 Mixed 正向代理已经提供通用客户端。

```kdl
http-clients {
    updates {
        outbound "edge"
        domain-resolver "bootstrap"
    }
    local-fetch {
        outbound "direct"
        domain-resolver "system"
    }
}
```

这些字段名与示例均为待实现的候选，不是现有配置。客户端 tag 在该分组内唯一，引用按完整 tag 精确匹配；缺失、重复及非法引用在启动前报错。`outbound` 引用具名出站，`domain-resolver` 引用具名 DNS 服务器，二者分别决定连接路径与域名解析；用途配置显式引用客户端 tag。各用途仍须定义自己的 URL、认证、内容限制及更新政策，不能把客户端 tag 当成 URL 或凭据。

## 生命周期与边界

加载配置时先建立所有客户端、DNS、出口和业务用途的依赖图，校验引用、能力和环；例如更新远程规则所需的出口不能依赖该规则本身才能决定如何连接。初始化证书和凭据失败则拒绝候选配置。连接不经本机 Mixed 端口回环，而通过内部连接器使用选定出口；系统接管或 TUN 启用时，还需履行平台绕行约束。DNS 引导和 VLESS 上游自身解析的依赖须进入同一检查，不能因配置了客户端解析器就假定所有解析都已隔离。

HTTP、TLS、DNS、拨号和业务层分别负责 framing、身份验证、解析、出站及用途策略。每次请求记录原始 URL 的 scheme、authority、验证身份和选定出口；对每个 DNS 候选地址应用相应连接约束。HTTPS 必须验证名称及信任链，SNI、HTTP authority 和拨号地址各自保留。不会将连接按 IP 合并到不同 TLS 身份、代理凭据或出口视图。当前单次 `https_exchange` 只是可复用的底层实验，尚不提供客户端调度、池或规则下载。

每个请求有总期限、取消和独立的头部、正文及并发预算，解析、排队、连接、TLS、重定向和读取共用总期限。调用者流式消费正文并对业务文件设上限；背压传递到读取端，取消或消费者拒绝时关闭不可安全复用的连接。停止先拒绝新请求，取消在途请求，等待操作释放持有的流与缓冲；共享客户端不能因单个请求取消而销毁其他请求。

重定向、自动重试、内容解码、条件请求及缓存按用途明确启用和限制；不得默认重放不可重放请求，跨 origin 重定向不得泄露认证信息，HTTPS 降级和跨出口行为须由用途明确授权。规则下载只有完成长度、格式和完整性校验后才能发布新快照，失败保留旧版本；本地持久化和离线有效期另行定义。日志与诊断不得输出凭据或 URL 中的秘密。

## 验证顺序

1. 配置校验覆盖重复 tag、悬空引用、依赖环、未编译能力与证书失败；配置失败不能发起网络连接。
2. 假连接器及受控 DNS 验证客户端 tag 到出口、解析器和身份的绑定，包括不同客户端同时请求、取消、超时及错误隔离。
3. 独立 HTTP/TLS 对端验证 framing、证书拒绝、ALPN、截断、背压、重定向与停止；按用途测试上限和禁止泄露凭据。
4. 最后接入远程规则获取，验证失败保留、原子发布与重启恢复，再考虑连接复用和其他 HTTP 版本。
