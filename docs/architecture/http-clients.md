# 具名 HTTP 客户端设计草案

规则下载支持具名 HTTP/1.1、可选 HTTP/2 和 HTTP/3。TCP 和 QUIC 可使用具备相应传输能力的具名代理出站，客户端独立选择源站 DNS。`nexus rule fetch` 验证并发布单次下载，`nexus rule watch` 周期发布到同一文件。支持热加载的代理监听器通过 SIGHUP 接收更新。配置格式与实测覆盖见 [配置规范](../configuration/spec.md#具名-https-规则下载) 和 [支持矩阵](../planning/proxy-kernel-support-matrix.md)。其余连接器和后台生命周期沿用下文设计。

```kdl
http-clients {
    updates {
        outbound "direct"
        domain-resolver "bootstrap"
        ca-file "/etc/nexus/update-ca.pem"
        protocol "auto"
    }
    local-fetch {
        outbound "direct"
        domain-resolver "system"
        ca-file "/etc/nexus/local-ca.pem"
    }
}
```


## 生命周期与边界

加载配置时先建立所有客户端、DNS、出口和业务用途的依赖图，校验引用、能力和环；例如更新远程规则所需的出口不能依赖该规则本身才能决定如何连接。初始化证书和凭据失败则拒绝候选配置。连接不经本机 Mixed 端口回环，而通过内部连接器使用选定出口；系统接管或 TUN 启用时，还需履行平台绕行约束。DNS 引导和 VLESS 上游自身解析的依赖须进入同一检查，不能因配置了客户端解析器就假定所有解析都已隔离。

HTTP、TLS、DNS、拨号和业务层分别负责 framing、身份验证、解析、出站及用途策略。每次请求记录原始 URL 的 scheme、authority、验证身份和选定出口；对每个 DNS 候选地址应用相应连接约束。HTTPS 必须验证名称及信任链，SNI、HTTP authority 和拨号地址各自保留。不会将连接按 IP 合并到不同 TLS 身份、代理凭据或出口视图。规则下载与嵌入调用共用 `nexus.http.named_client`。每个客户端实例固定具名配置和 HTTPS authority，对外提供可取消的异步 GET 和可挂起的正文消费者。调用方驱动实例的 executor，等待请求退出后销毁客户端，收到完整响应状态后才提交此前收到的正文。HTTP/1.1 复用已确认自分帧的响应连接，复用连接失效且尚未交付响应时允许 GET 在原期限内重拨一次。HTTP/2 和 HTTP/3 可在同一实例上复用连接并并发处理请求，正文消费后归还接收窗口额度，取消只结束对应请求流。连接池空闲回收时间为 15 秒。具名 HTTP/3 池按实际连接端口区分直连及 Alt-Svc，保留 QUIC、静态 ECH 与所选代理 PacketTunnel 的生命周期。

每个请求有总期限和取消。解析、连接、TLS、重定向和读取共用该期限。H1、H2 和 H3 的规则下载支持按块等待正文消费者。H1 等待后继续读取，H2 和 H3 在消费者接收后归还对应接收窗口额度。消费者拒绝、事务取消或正文超限会终止下载。规则命令按配置上限收集正文，完整通过格式和摘要校验后发布文件。共享客户端后续按请求隔离头部和正文预算，限制并发和排队，并在停止时拒绝新请求、排空在途操作。

重定向、自动重试、内容解码、条件请求及缓存按用途明确启用和限制；不得默认重放不可重放请求，跨 origin 重定向不得泄露认证信息，HTTPS 降级和跨出口行为须由用途明确授权。规则下载只有完成长度、格式和完整性校验后才能发布新快照，失败保留旧版本；本地持久化和离线有效期另行定义。日志与诊断不得输出凭据或 URL 中的秘密。

## 验证顺序

1. 配置校验覆盖重复 tag、悬空引用、依赖环、未编译能力与证书失败；配置失败不能发起网络连接。
2. 假连接器及受控 DNS 验证客户端 tag 到出口、解析器和身份的绑定，包括不同客户端同时请求、取消、超时及错误隔离。
3. 独立 HTTP/TLS 对端验证 framing、证书拒绝、ALPN、截断、背压、重定向与停止；按用途测试上限和禁止泄露凭据。
4. 最后接入远程规则获取，验证失败保留、原子发布与重启恢复，再考虑连接复用和其他 HTTP 版本。
