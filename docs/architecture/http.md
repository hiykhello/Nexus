# HTTP/1.1、HTTPS 与后续 HTTP/2

状态：HTTP/1.1 与 HTTPS 自研方向已确定；HTTP/2 接入优先级已提高，当前已加入固定 libnghttp2 1.70.0 的可选包、模块封装及实验性无 I/O 服务端会话，内存测试覆盖头部限额、DATA 事件和分片驱动；运行时 h2 适配仍未完成。实验代理已有有限的 HTTP/1.1 CONNECT 解析与隧道及有限的单请求 HTTP 正向转发（包括定长和 chunked 请求/响应及 100-continue）；通用 HTTP framing、HTTPS 和 HTTP/2 尚未实现。具体完整特性和默认限额仍为草案。方向见[决策 0005](../decisions/0005-http-stack.md)。

## 分层与复用

HTTP/1.1 自行实现增量解析、编码、消息边界及连接状态，不将第三方 HTTP 库或解析器作为其实现。HTTPS 由该 HTTP 层叠加[自研 TLS](tls.md)、证书验证和异步流组成，两个方向均沿用该分层。密码底座按[决策 0007](../decisions/0007-boringssl-libcrypto-and-ktls.md)采用 BoringSSL libcrypto，具体接入仍待验证。

后台用途的具名客户端及配置依赖见[具名 HTTP 客户端设计](http-clients.md)，目前仍是草案。

当前 chunked 解码器可报告消费的输入长度，使调用方保留后续消息的预读字节；它仍输出经验证的 chunked framing，不提供完整连接复用。实验性异步 TLS 客户端已使用现有 HTTP 响应解析器验证 OpenSSL 的关闭定界响应，这尚不是正式 HTTPS 客户端。

无 socket 响应状态机组合现有响应头和 chunked 校验，逐步报告输入消费量与重写后的输出；支持中间响应、HEAD、定长、chunked 和关闭定界，调用方必须区分认证关闭与截断。每步最多处理 16 KiB，最多接受八条中间响应。GCC 16 分片、边界与 EOF 测试及异步 TLS/OpenSSL 关闭定界互操作通过；Mixed 普通 HTTP 正向代理也已使用该状态机，并通过转发、上传与 Expect 回归。输出沿用代理的 `Connection: close` 策略，尚不提供连接池或正式 HTTPS 调度。

私有 `https_exchange` 将已认证 TLS 连接与该状态机组合为一次请求，默认要求 `http/1.1` ALPN，调用者可以显式允许对端不选择 ALPN；输出通过同步、非重入回调分段交付。调用方负责建立连接、验证身份、构造请求、管理期限和对象寿命；结果不可用于连接复用。GCC 16 io_uring/OpenSSL 验证了大请求、关闭定界、定长、chunked 和无正文响应，以及截断、畸形 chunk、ALPN 缺失和回调拒绝；广泛故障注入及正式业务接入仍待验证。

| 边界 | 职责 |
| --- | --- |
| HTTP 公共模型 | method、URI/authority、状态码、字段、body/trailer 事件及应用语义 |
| HTTP/1.1 核心 | 增量字节输入、语法/消息长度、编码、连接复用及切换状态 |
| HTTP/2 适配（未来） | libnghttp2 session、帧/流事件、HPACK、流控及错误映射 |
| 异步连接驱动 | Corosio 部分读写、背压、deadline、取消、TLS 流与输出寿命 |
| 应用适配 | 正向代理/CONNECT、规则集获取、可选管理接口和 HTTP 承载各自的策略 |

公共模型不暴露 nghttp2 对象，也不将 HTTP/2 的所有语义硬套为 HTTP/1.1 文本消息。不同用途声明支持的 method、消息大小、重定向、认证和内容编码；共享协议实现不代表同时实现浏览器、通用 Web 服务器和完整缓存代理。

## HTTP/1.1 状态与消息边界

核心接收字节片段与显式 EOF，返回已消费长度、需要更多数据、头/体事件、消息完成或错误。输入和输出均支持部分处理；头部、chunk、body 与下一条消息可能落在同一缓冲中，不能丢掉剩余字节。解析器可暂停，body 以有界片段传递，不能要求收齐整个响应后才转交。

消息 framing 以 [RFC 9112](https://www.rfc-editor.org/rfc/rfc9112.html) 为规范依据；方法、状态与 CONNECT/Upgrade 的含义依据 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)。实现前固定采用章节和勘误，以下是重点验收范围，不宣称已经完整实现规范：

- 请求行、状态行、请求目标各种形式、字段名称和值、CRLF 及严格语法策略。
- Content-Length、Transfer-Encoding、chunked、trailer 和关闭定界，区分无 body 与零长度 body。
- HEAD 响应、1xx/最终响应、204/304 及成功 CONNECT 对 framing 的影响，绑定对应请求上下文判断。
- 不同消息长度描述的冲突与重复字段，绝不将有歧义的输入继续透传成另一端的不同消息边界。
- chunk 长度及计数溢出、提前 EOF、部分 header/body、管线化消息和持久连接边界。

安全草案采用严格接收策略：拒绝不支持/有歧义的 TE/CL 组合、非法长度和折行，不先“修复”后盲目转发。字段保留顺序与重复值信息，不能用单值 map 隐去 framing 冲突；按字段定义处理组合，不合并 Set-Cookie 等不适用字段。

代理适配负责验证 target/Host/authority 一致性、逐跳字段及 Connection 指定字段、代理认证作用域。协议核心不得把字符串拼接当作 header 编码，写入路径也检查注入和长度。首期若不支持 pipelining、多种 Transfer-Encoding 或特定 Upgrade，应明确策略并安全结束连接，不能错位解析下一请求。

## HTTPS 与 CONNECT

HTTP/1.1 over TLS 继续由 Nexus 完成握手、验证身份和 HTTP 处理。连接地址、SNI、验证名称与 HTTP authority 分别建模，连接池不能因同一 IP 就跨身份或代理凭据复用。

HTTP 正向代理建立 CONNECT 后，成功应答完成才切换为隧道；应答和隧道首字节相邻时保留预读内容。通过 CONNECT 转发客户端 HTTPS 时，隧道内 TLS 属于客户端与目标，代理不自动终止或解密它。自研 HTTPS 不等于加入透明解密功能。

TLS ALPN 只通告实际可用的应用协议。尚未接入 HTTP/2 时不能为追求握手指纹通告 h2 后继续按 HTTP/1.1 解析；版本选择是连接建立状态的一部分，协商后的数据不能任意回退重解码。

## 后续 libnghttp2 接入

nghttp2 官方说明核心库不执行网络 I/O，接收输入字节、产生输出字节，并通过回调交付协议事件，适合放在自有运行时中。此处“纯状态机”指无 socket/TLS/event-loop 的协议边界，不是无内部状态、无分配或所有应用策略均由库完成。[官方架构说明](https://nghttp2.org/documentation/programmers-guide.html)

接入时优先评估 `nghttp2_session_mem_recv2` 与 `nghttp2_session_mem_send2`，具体 API 以锁定版本为准。适配层维护 consumed 长度、暂停与恢复；库输出 buffer 具有受限寿命，下一次取输出前必须完成发送或复制到有预算的自有队列，不能持有它跨异步写入后又驱动下一次发送。[输入 API](https://nghttp2.org/documentation/nghttp2_session_mem_recv2.html)、[输出 API](https://nghttp2.org/documentation/nghttp2_session_mem_send2.html)

每个 session 的驱动串行化；回调中提交允许的事件/帧，返回后再驱动输入输出，不从回调重入 send/recv。NGHTTP2 的 C 回调不承载可挂起协程，错误映射为公共 expected/事件，并避免异常穿越 C 边界。

适配器还需处理连接/流两级窗口、消费后窗口更新、DATA 延迟供应、RESET、GOAWAY 和流生命周期；头列表、HPACK 状态、并发流、待发送 body 与控制帧开销全部计入预算。单流超时不能直接销毁承载其他流的 session。GOAWAY 后重试依据请求是否已执行、幂等性与 body 可重放性，不能自动重发任意请求。

仅引入 libnghttp2 核心库，工具、示例服务器和它们使用的 TLS/事件循环不进入 Nexus 运行依赖。当前通过 `xmake f --http2=y` 启用固定包和实验性内存服务端会话。会话同步交付借用的头部与 DATA，调用方必须在回调返回前处理数据；输出复制到调用方缓冲区，禁止驱动重入。nghttp2 内部使用逐会话分配器，默认将活跃请求大小和分配头合计限制为 4 MiB，可通过 `library_memory_bytes` 配置；内存耗尽等 nghttp2 致命错误会使会话失败。扩容时按旧块和新块的请求大小同时预留，可能比原位扩容所需空间更保守；峰值计数反映这一预留。此预算不包括分配器自身开销，也不包括 Nexus 的头部、响应、TLS 和传输缓冲，因此不是完整连接内存预算。并发流 SETTINGS 和头块限额同样不是完整预算；响应提交现支持有界空体、会话拥有的有界响应体及普通响应头，数据经 nghttp2 provider 分片读取。附加响应头默认限 32 项和 8192 字节，必须为合法小写字段；伪头和连接专用字段禁止；普通响应的 `content-length` 必须与响应体一致，HEAD 和 304 的表示长度由应用保证正确，204 不允许该字段。HEAD 不发送响应体，初始请求头未完成前不能提交响应；nghttp2 负责复制编码；重复提交、未知流、单响应超限和并发响应总预算超限均被拒绝。响应体以精确大小的独占数组持有，`response_memory_used()` 报告当前持有的响应体字节；流关闭或重置处理后释放，提交失败也会释放。该计数不包括分配器开销和其他缓冲。 `shared_memory_bytes` 可额外限制 nghttp2 活跃分配、持有的响应体、活动流对象、请求头、提交响应时临时字段数组及 TLS 驱动输入、密文记录、输出、步骤暂存和常驻读取缓冲预留的逻辑额度之和，默认不再施加额外上限；`shared_memory_used()` 报告这些项目之和。响应字段数组按字段数量（包括 :status）乘 nghttp2 字段对象大小计费，提交结束或失败时归还；额度不足返回 `budget_exceeded`，响应可重试。活动流按对象大小计费并在流关闭时归还，链表节点额外开销不计入；请求头逻辑额度为字段对象大小加名称及值的字节数，头块完成或失败时释放；超额会重置当前流。响应体直接超限返回 `budget_exceeded`，预留响应后 nghttp2 分配失败按其致命错误处理并释放响应体。请求头计数不代表 vector/string 的实际容量；这个共享上限不包含多余容量、链表节点额外开销、TLS 其他缓冲、传输、分配器开销或其他临时副本，不能视为完整连接预算。输入 DATA 回调可暂停，调用方必须显式恢复后再提交后续输入。接收侧关闭 nghttp2 自动窗口更新，`accepted` DATA 在回调内确认，`pause` DATA 由 `resume_input` 确认；`ServerLimits::outbound_ack_frames` 还限制输出停滞时自动排队的 PING/SETTINGS 确认帧，超限会使会话失败。HPACK 编码动态表上限配置给 nghttp2，解码动态表上限通过 SETTINGS 通告；对端确认之前解码表仍按协议默认值处理。内存对端已验证零表大小的 SETTINGS 和后续请求，HPACK 的 nghttp2 内部分配受该预算约束；仍需测量其他层的资源使用。两阶段关闭接口先排队 GOAWAY 通知，再以最后处理的流 ID 排队最终 GOAWAY，并继续处理已接受的流；调用方负责发送通知、等待在途请求、排空输出和关闭传输。异步输出背压和连接级完整总内存预算尚未实现。实验性单所有者驱动现可组合 Corosio、要求 `h2` 的 TLS 握手和 HTTP/2 服务端会话：逐步排空输出并处理输入，暂停时保留明文余量，仍可发送已排队的输出；输出排空后返回暂停状态，调用方在回调外恢复或响应。真实 TLS 测试验证上传暂停期间提交并发送响应，再恢复输入；另验证上传流暂停时另一个流发送响应并关闭，暂停流仍可恢复并完成。Python/OpenSSL 对端已验证证书、ALPN、分片请求、上传暂停恢复、两个并发流、两阶段 GOAWAY、双向 TLS close_notify、截断拒绝、空闲读超时和取消；curl 也已完成 HTTPS/HTTP/2 请求。上述网络测试在 epoll 和 io_uring 下运行。关闭前检查排空结果是否仍与会话状态一致；调用方负责完成握手并确认 ALPN、两阶段 GOAWAY 间等待、超时及 socket 生命周期，并串行化会话操作。该驱动尚未接入运行时应用，未验证完整连接预算和更广泛的关闭流程；h2c、扩展 CONNECT 和服务器推送仍未实现，因此现有应用不能通告 h2。

应用可对已打开的流排队 RST_STREAM；排队后不能再为该流提交响应或重复重置。关闭回调发生时释放流及其响应预算，调用方须继续排空输出。若该流的 DATA 回调处于暂停状态，先处理并恢复输入，再请求重置；这避免在仍借用输入时丢失确认状态。

当前 TLS/HTTP2 实验驱动的缓冲核查（均为内容长度，非分配容量或进程内存上限）：

| 所有者 | 内容与寿命 |
| --- | --- |
| TLS 输入 | `ApplicationInput` 固定 4096 字节，保存传输读取或握手余量，超过 4096 字节的握手余量会使已认领的 HTTP/2 会话立即失败；`RecordStream` 同时累积至多 16645 字节（5 字节头加 16640 字节密文），完整记录移交给解密调用。解密后的单条明文内容最多 16384 字节。 |
| TLS 握手后消息 | `ApplicationRecords` 的重组内容最多 147724 字节；这是客户端接收票据所需的通用上限。服务端仅接受 KeyUpdate，重组内容在插入前限制为五字节；解密一条记录时仍有单记录临时缓冲。消息消费完毕时释放该向量的分配；失败时随记录所有者销毁。 |
| HTTP/2 输入 | 驱动接收一个 TLS 明文事件并持有其余量，暂停时可跨多次 `step` 保留，最多 16384 字节；会话回调借用它，不得在回调外继续持有。消费完毕后释放该向量的分配。 |
| HTTP/2/TLS 输出 | 每次 `step` 的协程帧含 16384 字节 HTTP/2 输出数组，`send_all` 借用它直到完成；TLS 输出一条未填充记录最多 16406 字节，异步写入另持有最多同样大小的副本直到完成。部分写入后仍持有原记录，副本按剩余部分重建；记录完整写出后释放原记录的分配。 |

驱动成功认领时为其固定 4096 字节读取缓冲预留共享逻辑额度，额度不足使已认领会话失败、驱动无效；该额度保留到驱动销毁，即使连接已取消。每次 `step` 开始执行时为 16384 字节输出数组预留共享逻辑额度，步骤返回或挂起操作完成后归还；协程帧在开始执行前可能已经分配，帧及分配器开销不包含在内。驱动串行执行 `step`，但暂停时保留的 HTTP/2 输入可以与输出数组、TLS 待写记录及写副本并存；通用 `ApplicationConnection` 还允许一个读操作和一个写操作并存。记录解密时密文与明文并存，封装时明文、加密结果及最终记录也可能暂时并存；向量扩容和密码库内部也可能产生临时分配。取消会释放 TLS 部分输入记录及待写记录的分配并发起 socket 取消；挂起写入的独立副本仍须等操作完成后释放，所有者也须等待读写完成后才能销毁。通用流式读取器消费完一个明文事件后也释放其分配；这些释放不保证分配器立即将内存归还操作系统。应用输出从会话取出后、TLS 加密前预留 `2 × max(输出字节数 + 22, 27)` 字节，覆盖一条待写 TLS 密文记录和挂起写副本的逻辑长度（含可能先发送的 KeyUpdate）；额度不足使会话失败且不发送这批输出。预留跨异步写入保留，写入成功或失败完成后归还。驱动读取前从 `shared_memory_bytes` 同时预留 16384 字节明文、16645 字节密文记录和 54 字节控制输出额度；KeyUpdate 响应在读取中生成时保留后者直到写入完成，否则读取完成后归还。密文记录预留在读取完成或取消排空后归还。发送 close_notify 前预留 48 字节并在写入完成后归还。额度不足则返回 `budget_exceeded` 并取消驱动；明文预留贯穿 DATA 暂停，直到输入处理完成后归还，挂起读取取消完成后也归还。会话仅允许一个 TLS 驱动认领，重复驱动返回无效状态且不干扰原所有者；驱动拒绝客户端角色或尚未准备好接管的 TLS 记录状态并使已认领会话失败；包括已移动、关闭、方向不匹配、记录限制无效、发送密钥已耗尽或无法更新，以及有未完成控制消息的状态。驱动取消、销毁或发生传输、预算失败后会话转为失败，不能把关联会话接到新传输；这也防止恢复时引用已释放的输入。挂起操作完成前保留其所需缓冲。步骤和 close_notify 执行中捕获 `bad_alloc`，取消传输、使会话失败并归还操作预留，返回 `allocation`；其他异常清理后继续传播。协程创建前的分配失败仍由调用方处理。已从会话取出的输出若未完整发送即失败或取消，会话同样转为失败；已发送前缀不能撤回，持有的响应体随会话销毁。这些预留覆盖输入明文、输入密文记录及输出密文和写副本的逻辑长度；握手消息重组、容量、协程帧及分配器开销、传输和临时对象仍未计入，不能把这些长度相加作为严格的实际内存上限。完整连接预算需要在分配或保留容量前统一记账，明确临时副本及传输层的边界，并在取消和异步完成后释放额度。

后续连接预算应先限定为**连接 owner 控制的用户态存储**，并分别报告未纳入的开销；它不是 RSS、内核 socket 缓冲或整个进程的上限。握手开始前建立预算所有者，贯穿握手、ALPN 交接、HTTP/2 会话及取消后的异步排空，最后一个借用或操作结束后才能销毁。调用方持有的请求处理数据、外部任务及密码库或传输后端无法归属到该 owner 的分配，需要另有上限或明确作为排除项，不能靠本计数推断其大小。

现有实验会话可接收共享 `nexus.memory.budget` 所有者，其上限须与 `shared_memory_bytes` 一致；调用方可在会话创建前取得可移动预留，会话的各项逻辑计费与这些预留竞争，`shared_memory_used()` 包括二者。所有者最多连接一个会话，创建失败和会话销毁时解除关联；预留独立持有所有者，直至释放。所有操作须由连接的同一执行器串行化。该机制仅为跨阶段记账提供所有权基础，TLS 握手尚未自动申请预留，也没有控制其实际分配，不能视为握手或连接总内存上限。

实现这个边界前需要逐项解决：

- 握手阶段的记录、消息重组和交接余量必须在分配前计入同一所有者；交接时转移所有权和额度，不能出现释放额度但数据仍存活的窗口。
- 容器按实际保留容量及受控分配计费，增长时覆盖旧、新分配可能共存的峰值；nghttp2 的 `realloc` 已按旧块和新块同时预留请求大小，但仍不包含分配器开销。不能将当前按内容长度预留的额度直接当作容量计数。
- 密文、明文、加密结果和异步写副本并存时分别计费；暂停输入和取消后尚未完成的操作继续持有额度。协程帧及固定成员在创建前计费，或以明确的固定开销单独限制；仅在协程开始执行时预留不能限制其创建分配。
- 对无法经预算分配器控制的密码库、分配器元数据和后端开销，先确认可测量或有可证明的上限；否则将其列为排除项，并避免声称严格的实际内存上限。

验收需用受控分配和失败注入检查分配前拒绝、扩容峰值、握手交接、暂停输入与输出并存、取消后完成回调，以及所有操作真正结束后的额度归零。还需验证单连接耗尽不会破坏其他连接，区分预算拒绝与系统分配失败；实际 RSS 测量可辅助容量规划，但不能替代上述所有权检查。当前这些是设计目标，并非已实现的保证。

## 资源、停止与验收

头部字节/数量、请求行、单字段、chunk 扩展、trailer、body 队列、活动连接/流和池有独立预算；body 可流式处理，业务文件大小限额由调用者设定。头部/body 进度超时和完整操作 deadline 分开，持续滴入字节不能无限占用资源。解析工作每轮有预算，防止始终就绪的连接独占执行器。

HTTP/1.1 连接只有消息边界明确、无未处理输入/输出且按策略可复用时进入池；取消、未读 body、framing 错误和关闭定界响应需明确排空或关闭。共享 session 停止先拒绝新操作，再按期限排空与取消，最后销毁协议状态和 TLS/底层连接。

验证从分割到每字节的固定报文开始，覆盖恶意 framing、重复字段、请求走私差异、EOF、首包、背压、超时和池复用。HTTPS 加入证书负例、ALPN 与独立实现互操作；HTTP/2 后续增加流控、HPACK 资源、RESET/GOAWAY 和驱动不重入测试。自实现两端互通不能单独证明正确，验收入口见[网络验证](../planning/network-validation.md)。
