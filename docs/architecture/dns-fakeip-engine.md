# Fake-IP 分配池与连接嗅探

状态：设计草案；已有独立 IPv4 内存地址池实验，尚未接 DNS、路由、配置或持久恢复。Fake-IP 是 DNS 给客户端的短期地址令牌，不是目标真实地址或身份认证；它与普通 DNS 缓存、负缓存及乐观缓存分开。已有约束见 [DNS 设计](dns.md)、[状态恢复](state-and-cache.md)和[DNS 状态验证](../planning/dns-state-validation.md)。

实验 `nexus.dns.fakeip` 在单执行上下文中管理调用方指定的连续 IPv4 可分配范围（最多 65536 地址），规范化有限 ASCII 域名并按 view 区分，发布时保护 TTL 加缓冲，pin 阻止复用，游标扫描安全候选，池满拒绝。查找和 pin 使用池身份及代次，旧令牌不得跨池或跨池生命周期使用；未知地址以空结果报告，调用方须区分池内未知地址并拒绝。它不自行判断 CIDR、保留地址或跨池冲突，不实现 LRU、IPv6、并发、持久化或重启隔离；范围合法性和异常后保护仍是接入前的要求。GCC 16 测试覆盖大小写、视图、重复发布延长保护、满池、pin、复用、旧令牌、时间倒退与溢出。

实验 `nexus.dns.fakeip_response` 将受限 DNS 报文与地址池组合：接受单个未压缩 IN/A 问题和可选的无标志、无选项 EDNS(0)，返回单条带池 TTL 的 IPv4 答案；EDNS UDP 大小上限为 1232。其他类型、EDNS 标志或选项、压缩问题和非标准查询标志明确返回不支持，池满返回错误。待发应答持有地址 pin，明确完成后释放：可能已发送时从完成时间重新计算 TTL 加缓冲，确认未提交才直接释放；时钟错误保留 pin，未完成对象被丢弃也保留 pin，避免不明在途发送后地址被复用。调用方须串行驱动、限制待发数量、保持池和缓冲活到 I/O 完成，不能在发送完成前标记取消；缓冲期还须覆盖合理的网络传播延迟，完成不等于客户端收到。尚无通用 DNS 服务端、真实迟到完成验证、DNSSEC 或持久恢复。

实验 `nexus.dns.fakeip_target` 将已分配范围内的未知地址和不匹配视图作为错误，范围外返回普通地址；有效映射返回域名与持 pin 的连接句柄，连接结束时显式释放。句柄丢弃或释放时间异常会保留 pin，防止误复用但可能耗尽容量。这里的范围仅为池的连续可分配区间，不包含 CIDR 中额外的保留地址或其他已禁用/历史池；接正式路由前必须统一识别整个 FakeIP 地址空间并处理所有上下文，不能据此认定范围外地址安全直连。

实验 `nexus.dns.fakeip_registry` 在单执行上下文中持有多个池及其完整 IPv4 范围，包含不可分配的保留地址；范围不能重叠，纯保留区和停用区内的目标均拒绝，已取得的句柄在停用后仍可释放。应答由 registry 创建，停用后拒绝新应答，已创建的待发应答仍须完成或确认未提交。停用不移除范围，防止同一 registry 生命周期内将旧地址误作普通地址。调用方不得保留转移进 registry 的池别名或绕过它发布，须保证 registry 比应答和连接句柄存活得更久；丢弃未完成的对象不会自动释放 pin。范围数量有界，注册时调用方负责提供所有需保护的范围；进程重启后不会自动恢复历史范围，未注册范围也无法识别。GCC 16 测试覆盖重叠、边界、保留区、视图、停用、待发应答与释放；尚未接入实际 DNS 或连接路由。

registry 可选用隔离期创建全新空池：从调用方指定的单调时钟起点经过指定的正时长之前，拒绝应答，池内目的地址仍按未知地址拒绝；期限到达后才允许发布。时间倒退到起点前及期限溢出会拒绝。此机制只提供进程内计时，安全性依赖调用方在旧 owner 停止后取得跨进程独占，并覆盖旧配置、未完成发送和网络传播的最大对外 TTL 加缓冲；还依赖客户端遵守 TTL，不能恢复旧映射或保护无限期缓存。每次启动均须重新隔离并登记所有历史范围，持久配置、独占锁和真实重启流程尚未实现，因此不能宣称已经具备重启安全。虚拟时间测试覆盖隔离前、边界、时钟和溢出。

Linux 回环测试将 registry 与 Corosio UDP 的实际接收和发送组合：验证应答待发时不能复用、发送完成后客户端能解析地址、目标句柄在 TTL 后继续阻止复用，以及发送前停用后已有应答仍可完成。发送启动前已取消的测试返回取消和零字节，接收端未观察到数据报，释放 pin 后到期可复用；关闭挂起接收后事件循环排空。测试使用虚拟池时间，待发 pin 的检查发生在提交发送前；尚未验证内核已提交发送的取消、迟到完成、网络传播上界或生产监听器，不能将其他取消结果当作确认未发送。

私有实验 `FakeIpListener` 仅绑定 IPv4 回环，单执行器串行接收和发送，每次只持有一个应答；畸形、超长或不支持的查询直接丢弃，对已验证的受支持查询在池满、隔离、停用和其他 registry 故障时返回 SERVFAIL。成功应答的发送完成（包括错误或取消）均按可能已发送保护映射。停止关闭 socket，owner 须保持监听器和 registry 存活直到协程返回。GCC 16/io_uring 回环测试经现有 UDP 客户端查询，验证超长及畸形数据报后仍可应答、EDNS 成功应答、池满和隔离期 SERVFAIL、反查原映射、停止及排空；尚未接入配置、正式路由、TCP、EDNS 选项、并发处理、故障注入或已提交发送取消，不是完整 DNS 服务。

实验 `nexus.dns.fakeip_request` 把已知 IPv4 或 IPv4 映射 IPv6 FakeIP 的 SOCKS 请求目标改为对应域名，保留端口和连接 pin；普通 IP 和域名原样传递，注册范围内未知地址与错误 view 拒绝。转换必须发生在域名路由 preflight 和解析之前，连接所有活动结束后在 registry 执行器释放 pin。另提供解析结果检查，拒绝所有登记范围（包括保留和停用范围）中的 IPv4 及 IPv4 映射 IPv6，供每个拨号候选防环回使用。GCC 16 测试覆盖两种地址形式、普通地址、保留地址、停用范围、视图、两个连接和复用。正式代理支持多 worker，尚无共享 registry 的串行 owner 或跨执行器释放；转换和解析结果检查均未接入正式拨号，也没有真实 DNS 防环回端到端验证。

实验 `nexus.dns.fakeip_shared` 用互斥锁串行化多线程 registry 操作，响应和目标句柄共享持有底层状态，外层 owner 销毁后仍可完成或释放；丢弃未完成句柄仍保守保留 pin。单个句柄和其借用报文仍由一个调用方管理，不能并发操作或在发送完成前销毁。共享 owner 必须先登记至少一个范围并不可逆地冻结，才能发布、反查或检查目标；冻结后禁止新增范围，停用仍保留范围。冻结和新增在同一把锁下竞争，避免检查后新增范围；调用方仍须确保登记了全部历史范围。无时间参数的操作在获得锁后采样单调时钟，避免线程等待导致采样顺序颠倒；显式时间接口供虚拟时间测试，调用方须保证顺序。实验 UDP 监听器、请求转换和解析结果检查已使用共享 owner；GCC 16 回环测试在四个工作线程持续发布、反查和释放时完成 DNS 查询，另验证冻结竞争、八线程真实时钟操作和 owner 销毁后的跨线程句柄释放。锁内的解析与分配会阻塞工作线程，负载和异常路径尚未评估；尚未接正式服务、跨进程排他或重启恢复。

共享 owner 支持登记纯保留范围，无须为旧地址分配池，且不受可分配池 65536 地址上限限制；此范围参与重叠检查，冻结后不可新增，其内所有目标及解析结果均拒绝。GCC 16 测试覆盖大范围边界、重叠和冻结。隔离期至少等于当前池的 TTL 加保护期；旧配置可能要求更长期限，调用方仍须覆盖历史 TTL、传播和在途完成并保证独占。此机制不自动保存或发现历史范围，启动配置和持久状态仍须提供完整清单。

实验 `nexus.dns.fakeip_recovery` 接受当前池与最多 256 条历史范围及各自最长保护期，合并重叠或相邻的旧范围，保留当前池外的历史地址，并按当前及历史保护期的最大值加传播缓冲创建隔离池、冻结 owner。历史更新操作将当前池加入记录并保守保留各合并范围的最长保护期，超限拒绝；调用方必须在发布前可靠提交更新。边界、溢出与隔离期限通过虚拟时间测试。它不读取或保存历史，也不持有进程锁；调用方必须先取得稳定的排他权并提供完整可信的持久历史，持续持锁直至应答和连接排空，因此这还不是重启安全的正式实现。

实验 `nexus.dns.fakeip_history` 将规范化历史编码为版本化、有长度上限的二进制记录，绑定调用方提供的实例 ID 并使用 HMAC-SHA256 验证；严格拒绝非规范范围、无效保护期、截断与多余字节。GCC 16 测试覆盖篡改、错误密钥、错误实例及重签非法记录。密钥管理、可靠提交和所有权尚未接入；认证无法检测旧的有效记录被回滚或删除，不能单独保证历史完整。

Linux 文件夹具组合历史编码、私有目录锁、文件和目录同步，再创建隔离 owner。进程杀死及受控失败测试覆盖提交各阶段的可见状态、锁竞争和损坏记录拒绝；这不模拟断电，故障分支也不等同真实系统调用故障。夹具采用固定测试密钥，依赖锁文件和目录不被替换，未解决防回滚、密钥管理或正式服务生命周期。

历史夹具另用 `LD_PRELOAD` 在真实调用层注入部分 `write` 后 EIO、文件 `fsync`、`renameat` 和目录 `fsync` 错误；各路径保持旧状态并禁止发布，故障解除后可继续更新。该探针仍是用户态拦截，不代表内核、设备或断电语义，不能替代文件系统实测。

实验夹具为快照加入单调 generation 和独立 high-water 文件：读取到低于 high-water 的认证快照即拒绝；历史文件先提交而 high-water 尚未更新的崩溃窗口可在重启时采用更高代次并补写 high-water。若攻击者同时回滚或删除两者，仍无法检测；high-water 需与可信防回滚介质、密钥和稳定 owner 结合，不能把该夹具当作完整持久性保证。

项目 store 将显式首次创建和已有状态恢复分开：恢复要求历史和高水位均存在，权限、类型、链接数、长度或读取不正确时拒绝。首次提交在高水位写入前中断时也会拒绝恢复，须由上层进行受控修复；不能仅凭文件缺失判定这是首次启动。实验文件夹具仍使用较宽松的缺失语义，不代表项目 store。

历史文件夹具从同一私有目录读取 32 字节历史密钥和 16 字节实例身份，要求当前用户、0600 常规文件、单硬链接并拒绝最终符号链接；认证绑定实例身份，身份或密钥不匹配时不恢复。测试仍直接预置密钥，未定义正式密钥存储、轮换、撤销或跨主机共享。

项目模块 `nexus.dns.fakeip_history_store` 将目录锁、快照读取和两阶段提交组合成可复用 owner：历史文件必须先完成文件与目录同步，随后才更新高水位；store 在整个生命周期锁定目录 inode 和 `owner.lock`。在本地 Linux 文件系统上，所有 owner 均使用该实现时，即使 `owner.lock` 被删除并替换，新的 owner 也不能取得同一目录 inode 的锁。锁是协作式的，替换整个目录仍可产生独立 owner；不同文件系统的锁语义尚未验证。实验性 `start_fakeip` 消费已打开的 store，合并并提交历史后才返回隔离的共享 owner；owner、应答及目标句柄保留锁，隔离期从提交完成后计算。提交后创建 owner 若失败，历史可能已经推进，必须重开并重新恢复。首次创建模式、密钥和实例由调用方可信地选择或传入，不提供防止整个目录、密钥或设备状态一起回滚的保证，尚未接入正式服务。

实验性 `open_with_credentials` 在获取目录锁后通过同一目录描述符读取预置的 `instance.id`（16 字节）和 `history.key`（32 字节）。两者须为当前有效用户所有、模式 0600、单硬链接的普通文件，拒绝最终符号链接和错误长度；store 移动和销毁时清理内部密钥副本。文件须由可信外部机制预置并保持稳定；该校验不阻止同一用户替换目录或文件，也不提供密钥生成、轮换或防回滚。

store 成功打开后保留已认证快照及其 generation，供上层传给恢复组装器；commit 成功后才替换内存快照。调用方必须将 commit 和 owner 创建作为顺序操作，任何提交错误都不得对外发布当前池。

store 提交 I/O 错误后进入失败状态，清除对外可见的内存快照并拒绝同一实例继续提交，需关闭后重新读取磁盘状态。迁移测试将已提交历史交给恢复组装器，验证旧范围保留与隔离期限边界。

store 的测试在历史和 high-water 两个提交阶段分别对写入、文件同步、重命名和目录同步注入 EIO，验证失败不应被当作提交成功；探针是用户态 `LD_PRELOAD`，不代表掉电一致性。

纵向回环夹具通过实验 UDP 监听器查询 `localhost` 并取得 FakeIP，将其转换为域名；受控本地上游 DNS 实际返回两个 A 记录，依次为 FakeIP 和 `127.0.0.1`，夹具拒绝第一个候选并检查、连接第二个候选，与本地 TCP 对端交换数据，连接结束后释放 pin。GCC 16/io_uring 通过；这是夹具手动串接各组件，并非正式代理的拨号或策略路径，也未验证跨进程重启或网络故障。

另有非默认实验构建 `nexus-proxy-fakeip-experiment`，在现有代理 TCP 拨号路径前转换 FakeIP，并检查每个解析出的候选；共享 owner 传给所有 worker，会话的最后一个引用销毁时关闭 socket 并释放连接 pin。测试夹具直接注入已冻结 owner，未启用 KDL 或正式二进制支持。GCC 16/io_uring、单及双 worker 的真实回环测试验证 SOCKS 和 HTTP CONNECT 转发、IPv4 映射 IPv6 目标、域名规则在 DNS 前阻断、未知池内地址拒绝、受控 DNS 中 FakeIP 候选被过滤、连接跨 TTL pin 和结束后复用，以及双 worker 活动连接停止。测试发现 HTTP 和 VLESS 内部目标未填完整状态及长度，已在各入站补齐；常规 Mixed 和 VLESS 入站回归通过。更多取消、异常及其他入站的持久恢复仍未验证；不可作为正式 FakeIP 服务能力。

另一个非默认夹具将持久 store 的恢复 owner 同时注入本地 UDP FakeIP 监听器和 Mixed 代理：真实 DNS 查询在隔离期返回 SERVFAIL、到期后返回旧池地址，随后强杀进程；重启迁移并验证旧地址和 DNS 候选被拒、新池隔离到期后 DNS 应答及 SOCKS 回环转发、活跃 owner 锁竞争以及再次重开保留历史，单、双 worker 均通过。强杀不模拟断电或可信存储回滚；夹具没有接入系统 DNS 或正式服务配置。

启动故障测试还通过用户态系统调用拦截，在历史及高水位各阶段注入 EIO，或在文件 fsync、rename、目录 fsync 成功后暂停并强杀进程；单、双 worker 均确认故障前未调用 `listen`，独立重开后检查可见历史及旧池隔离。成功启动的监听探针同时校验拦截有效。进程崩溃和目录同步失败后的当前可见状态不证明断电持久，也不能证明设备故障语义。

真实 UDP DNS 测试在 Corosio 同步推测 `sendmsg` 分支注入 EIO：分别未发送即失败，以及先实际送达应答再伪造失败；单、双 worker 均验证地址在 TTL 内不被其他域名复用、保护期后可复用，监听器报错且持久 owner 锁不释放。实验夹具将监听器错误通知代理执行线程，关闭监听并排空活动 SOCKS 转发；测试验证转发两端关闭和新连接拒绝。该测试不覆盖已提交到 io_uring 的发送与取消竞争，故障传播尚未接入正式服务。

普通 HTTP 实验测试也通过：以 FakeIP 为绝对 URI authority 时，路由使用恢复域名，发往真实目标的请求改为 origin-form，Host 保持原始 FakeIP authority；域名阻断在 DNS 查询与目标连接前发生。该行为没有将权威域名自动改写为 HTTP Host，可能不适合依赖虚拟主机的目标，未来若提供改写须作为明确策略设计；目前测试只覆盖单次 GET，不代表完整 HTTP 互操作。

## 地址池与索引

IPv4 可以显式选择 `198.18.0.0/15` 的受限子网作为实验地址池；该段是基准测试专用地址，并非 Nexus 独占私网，必须检测宿主/内网/VPN 冲突。IPv6 使用用户配置并检查冲突的范围，不假定所有保留前缀可安全占用。地址池可用范围、DNS 视图、实例 owner、容量及代次形成配置身份；范围、地址族或 owner 改变时不能悄悄复用旧映射。

运行态同时维护 `canonical_domain + qtype + view → lease` 和 `fake_address → lease`，同一系统地址空间内地址不可属于两个不同 view/域名。映射包含唯一代次、DNS TTL、最后一次对外发布的到期界限、活动连接引用、最近使用时间及持久状态。分片哈希表或紧凑数组、free bitmap/游标可作为候选：从游标环形寻找空槽，跳过预留、冲突、已占用与隔离地址；回绕和表满有确定终止条件。需要按 shard 或单 owner 协调正反索引及占位/提交，不能让两个并发查询把同一地址发给不同域名。

LRU 只从**满足安全复用条件**的候选中选最久未使用项，不是把最旧条目立即覆盖。至少满足：没有活动连接 pin；此前每次发给客户端的 DNS TTL 已到期，外加配置的传播/时钟缓冲；持久化与代次策略允许复用。重复应答要更新“最后发出时间 + 对外 TTL”的上界，普通访问不应无上限延长 DNS TTL。池满而没有合格候选时返回明确错误（例如 DNS SERVFAIL），记录容量指标；不能静默把已发布地址重新分配。是否允许在耗尽时绕过 Fake-IP 返回真实地址是显式策略，默认关闭，因其可能改变路由和泄漏查询。

查询 A/AAAA 按独立池与 qtype 管理；域名规范化、IDNA 输入策略、视图隔离及 DNSSEC 行为与 DNS 设计一致。DNS 回答必须匹配已提交的反向映射；普通 DNS 过期乐观缓存不得延长 Fake-IP 归属。池内地址没有匹配映射时不能把它当真实公网 IP 直连，应按策略拒绝或诊断。

## 重启与持久性

崩溃后客户端可能仍持有未过期地址。若承诺每个已应答的映射可反查，必须在发出 DNS 应答之前把映射及相关分配状态持久提交到可恢复介质，明确事务、fsync 与磁盘失败行为；普通异步批写/定期快照不足以证明这一保证。若选择低开销批写，则明确只提供较弱保证：未恢复映射时拒绝未知池内地址，并在不确定状态下隔离地址一段不短于此前最大对外 TTL 与缓冲的时间，再谨慎复用；配置变化和多进程也需覆盖。

恢复检查地址范围、owner、代次、重复正反索引和持久数据完整性；损坏或版本不兼容不能静默清空后立即重发同一池地址。持久文件编码和提交策略仍待决定，[BEVE schema 草案](beve-schemas.md)不是当前已实现的持久化保证。

## 捕获与嗅探

入站先保留原始目的 IP/端口及来源。目标为已知 Fake-IP 时反查其权威映射并 pin 对应 lease；将恢复域名作为路由目标，选 direct 出站时通过该视图的上游解析真实地址，不把 Fake-IP 发到互联网。直连目标为普通 IP 时可按显式策略做有界嗅探，获得**不可信的候选域名**，连同来源、原目标、可信度和时间一起送入路由；不把普通 DNS 的 IP→域名反查结果当成唯一归属。

| 入口 | 可提取信息 | 限制 |
| --- | --- | --- |
| TCP TLS ClientHello | 明文 SNI、ALPN 等经长度校验的字段 | ClientHello 可能跨多次 read、TLS record 或握手片段；ECH 可隐藏真实名称，缺失/不合法时不猜测 |
| 明文 HTTP/1.1 | request-target 的 authority 或 Host | 需校验 framing、头数量/长度、多个 Host/冲突及 CONNECT 与普通请求的目标语义；不能从 HTTPS 密文读取 HTTP Host |
| UDP/QUIC | 首版不承诺通用域名嗅探 | QUIC Initial 的加密与分片需专门实现，ECH、版本及重传还需处理；未知时保留 IP 目标 |

对于可连续读取的字节，解析器在会话拥有的缓冲上使用 `std::span`/offset，不修改原报文；跨 record 或跨缓冲时可使用有上限的聚合缓冲，不能宣称任意分片都零拷贝。嗅探消耗的字节必须按原顺序完整交给后续握手/转发，缓冲在所有借用结束前不复用。设定最大字节、记录数、时间与并发预算；超限、格式异常、无域名或超时按显式回退策略处理，禁止无限等待。

嗅探只改变本次路由的目标元数据，不修改 TLS 字节，也不自动将原目标 IP 改成嗅探域名的 DNS 结果。是否按域名重新解析并连接必须由明确的出口策略决定，避免把伪造 Host/SNI 当作授权依据、跨越 ACL 或造成 DNS rebinding。Fake-IP 映射和显式代理的域名优先级、SNI/Host 与已知域名冲突时的拒绝或忽略策略须固定；原 IP 与路由决策始终可观察。

## 验收

检查并发同名/不同名分配、游标回绕、池满、不同 view、冲突 CIDR、TTL 和活动连接 pin；模拟重启、磁盘失败、未完成提交、时钟变化及旧地址再次访问。嗅探测试拆包、跨 TLS record、ECH/无 SNI、多个 Host、恶意长度、超时与原数据重放；验证 fake 与普通 IP 在 direct/代理/阻断出口上的行为以及 DNS 防环回。
