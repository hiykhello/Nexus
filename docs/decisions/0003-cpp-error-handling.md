# 0003：尽量无异常，优先使用 expected 与 optional

日期：2026-10-27。状态：方向已确定。来源：用户追加的 C++ 规范要求。

## 决策

- Nexus 自有 C++ 代码尽量不使用异常表达预期失败。
- 优先使用 `std::expected<T, Error>` 表达成功或失败，无成功返回值时使用 `std::expected<void, Error>`。
- 优先使用 `std::optional<T>` 表达正常的可缺失值，不以空值掩盖错误。
- 组件、协程与第三方适配边界保持明确的错误语义。

## 影响与待验证事项

直接使用标准库 `std::expected` 要求至少 C++23；具体工具链、标准库和 Modules 支持需实测。错误类型、协程结果类型、第三方异常转换和内存耗尽策略尚未冻结。

本决策不直接要求全局禁用异常，也不意味着每个函数都应标记 `noexcept`。是否对特定 target 关闭异常，须先验证其完整调用链和依赖兼容性。

详细约定见[C++ 编码规范](../development/cpp-guidelines.md)。
