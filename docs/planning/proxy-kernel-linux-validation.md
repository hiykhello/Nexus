# Linux 代理内核第 68–70、87–90 批验收

范围为 Linux x86-64、GCC 16.2.1。第 68–70 批与第 87–90 批的原始证据分别保存在 `target/proxy-kernel-parity-2026-11-19/` 与 `target/batch87/`–`target/batch90/`，第 91–110 批最新验收见 [项目进度](../progress.md)。

## 第 68 批 · 容量和受限资源

使用 `68-release-{epoll,uring}-cli` 的离线锁定优化构建。代理绑 CPU 12–13，夹具绑 CPU 14–17。每档先经 SOCKS CONNECT 建立并验证回声，再让所有连接保持活动，记录代理进程的 FD、RSS 和客户端接入延迟。用 `tests/proxy_capacity_network.py` 重跑，档位为 64、256、512、1024 和 2048。

| 后端 | splice 管道上限 | 2048 活跃 FD | 2048 活跃 RSS KiB | 接入 P99 ms | 排空后 FD |
| --- | ---: | ---: | ---: | ---: | ---: |
| epoll | 0 | 4114 | 100220 | 73.124 | 18 |
| epoll | 16 | 4146 | 99600 | 67.212 | 18 |
| io_uring | 0 | 4112 | 99280 | 95.897 | 16 |
| io_uring | 16 | 4144 | 98676 | 68.221 | 16 |

两后端在每档都验证连接 FD 和 splice 管道回收。epoll 会按需保留最多两个与普通监听执行器相关的 timerfd，夹具记下其实际类型和数量。读数为该次本机运行，2048 是已测档位。证据为 `68-*-capacity-pipes*.jsonl`。

每次混合运行在同一进程执行三轮，总计 2400 条短 TCP、36 条 16 MiB 回声长流和 12000 条 DNS 查询。每行来自约一分钟的单次运行。吞吐以全部循环墙钟时间及双向转交字节计算，DNS 流量计入 CPU 时间。FD、DNS 上游次数及释放时的 RSS 均保存在原始记录。

| 后端 | splice 管道上限 | 混合 MiB/s | 短流 P99 ms | DNS P99 ms | 代理 CPU ns/转交字节 |
| --- | ---: | ---: | ---: | ---: | ---: |
| epoll | 0 | 18.943 | 17.402 | 21.349 | 1.5646 |
| epoll | 16 | 18.957 | 18.535 | 21.182 | 1.4570 |
| io_uring | 0 | 18.893 | 21.099 | 21.579 | 1.9288 |
| io_uring | 16 | 19.006 | 13.849 | 20.806 | 1.1093 |

每次混合运行只向上游发送 5 次 DNS 查询，其中一次是预热，四次是在约 60 秒 TTL 到期后并发刷新。证据为 `68-*-mixed-pipes*-final.jsonl`。

- 限制 `RLIMIT_NOFILE=192` 时让已建立的 24 条回声流继续传输，再用空闲连接填满描述符。原版 io_uring 因 `EMFILE` 关闭监听。修订后两后端使用既有 10 ms 退避，旧流可继续，释放后各重开 24 条业务流。证据为 `68-*-fd.log` 和首轮 `68-uring-fd-first.log`。
- 在 `RLIMIT_AS=160 MiB`、限制 malloc arena 的条件下验证 256 条活动流、会话配额拒绝和重新接入。这里测的是有限地址空间下的实际运行和配额恢复。证据为 `68-*-memory.log`。
- 经真实本机控制命令换代两次，验证同时活跃的三代各 64 条业务连接。活跃峰值 435/427 FD，新代保有两个监听器，旧代回收后为 28/25 FD，并可重新接入。证据为 `68-*-generations.log`。
- SOCKS UDP 发送至 65 个目标并验证最早的目标被逐出回复授权表。SS-2022 的 16 个同密钥入站通过共享重放与回复路由验证，第 17 个入站在接入前拒绝。两后端均通过，证据为 `68-*-udp-capacity.log`。

## 第 69 批 · 边界和兼容

`tests/proxy_kernel_regression.py` 保存每例命令、产物 SHA-256、退出码与子夹具日志。HTTPUpgrade/XUDP 矩阵在每个后端跑 44 例，覆盖双族、两种 worker 数、分帧、截断、候选重试及停止。回归另包含旧 KDL 写法、旧控制请求、最近成功流观察、DNS 监听失败回滚、规则和缓存代次、FakeIP 历史区间、手动 selector 状态、QUIC 旧流、新连接及 CONNECT 半关闭。长时间混合样本见第 68 批。

旧夹具的自动端口偶尔无法同时绑定 TCP 和 UDP。公共 DNS 对端和双族回声对端现在成组保留 socket，自动端口冲突时整组重新选端口。第 69 批独立复验通过，第 70 批在最终两图重新运行。证据为 `69-epoll`、`69-epoll-dns-policy-retry.log`、`69-uring` 和 `70-uring-regression-fixture-conflict`。新的普通 DNS 缓存快照也进入最终图验证。

## 第 70 批 · 发布和三方对照

离线锁定图从独立 mcpp home 和 wrapper 构建。隔离目录复用已校验的下载归档、工具链和预装依赖源码，开始时没有目标对象缓存。两套启用图和两套最小关闭图均以 `-O2` 构建。ELF、编译命令和本地图路径共同验证 epoll 与 io_uring 的选择。十项依赖核对固定归档和已安装源码。证据为 `70-{epoll,uring,off-epoll,off-uring}-release.log`、`70-isolated-installed.log`、`70-pins.log`、`70-source-inputs.sha256` 和产物 SHA-256。

系统包经解包核对 Build ID，并用包内启动器通过 CONNECT、HTTP forward 和 SOCKS UDP。打包工具报告运行端需要 glibc ≥ 2.38，并提示未自动发现许可证输入。包内程序已在记录的验收主机运行。

最小关闭图验证普通 SOCKS TCP/UDP 和固定数值上游的 DNS 缓存快照。DoT、FakeIP、Hysteria 2、MASQUE、SRS 和已选 DNS 响应规则在接入前显式拒绝。两个关闭图的 ELF 都未链接 DoH 查询执行器。

最终网络回归覆盖第 69 批脚本、普通 DNS 缓存快照过期和错上游、真实 UID 控制、隔离命名空间的进程归属、DoH/DoQ、Mixed 首包配额及 Hy2、TUIC、SS-2022 的已选字节配额。io_uring 首轮 DoH H2 在完整响应之后出现连接收尾错误，诊断确认其造成了错误的 SERVFAIL。修订后以已验证的 HTTP/2 END_STREAM 结束单次查询，关闭并排空一次性连接。首次日志和二进制保留在 `70-before-h2-fix/`。

### 基线测试口径

在同一主机固定代理 CPU 12–13、对端 CPU 14–15，各跑三轮取中位数。TCP 使用本机 SOCKS、64 条活跃短连接和四条并行长流，每条每次传输 16 MiB 并校验内容，含拨号失败后恢复。UDP 使用同一 SOCKS 关联做 32 次回声。DNS 比较 32 次同名 UDP 查询的真实上游次数，并在有请求挂起时关闭其 TCP 客户端，再从新连接查询。

共同的 TUN 夹具将客户端和原站放在独立网络命名空间，外部 Linux 策略路由把客户端传入流量送进 TUN，验证 MTU 1420 的 IPv4 TCP/UDP 及设备撤回。

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Nexus epoll | 17.02 | 16.99 | 24.88 | 0.14 | 146 | 10.237 | 100.932 | 1 | 300.52 |

此早期样本中定位出长流 CPU、SOCKS UDP 与独立 DNS 轮询延迟三项优化目标，随后在第 88 批（事件驱动唤醒）与第 96 批（TCP/Splice 快路径重构）中全部完成优化。

本轮收敛范围为已有 Linux 能力。原生 SS-2022 UDP 出站、完整 uTLS、生产 QUIC 0-RTT、复杂 DNS 视图的缓存持久化和其他协议组合继续列于[功能完整度清单](feature-completion.md)。源文件行数检查仍报告原有 19 项超限。

## 第 87–90 批 · 集成、性能和发布验收

### 第 87–89 批

- 第 87 批以事件驱动优化后的实际 CLI 完成 epoll、io_uring 各 60/60 项，包括选定的协议互通、故障、关闭和 Linux 宿主生命周期。最终用例清单、CLI SHA-256、通过指纹及重跑日志在 `target/batch88/wakeup/integration/{epoll,uring}/`。两张最小关闭图另有产物哈希及运行证据。
- 第 88 批将 SOCKS UDP 和独立 DNS 的就绪等待接入事件驱动路径。同机空闲首包中位数约 0.054–0.056 ms，独立 DNS UDP/TCP 约 0.078–0.081 ms。首包、单请求、长流及 strace 各自采样。TCP worker 仍有约 20 ms 的有界等待，UDP 背压和隧道重试保留定时器。证据见 `target/batch88/wakeup/` 和 `target/batch88/optimized/summary.md`。
- 第 89 批各 14/14 项。两后端在 splice 管道上限 0 和 16 时均验证 2,048 条并发。192 FD 限制解除后各恢复 24 条流，160 MiB 地址空间中各验证 256 条连接及配额恢复，三代同时持有共 192 条连接。每后端 60 轮混合使用 23,040 条短流、480 条长流及 30,720 条 DNS 查询。epoll/io_uring 的短流 P99 为 7.181/7.279 ms，DNS P99 为 1.511/1.560 ms。用例、资源采样以及 DNS 端口冲突的原始失败和复跑在 `target/batch89/`。

### 第 90 批发布

用 mcpp 2026.11.20.1 从新隔离 home 和空 wrapper 构建。起始只复用已校验的下载归档、固定依赖源码及已装工具链。四张图均以 `-O2` 离线锁定，靠 ELF 和编译记录确认实际后端。最小 epoll 首轮链接成功，但同一构建树的编译数据库包含启用图的历史条目。保留首轮记录后，换空构建树串行复跑两张关闭图，编译审计和运行均通过。隔离源码审计核对十项固定依赖，锁文件中的绝对补丁路径在比对时按仓库根解析。审计覆盖补丁变体的源码树，变体继承的安装元数据由现有审计范围排除。证据在 `target/batch90/` 的四份 release 日志、编译数据库、ELF、锁和 installed-source 日志。

两份系统包解包后的 `bin/nexus` 保持对应 CLI 的 Build ID。包内启动器通过 CONNECT、HTTP 转发、SOCKS UDP，以及 IPv4 UDP 和 IPv6 TCP 上的 NXDNS1 → NXDNS2 迁移。还验证过期、损坏快照、重载和 DNS 多视图隔离。包要求 glibc ≥ 2.38，实际动态依赖见包内 ELF 日志。mcpp 报告未自动发现许可证输入。独立的 `nexus-pinned-source-notices.tar.gz` 以已核验归档生成，包含十个固定依赖的许可证通知和源码 pin 清单。四份 CLI、两份系统包及附包均列在 `target/batch90/SHA256SUMS`。

最小图从编译数据库及运行确认 HTTPS CONNECT 关闭，DNS TLS 与 FakeIP 明确拒绝，仍能执行普通 SOCKS TCP/UDP、认证的双栈代理串联、HTTP 专用监听、预读重放、半关闭和握手限时。构建和包内运行使用隔离发布产物。第 87、89 批的全量集成和压力有各自优化产物的哈希记录。
