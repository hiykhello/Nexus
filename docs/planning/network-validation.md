# 自研网络能力验证路线

状态：验证计划草案；内存设备上的 IPv4 TCP 和 IPv4/IPv6 UDP 已与本机回环出口组合验证，已完成隔离 TUN 上的单流 Linux TCP 基本互操作；组合驱动已在隔离命名空间完成 IPv4 TCP、IPv4/IPv6 UDP 直连往返及设备回收；真实系统接管及生产调度尚未完成。细节和限制见 [TUN 架构](../architecture/tun.md)。方向依据见[决策 0002](../decisions/0002-self-developed-network-stack.md)。

## 前置记录

每轮实验记录 Nexus 提交、工具链、操作系统、对照实现版本、协议与算法范围、配置、输入样本和判定结果。参考实现更新时固定到新提交并记录行为变化。

依赖验证需检查源码与 package recipe、传递依赖、静态和动态链接产物，确认使用指定的 BoringSSL libcrypto 且没有引入第三方 libssl、独立 OpenSSL 或其他 TLS 实现；仅检查动态库列表不足以覆盖静态链接。测试对端与 Nexus 发布依赖分别记录。

## TUN 路线

| 阶段 | 重点 | 判定依据 |
| --- | --- | --- |
| 包与内存设备 | 长度、校验和、所有权、队列满与关闭 | IPv4 TCP/UDP、IPv6 UDP 包和有界内存链路已有测试；隔离 TUN 的 IPv4 TCP 基本读写已验证，其他设备与包层场景仍待验证 |
| 最小传输 | TCP 建连和关闭、UDP 往返、返回路径 | 内存设备经真实回环出口验证 IPv4 TCP 和 IPv4/IPv6 UDP 双向传输；隔离 TUN 上的 Linux TCP 单流握手、双向数据、半关闭、真实回环直连出口以及真实 TUN 的 IPv4 与 IPv6 UDP 往返已验证；更广泛的独立对端场景仍待验证 |
| 协议边界 | 丢包、重复、乱序、重传、窗口、半关闭与复位 | 确定性事件和虚拟时钟下状态符合预期；隔离双栈 TUN 上首个 SYN-ACK、双向数据段及两端首个 FIN 丢失后的重传已与 Linux TCP 验证；完整直连组合也验证两族两方向首个 FIN 丢失后完成半关闭，其他交错仍待验证 |
| IP 与 MTU | 声明支持的 IPv4/IPv6、分片、ICMP、PMTU | 限制和失败行为与能力清单一致 |
| 路由与 NAT | 预判延迟决定、L3/L4 分派、映射与过滤组合 | 九种映射/过滤组合、IP 规则阻断及真实 UDP 回环出口已测试；完整多出口路由和系统 NAT 仍待验证 |
| 系统接入 | TUN、路由、DNS、出口绕行、失败回滚 | 隔离环境中无递归代理，停止后回收本实例修改 |
| 压力与扩展 | 多流、内存上限、多队列、网络切换 | 预算和队列溢出策略有效，没有跨队列状态错误 |

优先建立可注入丢包、延迟、乱序和时钟事件的内存测试环境。真实 TUN 实验在隔离网络环境中进行，系统配置变更作为测试夹具的一部分管理。

当前测试夹具 `tests/tun/scheduled_link.cppm` 可按虚拟时间调度有界的拥有报文，显式丢弃或重复安排报文；相同期限按插入顺序交付，目标队列满时保留最早事件。UDP 桥接测试已覆盖乱序、丢弃、重复、背压恢复与时间倒退。双栈 TCP 内存引擎测试通过此夹具丢弃首个数据段，先投递并重复携带 FIN 的后续段，再投递缺失段；验证序号回绕、累计 ACK、ACK 输出背压恢复、数据去重和排空后的 EOF。它是单 owner 的确定性夹具，不模拟带宽、随机丢包或内核，目标队列满会阻塞后续事件；该 TCP 场景由夹具模拟补发，并非独立对端的重传测试。

## TLS 与 profile 路线

| 阶段 | 重点 | 判定依据 |
| --- | --- | --- |
| 基础组件 | 密码原语已知答案、ASN.1 与消息边界 | 固定向量和异常输入得到预期结果 |
| 核心状态机 | client/server、transcript、密钥调度、告警 | 本实现两端及独立实现对端的握手和数据传输通过 |
| 身份验证 | 正确身份、错误名称、过期、不可信链及声明支持的约束 | 成功与失败都符合明确的信任策略 |
| 连接行为 | 部分读写、超时、取消、关闭、KeyUpdate | 不丢失在途数据，不使用已释放对象 |
| profile | 扩展顺序、GREASE、ALPN、key share、padding 与 HRR | 抓取字节符合 profile，协商后可正确完成握手 |
| 扩展能力 | 恢复、ticket、PSK 等逐项能力 | 每一项有互操作结果，未实现项可明确拒绝 |

互操作对端应包含标准 TLS 服务端、现代浏览器指纹校验对端与多协议独立实现，分别记录启用选项。自实现两端相通不能单独证明协议正确。解析器和状态机应接受模糊输入与截断输入验证。

## HTTP 与 HTTPS 路线

HTTP/1.1 自研与后续可选 HTTP/2 的分层见[HTTP 设计](../architecture/http.md)，已执行有限的代理测试；完整阶段仍待验证。

| 阶段 | 重点 | 判定依据 |
| --- | --- | --- |
| 增量 HTTP/1.1 | 所有字节切分、预读、body/chunk/trailer、EOF | 消费长度、事件与输出正确，消息间无丢失和错位 |
| framing 与代理边界 | TE/CL、重复字段、非法长度、Host/authority、逐跳字段 | 严格拒绝有歧义消息，不形成跨对端的解析差异 |
| 连接状态 | HEAD、1xx/204/304、Expect、关闭定界、CONNECT/Upgrade | 按已声明能力处理，切换后首字节保留，池不会复用脏连接 |
| 异步与资源 | 部分写、body 背压、取消、滴流、限额及停止 | 无无界缓冲、悬挂引用、无限占用或关闭后访问 |
| HTTPS | 自研 TLS、证书、SNI/authority、ALPN 与池身份 | 与独立对端互操作；未支持 h2 不通告 h2；CONNECT 不自动解密内层 TLS |
| 后续 HTTP/2 | mem API buffer 寿命、回调重入、HPACK、双级流控、RESET/GOAWAY | 不引入额外网络/TLS 栈，单流失败不误伤其他流，重试不重复非可重放请求 |

先验证协议核心，再接入 HTTP 代理、远程规则获取等具体用途；这些用途各自定义请求与重定向/认证政策。固定对端版本及报文集，通过自实现两端之外的互操作和畸形输入对照，记录任何未支持特性。
