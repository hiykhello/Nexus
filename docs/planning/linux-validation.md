# Linux 集成验证计划

状态：计划草案，未执行。参考[Linux 网络设计](../platform/linux/networking.md)和[服务体验](../operations/linux-service.md)。

## 环境与证据

网络变更实验在独立 namespace 或专用 VM/测试机进行，记录内核配置/模块、systemd/nftables 版本、防火墙管理器、容器后端、权限与网络拓扑。namespace 测试不能替代宿主 systemd/resolved 和真实路由器测试。

保留操作前后属于测试实例的 Netlink/nft 对象、路由、DNS 状态、服务日志、计数器及包抓取。不要通过清空宿主规则来制造测试前提。

## 验证矩阵

| 范围 | 场景 | 完成依据 |
| --- | --- | --- |
| 普通代理 | 无 TUN/nft 权限运行，不使用自动接管 | 无不必要系统权限依赖，监听与流量正确 |
| systemd 启停 | 配置错误、绑定失败、依赖暂不可用、正常启动与 SIGTERM | 退出码与状态准确、停止完成且资源回收 |
| 就绪协议 | 如实现 notify：启动中、就绪、失败与超时 | 网络资源与监听可用前不提前 READY，失败可被观察 |
| 多实例 | 接口、表、mark、路由 priority、队列和端口相同/不同 | 冲突可诊断，不改写活跃实例资源 |
| 本机与网关 | output/prerouting、IPv4/IPv6、TCP/UDP/ICMP | 原始目标、返回路径与策略语义正确 |
| 出口绕行 | 上游服务器、引导 DNS、本地地址、TUN 返回 | 不递归接管、不重复判定，计数对应实际路径 |
| NFQUEUE | 消费者未就绪、队列满、崩溃、超时和不支持模块 | 按已定义策略处理，失败原因和丢包计数明确 |
| conntrack/mark | 已有标记、回复方向、规则更新与连接状态 | 保留外部 mark 语义，按声明策略复用或重判 |
| 集合更新 | 地址/默认路由变化、规则源更新、事务拒绝 | 更新范围正确，失败不留下不可解释的半配置 |
| 防火墙共存 | 选定 Docker 后端、fw4，其他管理器分别测试 | 首次启动、外部重建和清理后均满足已声明兼容范围 |
| DNS | resolved 存在/不存在、D-Bus 拒绝、分流域、其他 VPN | 不抢占其他所有者配置，系统解析与绕行符合声明 |
| 异常恢复 | SIGKILL、部分初始化失败、再次启动 | 识别本实例遗留对象，避免误删他人资源与重复规则 |
| 权限与 namespace | 各部署权限集合、容器及命名空间 | 不支持环境清楚报错，无错误的“rootless 接管宿主”承诺 |
| 包安装 | unit 路径、状态目录、补全、升级与卸载 | 不覆盖用户配置、不遗留无主接管规则 |

若未来启用重载，另测同步结果、候选失败、存量连接与新连接，以及不支持热变更时的明确拒绝。watchdog/socket activation 仅在决定实现后加入专项验证。

## Linux 优化专项

按[通用性能计划](performance-validation.md)固定对照，额外测量普通 TUN、nftables 自动分流、内核 bypass 和支持的 L3 路径，记录进入 NFQUEUE 的包/流比例、系统调用、CPU、吞吐、延迟及丢弃。

多队列和 offload 分别开启/关闭，覆盖不同 MTU、包长、并发、转发与本机流量；区分用户态拷贝减少、系统调用减少和实际零拷贝。防火墙规则数、集合规模、conntrack 状态及规则更新期间的延迟也需记录。

优先建立“可正确接管、可诊断、可回收”的基线，再设性能目标。当前不指定内核/systemd 最低版本，也没有已测收益。
