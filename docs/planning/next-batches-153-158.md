## 编译期策略：方案 A（全端统一 Clang `llvm@23.1.3` + C++26，移除 `-freflection` / `<meta>`）

1. **全端统一采用 Clang (`llvm@23.1.3`) + `-std=c++26`（零 `-freflection` 依赖）**：Linux（`x86_64` / `aarch64`）、Android 免 Root sidecar（`aarch64-linux-musl`）、OpenWrt（`*-linux-musl`）、Windows 与后续 Apple 端统一收敛至受管 **Clang + C++26**（随附完整 `libc++`、`std.cppm` 与静态 runtime），移除 `dialect_cxxflags = ["-freflection"]`，跨平台标准库差异通过静态链接与轻量兼容性包装解决。
2. **仅移除 `<meta>` 反射，零开销兼容层补齐 LLVM 23 `libc++` 缺口**：
   - **CLI（[src/tools/main.cpp](../../src/tools/main.cpp)）**：移除仅此 1 处的 `#include <meta>` / `std::meta::*`，改为等价的零开销 `constexpr CommandTable` 静态命令分发表；
   - **`glaze-kdl` 序列化**：直接运行于标准反射路径（`GLZ_REFLECTION26 = 0`），完全满足当前及后续结构体规模；
   - **零开销标准库兼容性包装（[src/platform/compat.cppm](../../src/platform/compat.cppm) `nexus.compat`）**：由于 LLVM 23 `libc++` 尚未实装 `std::inplace_vector` 与 `std::function_ref`，通过 `nexus::inplace_vector` / `nexus::function_ref` 在标准库提供 `__cpp_lib_inplace_vector` / `__cpp_lib_function_ref` 时零成本别名转发，否则提供等价零堆分配 + Glaze `try_emplace_back` 兼容实现；`std::copyable_function` 与 `#embed` 直接由 LLVM 23 `libc++` 与 Clang 23 原生提供。
3. **新版 CI 多平台原生矩阵构建**：依托 `.github/workflows/ci-cross-platform.yml`（`ubuntu-latest` / `windows-latest` / `macos-latest` 与最新版 Actions `checkout@v7` / `setup-java@v6` / `upload-artifact@v7` / `setup-node@v7` / `pnpm/action-setup@v6` / `cache@v6`），不强制依赖 `mcpp` 托管交叉工具包。
