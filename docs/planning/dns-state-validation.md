# DNS 与持久状态验证

状态：验证方案，对应 [DNS 设计](../architecture/dns.md)、[缓存与持久状态](../architecture/state-and-cache.md) 及 [路由、DNS 与状态原则](../design-principles/routing-dns-and-state.md)。

## 可控实验环境

先使用可编程假上游、虚拟单调/墙上时钟、可注入错误的存储适配器与内存网络；避免依靠公网 DNS 或真实睡眠来判断 TTL。记录配置、工具链、提交、请求集、随机种子、预算、存储同步策略及采样方式，再在隔离 namespace/临时目录验证真实系统路径。

下表是验收要求，不表示已经有测试程序。不得用参考仓库中的测试函数存在代替 Nexus 验证。

## DNS 正确性与并发

| 场景 | 需要证明的行为 |
| --- | --- |
| 大小写、根标签、不同 QTYPE/QCLASS | 仅在规范化语义等价时共享，任意 wire label 不被错误改写 |
| 上游、出口、规则、ECS、DO/CD 与环境变化 | 不跨视图误命中；无法支持的请求明确绕过 |
| 不同 TTL、CNAME、TTL 零与时间边界 | 返回 TTL 递减，不延长记录；零 TTL 不变成乐观旧值 |
| NXDOMAIN、NODATA、缺 SOA、SERVFAIL、REFUSED | 正确分类与期限；错误不被伪造成名字不存在 |
| 消息解析、压缩指针、伪响应、TC、EDNS | 有长度/工作量限制，校验响应身份；截断不作为完整答案入库 |
| 同键并发、不同等待期限、首请求取消 | 在语义允许时合并；每个等待者独立结束，无引用悬挂和任务泄漏 |
| bootstrap、代理节点解析与 DNS 回环 | 显式环可诊断，动态循环有深度/时间限额；不悄悄向其他信任域泄露查询 |
| fallback 与重试 | 总 deadline 不因重试延长；有效负应答不因 IP 列表为空被当作网络错误 |
| A/AAAA 及系统 split DNS | 查询策略、地址排序与连接竞速分别验证；网络切换隔离旧结果 |

## 乐观缓存矩阵

用假时钟验证 `fresh_until`、`stale_until` 的前后及恰好边界。每次命中检查对外 TTL、内部 stale 标志与原始到期时间，重复命中和失败不能续期。

- 一个热点键大量过期命中时只保留允许数量的刷新；大量不同键不能突破全局/每上游任务和字节预算。
- 持续失败时退避、抖动和截止均生效；上游恢复后可刷新，成功负应答按政策替换旧正值。
- 丢包、超时、拒绝与验证失败不覆盖仍可用旧值；超过窗口时明确失败/重新查询，不无限供给旧值。
- 清空、配置发布、网络切换、关闭与刷新完成同时发生时，旧任务不能复活记录或覆盖较新 revision。
- 前台查询与后台刷新竞争时，取消、配额和优先级明确；调用者超时后残留工作仍计入预算并可回收。
- 乐观关闭、零窗口、负缓存、TTL 零、FakeIP 和不允许 stale 的视图不进入乐观路径。
- 若未来支持 DNSSEC，单独检查签名有效期、验证状态和 AD 位；未验证前不得声明 DNSSEC serve-stale 能力。

## 持久化与崩溃

| 故障/变化 | 验收依据 |
| --- | --- |
| 接受、读取可见、提交、同步 | 接口及状态准确区分，异步接受不报为持久成功 |
| 写入/文件同步/rename/目录同步逐阶段失败 | 保留可恢复版本；报告替换与持久性不确定，不假定错误即磁盘未变 |
| ENOSPC、只读、权限、锁竞争、慢盘 | 按状态类别背压/降级/失败，热路径和队列保持有界 |
| pending 与 writing 重叠、同键覆盖、清空及重试 | 新 revision 不被旧批覆盖，删除不会被重试复活 |
| 未知版本、截断、随机损坏、超长输入 | 可重建缓存隔离冷启动；用户状态及 FakeIP 不静默清除，解码资源有界 |
| 进程强杀与重启 | 只依赖已承诺的持久边界；不以正常退出测试替代崩溃测试 |
| 墙上时钟回拨/前跳、长时间离线 | 恢复 TTL 不重置，不跨原 stale 截止；不可信时钟按政策冷启动 |
| 同实例双启动、不同实例、快照替换 | 所有权隔离和稳定锁有效，路径/符号链接/权限处理可解释 |
| 迁移、版本降级、缓存清理 | 不破坏旧状态证据，不越过类别清理选择/FakeIP/网络恢复清单 |

断电持久性需与文件系统、挂载和设备条件一起验证，进程强杀本身不能证明断电后的结果。数据库损坏恢复、GC 与压缩分别检查，不能把删除条目当作立即归还全部磁盘空间。

FakeIP 专项检查双向唯一性、地址族、范围/owner/容量变更、游标回绕、LRU 淘汰、活动连接 pin 和未知池内地址。若采用段预留，在每个提交与分配边界模拟崩溃，验证未 checkpoint 地址不会立即重用，同时如实报告可能丢失反查；若承诺每个已应答映射可恢复，则逐个核查应答前的提交证据。

用户选择检查保存成功后发布、旧成员过滤与失败重试；已 rename 但目录同步失败时，同时检查磁盘、当前内存和重启恢复结果。宿主网络清单另按 [Linux 验证](linux-validation.md)核对真实资源，不能仅检查文件内容。

## 性能与运维证据

对比无缓存、内存缓存、乐观缓存、内存加磁盘四种受支持组合，使用一致请求分布和故障窗口。测量吞吐与 p50/p95/p99、fresh/stale 比例、过期年龄、上游请求数、重复刷新、CPU、实际内存、队列峰值、磁盘写入/同步次数、写放大与启动恢复时间。

分别覆盖热点、长尾随机域名、不同 TTL/记录大小、全冷启动、过期集中、上游持续故障和慢盘；说明 stale 带来的响应延迟改善与旧答案风险。只做吞吐比较会遗漏错误率、后台放大与新鲜度代价。

验收要求预算不超限、停止后无残留任务/锁、故障可定位；数据记录同步策略与丢失窗口。CLI 后续需能区分仅清 DNS、全部可丢弃缓存和显式重置持久状态，具体命令尚未定义。
