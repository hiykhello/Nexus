更新：2026-11-21。承接第 90 批 Linux x86-64 双后端正式发布基线，规划下一阶段 8 个核心批次（91–98，现已全部验收完成），并同步完成**模块名与命名空间移除 `nexus` 前缀**。

## 模块与命名空间去前缀约定

- **所有新增模块与命名空间不再使用 `nexus.` / `nexus::` 前缀**，直接采用领域名（沿用既有 `containers.byte_ring` / `containers.ring_queue` 与 `namespace containers` 风格），例如：
  - 日志系统：`logging.*` 与 `namespace logging`（避开 C `<math.h>` 全局 `::log` 符号）
  - 持久化系统：`state.*` 与 `namespace state`
- **存量模块按“底层叶子 → 协议/传输 → 运行时/工具”分批平滑去前缀**，避免一次性全局改名引入大面积编译回归：
  - **第一批（独立工具/基础设施叶子）**：`encoding.base64_key`（已完成）、`rulefile`（已完成）、`memory.budget`（已完成）、`rules.*`/`dns.policy`（已完成）、`config.*`（已完成）。
  - **第二批（密码与基础协议层）**：`crypto.*`（已完成）、`platform.*`（已完成）、`packet.*`（已完成）、`tls.*`（已完成）、`http.*`（已完成）、`quic.*`（已完成）、`http2.*`（已完成）、`sniff.*`（已完成）、`net.*`（已完成）。
  - **第三批（业务协议家族）**：`reality.*`（已完成）、`hysteria2.*`（已完成）、`socks5.*`（已完成）、`vless.*`（已完成）、`vision.*`（已完成）、`xudp.*`（已完成）、`uot.*`（已完成）、`httpupgrade.*`（已完成）、`websocket.*`（已完成）、`transport.*`（已完成）、`snell.*`（已完成）、`wireguard.*`（已完成）、`tailscale.*`（已完成）、`anytls.*`（已完成）、`grpc.*`（已完成）、`tuic.*`（已完成）、`trojan.*`（已完成）、`shadowtls.*`（已完成）、`shadowsocks.*`（已完成）、`masque.*`（已完成）。
  - **第四批（上层核心与入口）**：`dns.*`（已完成）、`tcp.*`（已完成）、`udp.*`（已完成）、`ss_udp.*`（已完成）、`endpoint.*`（已完成）、`proxy.*`（已完成，与 `proxy.v4` / `pro::` 零冲突）、`cli.*`（已完成）。至此 `src/` 内全部非第三方生产模块 `nexus` 前缀已清零。
- 第三方封装模块（`nexus.thirdparty.*`）留待稳定窗口统一迁为 `thirdparty.*`。`mcpp` 包标识（`namespace = "nexus"`）按包注册表约束独立评估，不强行与 C++ 模块名绑定。

- 遵循开发期“编译与切片定向验证为主、第 98 批统一跑完整发布矩阵”的节奏。
- 每次改动严禁在 `mcpp --strict` 构建期间并发修改工作区源码；保持默认 `mcpp/epoll/mcpp.lock` 恢复，不擅自 `git commit` 或 `git push`。
