# 性能、转发与数据面工程原则

本文汇总 Nexus 在高吞吐转发、加速通道、内存管理、UDP 调度与性能基准方法上的核心工程准则。

## 1. 双向转发公平性与语义完整

- **环形缓冲与先读后写**：转发缓冲支持在剩余空间连续读取，避免每次消费都整块搬移字节；尽量一次读满后再写入，减少按写次数分帧协议的额外封装开销。
- **单轮配额与协作让出**：每次突发搬运设置字节配额，超额后主动向执行器让出调度权，防止持续就绪的大流量长流饿死短流、控制面或定时任务。
- **独立半关闭与限时排空**：收发两方向独立推进 EOF、flush 与半关闭，仅对关闭排空阶段施加有界超时（例如单侧 EOF 后 10–15 秒强收尾），不给活跃读写方向强加固定寿命；交互式 TCP 连接启用 `TCP_NODELAY` 消除 Nagle + Delayed-ACK 抖动，并在 Linux 上配置 `TCP_USER_TIMEOUT` 防止静默失联的死连接挂死十余分钟占满文件描述符。
- **双栈 Happy Eyeballs（RFC 8305）快速回落**：对同时包含 IPv4 与 IPv6 的拨号候选列表在保留 DNS 首选地址族的前提下执行地址族交错，并在非末候选连接上施加 `300ms` 尝试上限，防止 IPv6 路由黑洞拖死双栈建连且不破坏单栈/状态化路由游标语义。
- **错误中断不丢账**：活跃会话与全局统计在读写周期内实时递增并在异常退出路径提交，确保连接被 RST、超时或取消时已传输字节仍准确计账，且不引入跨层锁竞争。

## 2. 可证明条件下的加速切换（`splice` / kTLS）

- **零残留转换屏障**：仅当底层确为裸 TCP 套接字且两端缓冲、待 flush 数据、协议 framing 与状态机均已清空后，才允许切换至 `splice(2)` 或 kTLS 快速通道；绝不绕过 TLS、限速、统计或未发完缓冲。
- **内核能力矩阵前置预检**：Linux kTLS 卸载前先基于缓存的内核版本矩阵校验支持边界（`>= 5.1` TLS 1.3 AES-GCM/RX、`>= 5.11` ChaCha20-Poly1305、`>= 5.19` `TLS_TX_ZEROCOPY_RO`、`>= 6.0` `TLS_RX_EXPECT_NO_PAD`、`>= 6.14` 内核 KeyUpdate）；若运行内核不支持协商套件，必须在提取用户态密钥之前返回 `unavailable` 保持用户态 TLS 零损伤回退。
- **统计与取消不丢失**：加速路径必须保持读写字节计数、协作让出、取消信号与半关闭状态机语义一致；事件 token 携带代次信息以过滤陈旧回调。
- **配额受限与无损降级**：管道等加速资源通过有界池与许可控制，遇到资源紧张或内核不支持错误时平滑回退到常规缓冲转发，完整处理管道内残留字节，绝不因优化资源耗尽导致连接失败。
- **实测驱动启用**：kTLS 等内核卸载在部分场景下收益取决于记录大小与密码套件，保持可裁剪特性边界，以真实负载实测为准。

## 3. 内存复用、驻留控制与空闲回收

- **前置 Headroom 预留**：在 TUN / 隧道包存储头部预留封装空间，使内层 IP 包可直接原位写入协议头或 Capsule 头，减少二次拼接拷贝。
- **避免小载荷钉死大缓冲**：存储所有权与可见区间分离；当极小载荷可能长期排队并钉住大块缓冲时，主动紧凑复制并归还大槽位——零拷贝并非在所有长度与驻留时间下都最优。
- **高负载复用与空闲回收并重**：per-worker 缓冲池与管道池同时约束对象数量、字节容量与空闲 TTL；空闲或承压时主动释放缓存，不让历史峰值永久决定进程 RSS；仍被异步内核操作引用的存储绝不提前归还。
- **HTTP/2 / XHTTP 帧长与每流内存硬预算**：显式钳制 `SETTINGS_MAX_FRAME_SIZE`（默认 16 KiB）与每流发送/接收窗口上限，避免大默认帧长导致并发流内存线性膨胀，确保在 50 MiB（移动网络扩展）与 128 MiB（嵌入式路由器）设备上长期零 OOM 运行。
- **限频丢弃日志**：拥塞或背压丢包采用逐事件原子计数 + 周期汇总日志，防止逐包打日志放大过载。

## 4. UDP 批处理、NAT 与无锁并发边界

- **就绪即批、绝不空等**：UDP 批处理基于 `recvmmsg` / `sendmmsg` 仅在首包到达后收集队列中已就绪的数据报（受最大批大小约束），不为凑满批次引入额外等待而拉高尾延迟。
- **GSO 合并与无损回退**：仅对目标地址、端口、分片长度等完全兼容的帧执行 UDP GSO（`UDP_SEGMENT`）合并，且 Linux TUN GSO 仅在 `MTU < 49152` 时启用；遇到 `EIO`/`EINVAL` 等不支持错误时自动关闭该优化并逐包无损重试，不丢包、不重复发包。
- **底层 QUIC 断链级联清理**：QUIC 传输连接断开或切网迁移时，必须立即级联注销并唤醒所有绑定该连接的关联 UDP NAT 会话，杜绝孤儿 UDP 条目永久滞留。
- **TUN 回写环回熔断**：对 TUN 直连 UDP 回写路径实施源/目地址与端口自环回检测及有界 NAT LRU，防止异常路由触发 CPU 100% 环回风暴。
- **昂贵建连不占会话表锁**：查询会话表命中直接返回；未命中时释放表锁再执行拨号或建连，完成后二次检查插入。
- **防并发建连与过期删除竞态**：会话映射绑定唯一代次/身份标识，任务退出清理时只删除匹配自身代次的条目，杜绝后退出的旧任务误删同键新建会话。
- **准入前硬配额**：容量上限在创建任务前强制校验，且关闭/排空中的会话继续计入配额，杜绝并发突发击穿上限。
- **统一事件循环与合并唤醒**：定时器采用集中时间轮与按需 `park`，避免每流固定频率轮询；合并唤醒通知通过确定性竞争测试验证无丢失唤醒。

## 5. 性能基准与证据纪律

- **固定输入与产物指纹**：所有基准固定测试输入、源码状态、二进制 SHA-256 与工具版本并保存原始 JSONL 样本。
- **计时前确定性预检**：先验证功能正确性与流量完整交付，再开始采样计时；明确区分有效、不可比与缺失数据。
- **避免常见指标误读**：批次均值的 P95 不等于单请求 P95；大规则集索引收益不能推导小规则集无回退；进程 RSS 不等于实时活跃堆。
