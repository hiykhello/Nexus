# 路由引擎、DNS 与持久化设计原则

本文沉淀 Nexus 在路由匹配、DNS 解析缓存、FakeIP 与崩溃安全状态存储方面的核心设计原则与不变量。

## 1. 路由匹配与规则索引

- **严格首命中顺序**：索引结构仅用于缩小候选集合，绝不改变跨规则的首个命中语义；连续同动作规则只有在动作、所有选项、错误行为与诊断身份均严格等价时才可合并。
- **零隐式 DNS 解析（Explicit Resolve Only）**：匹配流量路由规则（含 `ip_cidr`、`ip_is_private`、`ip_version` 及含 IP 条件的规则集）时，除非前序规则显式执行了 `action = "resolve"`，否则绝不隐式触发任何 DNS 查询或网络活动；目标为域名且尚无已知 IP 时按三态逻辑直接返回 `unknown` 并跳过，由后续域名规则或出口自行处理。`dns.reverse-mapping` 同样保持 100% 纯内存零 I/O 被动查表（仅消费既有 DNS 应答缓存，不主动发查）；DNS 规则除显式声明 `match-response` / `action = "evaluate"` 外，亦不隐式拉起上游探测。
- **三态逻辑（Match / Miss / Unknown）**：缺失元数据（如无域名、无认证用户、未获取进程信息）一律判定为 `unknown`，组合运算与取反严格保留三态，不将缺失值静默当作 `false`。
- **零分配规范化与结构特化**：
  - 域名匹配先扫描是否含 ASCII 大写，全小写输入直接借用原始 `std::string_view`，仅含大写时才在栈上局部转换；
  - 域名后缀按完整标签边界逐级匹配，防止子串误命中；
  - 小集合（如 ≤ 16 项）优先紧凑线性数组，大集合转用排序/哈希索引；IP CIDR 与端口范围在编译期排序并合并重叠区间，明确 IPv4-mapped IPv6 语义；包含大量纯 CIDR 或纯域名的复合 `rule-set` 节点须在内部构建有序区间二分/后缀索引，将万级规则集评估控制在 $O(\log N)$。
- **单请求匹配缓存与有序失效**：昂贵查询（如地理/进程/反查）可在单次请求上下文内缓存，但一旦有序动作（`sniff`、`resolve`）改变了流量元数据，必须按上下文代次失效重算。
- **严格的路由缓存边界**：路由缓存必须显式受规则依赖约束——凡涉及 DNS 解析、嗅探、来源地址、入口、认证用户、进程或配置代次的决策，绝不能复用仅以目标地址为键的缓存。
- **有界规则集加载**：规则集解析、解压（防 zip-bomb）、正则编译与节点数均施加严格预算，原子发布新代次；遇到未知或循环引用时保留旧代次运行。

## 2. DNS 解析、视图隔离与乐观缓存

- **多维精确缓存键**：缓存与在途合并键必须完整区分问题名、查询类型（`qtype`）、类（`qclass`）、解析视图/上游传输、有效 ECS、EDNS 标志（`CD`/`DO`）与配置代次，绝不仅按域名共享。
- **在途合并与独立取消**：对可缓存的简单查询合并在途请求，每个等待者保留各自超时与取消能力，返回副本恢复各自事务 ID 与剩余 TTL；最后一位等待者离开后取消上游并等待网络排空，刷新任务计入统一并发预算而非无界 `detached` 任务。
- **尊重权威 TTL 与负缓存**：严格保留原始零 TTL（仅交付当次等待者、不持久化）与 SOA MINIMUM 负缓存时长，绝不人为拉长最小 TTL 掩盖动态记录变更。
- **乐观缓存与防陈旧写回**：过期但仍在乐观窗口内的条目可按短 TTL（如 1 秒）先返回，同时按键去重触发后台刷新；后台刷新必须绑定同一解析视图并遵循原路由规则，发布写回前核验配置/flush 代次，避免清空缓存或切换网络后的旧结果回灌。
- **能力分层与故障隔离**：区分“原始 DNS 报文交换”与“地址列表解析”，区分空答案、NXDOMAIN、TC 截断与传输错误；贯穿单次绝对期限（覆盖 bootstrap、重试与 TCP 回退）；多上游并行或回退查询采用有界竞速，率先拿到有效答复后立即取消慢上游，避免单个挂死的加密上游拖慢整体解析。
- **连接池与反查边界**：DoT/DoH/DoH3 连接池按端点、TLS profile、出口绑定、DNS 视图与配置代次隔离并限制每端点连接数；DNS 反查归属原始 question、按视图隔离、保留更长同名映射、拒绝零 TTL 登记并识别多域名歧义。
- **QUIC ECH 失败关闭（Fail-Closed）**：启用 ECH 的 QUIC/HTTP3 出站在握手前统一通过 HTTPS/SVCB 记录获取 ECH 配置；获取失败直接中止连接，绝不静默降级为明文 SNI。

## 3. 崩溃安全状态存储与 FakeIP 持久化

- **按状态价值分级**：用户显式配置（selector 选择）、半持久映射（FakeIP）与可重建缓存（DNS、远程规则集）的丢失代价不同，按层级分别管理持久化与损坏恢复策略，不对所有状态统一“删库重建”。
- **原子落盘与不确定性显式汇报**：
  - 采用独立锁文件 + `0700`/`0600` 私有权限校验（拒绝符号链接与非本用户文件）+ 同目录临时文件 → `fsync`（macOS 支持 `F_FULLFSYNC`）→ `rename` → 目录 `fsync`；
  - 区分「替换前失败」与「已替换但目录同步失败（持久性不确定）」，让上层明确感知磁盘状态。
- **显式选择与自动健康分离**：持久化仅记录用户显式选择，健康探测与临时覆盖状态独立驻留内存；重启恢复时校验成员是否仍在当前配置中，失效成员不强行激活。
- **FakeIP 地址段预留**：分配前批量同步预留地址段（如最多 256 个且不超过池容量一半）并前移游标、清理该段旧归属，运行期再消费预留段。此举显著减少每次分配的同步写盘，并保证崩溃重启后跳过未 checkpoint 的段，大幅降低旧客户端复用地址误指向新域名的风险。
- **版本与修订保护**：所有持久化格式携带魔数、版本、完整性校验与容量上限；checkpoint 凭 `revision` 避免无变更重写，释放状态锁后再写盘且防止并发 LRU 更新把新 revision 误标为已落盘；遇到不兼容版本显式要求迁移或重置，不静默覆盖。
