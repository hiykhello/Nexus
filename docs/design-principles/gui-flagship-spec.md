# GUI 旗舰设计与逐界面规范

本文承接[GUI 设计系统与交互工程原则](gui-design-system.md)（哑光扁平视觉、GPU/内存红线、按频次动态克制与产品边界），定义 Nexus 四端图形客户端（Desktop Slint、Android Compose、Apple SwiftUI 与 Web 控制台）的旗舰级交互体系、统一仪器视觉语言、三项核心招牌能力及逐界面对齐规范。

> **核心设计命题（Instrument Thesis）**：让每一次数据包的流经路径与每一次路由决策都在 1 秒内一目了然——将四端统一打造成克制、零噪音、高精度的台式/掌上网络仪表工作台，而非松散的表单控制面板。

## 1. 仪器级视觉世界与四档主题体系

在既有哑光扁平基线上，四端统一提供 **4 档用户可选外观预设**，作为客户端本地宿主偏好持久化（旧版 `dark` / `light` 无损迁移至 `obsidian` / `paper|daylight`，严禁写入跨端共享工作区配置）：

1. **跟随系统（`system`，默认）**：系统浅色映射「暖纸日光」，系统深色映射「曜石仪表」。
2. **曜石仪表（`obsidian`，默认深色）**：冷静深炭黑机箱与哑光卡片层级，搭配高辨识度交互靛蓝与活态信号翡翠绿。
3. **暖纸日光（`paper` / `daylight`，暖纸浅色）**：以 `#F6F5F2` 暖纸底板替代刺眼冷白，搭配纯白 `#FFFFFF` 卡片与暖灰细描边。
4. **精密琥珀（`amber` / `studio_amber`，暗调精密仪表）**：暖石墨机箱与校准琥珀色仪表强调，面向长时间低照度运维值守。

### 1.1 双信号色分工原则

四端严格分离**交互强调色**与**活态链路信号色**，杜绝“所有激活态与在线态混用同一色相”导致的视觉疲劳：

- **交互强调色（Interactive Accent）**：`Obsidian` / `Paper` 采用校准钴蓝/靛蓝，`Studio Amber` 采用校准琥珀金；专用于主操作按钮、当前导航激活项、输入焦点环与选中胶囊。
- **活态链路信号色（Signal Emerald）**：全主题统一保留独立的翡翠绿通道（深色 `#34D399` / `#10B981`，浅色 `#047857`）；**专用于已连接隧道状态点、实时链路拓扑仪活态连接箭标、活跃配置主竖轨与直连/健康语义**。

### 1.3 实时主题色卡预览（Swatch Cards）与四端平台融合

- **可视化微型色卡**：四端在外观设置区或侧栏控制区提供 **4 枚纯原生/矢量绘制的微型色卡预览**（展示迷你侧栏 + 画布 + 卡片 + 交互强调与 Signal Emerald 双点），点击 `0ms` 瞬时生效，严禁引入位图资源或背景渐变；移动端触控热区不小于 `44×44pt` / `48×48dp`，桌面端完整支持键盘聚焦与 `2px` 焦点环。
- **四端系统特性融合纪律**：
  - **Android（Compose M3）**：保留可选 `Material You` 动态取色开关（仅 API 31+ 可用，默认关闭）；开启时按解析后的 `effectiveDark` 派生动态地表，同时保持遥测通道（RX/TX）、Signal Emerald 与五档延迟色严格解耦；`MainActivity` 必须通过 `SideEffect` 按 `effectiveDark` 同步更新 `enableEdgeToEdge` 的 `SystemBarStyle`，确保在深色系统强制切「暖纸日光」（或反之）时状态栏与导航栏图标清晰可读。
  - **Apple（SwiftUI）**：通过兼容 macOS 14 / iOS 17 的 `Sendable` `EnvironmentKey` 注入主题令牌（不依赖新版专属宏），响应 `@Environment(\.colorSchemeContrast)` 在开启增强对比度时自动加厚/提亮边框；偏好落盘私有 `host_kv`，严禁使用 `UserDefaults`。
  - **Web（Lit 3）**：切换主题时将 `documentElement.style.colorScheme` 精确映射为 `'light'`（`daylight`）或 `'dark'`（`obsidian` / `amber`），严禁写入非法枚举值；同步更新 `<meta name="theme-color">`（`#111318` / `#F6F5F2` / `#131210`）并在 `index.html` 预置首帧样式消除刷新白闪。
  - **Desktop（Slint）**：持久化于本地客户端偏好库，主题切换直接重算 `Theme` 全局属性，零重启、零缓存纹理重建。

## 2. 招牌设计一：实时链路拓扑仪（Live Route Transit Strip）

在概览页主状态卡旁/下方引入一枚**单一扁平哑光容器**（容器内部严禁再嵌套带边框子卡片），将代理运行的 4 个关键阶段串联为可点击的活态路径条。

### 2.1 四段交互矩阵与去重边界

| 阶段 | 核心读数（等宽数字防抖） | 状态信号编码 | 点击交互动作 |
| --- | --- | --- | --- |
| **1. 入口（Inbound）** | 活跃入站模式（如 `TUN · :7890`、`VPN · TUN`、`混合代理 :7890` 或监听器数量）与分应用/局域网摘要 | 运行时稳态主墨，停用时次墨 | Desktop/Apple 跳转宿主/设置；Android 跳转分应用；Web 跳转诊断 |
| **2. 路由引擎（Route Engine）** | 本地化出站模式（`规则` / `全局` / `直连`）+ 规则总数 + `FakeIP` 启用微标 | 模式语义着色，零底层格式术语 | 跳转规则与 DNS 诊断（或打开规则诊断弹窗） |
| **3. 当前出口（Active Exit）** | 主策略组名 / 活跃节点名（中间或尾部省略 + 完整 Tooltip）+ 实测延迟 `ms` 徽标 | 在线配 **Signal Emerald** 圆点；离线次墨 | 跳转策略组页，或直开内联快切菜单 / 命令面板切节点 |
| **4. 实时速率（Live Rate）** | 定宽数值槽 `↓` 下载 / `↑` 上传实时速率 + 活跃连接数 | RX/TX 双轨色，高对比等宽数字 | 跳转活动连接页 |

- **静态零空转连线规则**：阶段间使用方向箭标（`›` / `→`）连接，代理在线时呈 Signal Emerald，待机/离线呈静默次级色，**严格 `0ms` 状态切换，禁止任何无限脉冲、流动虚线或呼吸发光**。
- **反冗余原则**：拓扑仪第 3 段接管「当前出口 + 实时延迟」快速展示后，概览主状态卡（Hero）应同步收口重复的延迟/信号行，使 Hero 专注**五态状态机 + 一键启停 + 运行时长**，拓扑仪专注**4 段实时路径**。

### 2.2 四端响应式拓扑与桌面零滚动高度预算

- **Desktop（Slint）`1280×760` 零滚动精确高度预算**：主视口可用内高 `760 - 32(底栏) - 24(主区上下内边距) = 704px`，5 行布局加 `4 × 8px = 32px` 行距精确预算如下：
  - `Row 0` 实时链路拓扑仪：**固定 `44px`**（`vertical-stretch: 0`）；
  - `Row 1` 状态主卡（`2fr`）+ 双轨吞吐波形卡（`2fr`）：**固定 `142px`**（`vertical-stretch: 0`）；
  - `Row 2` 活动连接预览（`2fr`）+ 软件性能（`1fr`）+ 内核性能（`1fr`）：**`min-height: 176px`**（弹性伸展至 `190px`）；
  - `Row 3` 服务连通 + 分流规则 + 出站模式 + 策略组快切（`1fr × 4`）：**`min-height: 174px`**（弹性伸展至 `188px`）；
  - `Row 4` 底排快捷开关条（`1fr × 4`）：**固定 `56px`**（`vertical-stretch: 0`）；
  - **最小总高度 `= 44 + 142 + 176 + 174 + 56 + 32 = 624px`**，在 `1280×760` 保留 `80px` 舒展余量，且在 `680px` 桌面临界窗高仍为 **`0px` 垂直溢出**；缩窄至 `780×560` 紧凑断点时拓扑仪平滑折叠为 `2×2` 网格（`84px`）。
- **Android（Compose）**：Compact 手机（`<600dp`）或 Medium 且字体缩放 `>= 1.5x` 时渲染为 `2×2` 网格（单格 `minHeight >= 54dp`）；`674dp` 折叠屏与 `>= 840dp` 平板以全宽跨列独占整行横向 4 段呈现，严禁挤压进双列半宽槽位。
- **Apple（SwiftUI）**：macOS 与 iPad `.regular` 宽度横向 4 段；iPhone `.compact`（`375pt`）自动折为 `2×2` 网格（单格 `minHeight >= 52pt`）；macOS 菜单栏浮窗（`MenuBarPopover`）顶部同步提供单行压缩版 **`MiniTransitStrip`**（如 `:7890 › 规则 › HK-01 38ms`），实现 2 秒一眼扫读。
- **Web（Lit 3）**：桌面宽度采用 `1fr auto 1fr auto 1fr auto 1fr` 单行横向布局；`<= 860px` 移动端折为 `2×2` 网格（隐藏箭标，单格热区 `>= 44px`）。

## 3. 招牌设计二：全局命令与内联域名诊断面板（Command & Inline Diagnostic Palette）

将跨页检索、快捷控制与域名排障收敛至统一的单输入仪器面板，使高频运维操作无需在多页间往返跳转。

### 3.1 统一触发入口与 0ms 瞬开纪律

| 平台 | 键盘快捷键 | 显性触控 / 指针入口 | 宿主容器 |
| --- | --- | --- | --- |
| **Desktop（Slint）** | `Ctrl+K`（可于快捷键设置中自定义） | 底部状态栏紧凑 `Ctrl+K` 按钮 | 居中模态层（`CommandPaletteState` 全局解耦） |
| **Web（Lit 3）** | `Ctrl+K` / `Cmd+K`（优先于输入目标过滤） | 侧栏顶部 / 移动端顶栏检索按钮 | 根级 ARIA `dialog` + `combobox`/`listbox` |
| **Apple（SwiftUI）** | macOS / iPad `⌘K`（页内检索独立为 `⌘F`） | iOS 顶栏检索按钮；macOS 菜单栏「命令 / ⌘K」 | macOS/iPad 居中 Sheet；iPhone 弹窗 Sheet |
| **Android（Compose）** | 外接键盘 `Ctrl+K` / `Meta+K`（含 Activity 级兜底） | 全页 `TopAppBar` `48×48dp` 检索图标（平板附 `Ctrl+K` 胶囊） | 手机 `ModalBottomSheet`；折叠屏/平板居中 `Dialog` |

- **0ms 零延迟硬约束**：作为日均触发数十至上百次的键盘/快捷工具，面板**打开、关闭、键入筛选与上下切换焦点一律 `0ms` 瞬时响应**，严禁入场缩放动画、列表逐项交错淡入或 `<300ms` 闪现骨架屏；打开当帧自动聚焦输入框。

### 3.2 三类即时交互模式

1. **空输入与 `>` 快捷命令模式**：输入为空时呈现置顶高频动作（切 `规则`/`全局`/`直连`、切换 TUN/系统代理、当前组测速、刷新 FakeIP、清空 DNS 缓存、热重载配置、切换四档主题、页面跳转）与主策略组前若干常用节点；输入 `>` 前缀时纯筛选命令列表。
2. **节点模糊秒切模式（默认输入）**：跨全部缓存策略组即时模糊匹配节点名与组名，列表项展示策略组标签、节点名、当前激活标记与实时延迟徽标；按 `Enter` 或点击即触发乐观切点、向吞吐图写入事件刻度并自动收起面板。
3. **内联域名诊断模式**：当输入内容符合域名或主机形态（含 `.`、无空格、非 `>` 开头）时，经 `180–220ms` 可取消防抖后在面板顶部渲染单行流水线诊断卡：
   - **统一呈现格式**：**`域名` → `[命中规则]` → `实际出口（策略组 · 节点 · 延迟）` → `实时 DNS 解析（RCODE · IP / FakeIP 徽标 · TTL · 耗时 ms）`**。
   - **即时后续动作**：提供一键「基于此域名创建规则」（预填规则弹窗）或命中 FakeIP 时的「刷新 FakeIP」快捷按钮。
   - **各端能力诚实对齐**：Desktop 与 Android 直接调用本地 Core 权威规则解释（内核未启动时仍可执行本地静态规则匹配，并诚实标注「核心未运行 · 仅本地规则匹配」），并行请求运行态实时 DNS 查询；Apple 与 Web 在控制面尚未独立开放规则解释接口前，基于实时拉取的有序规则清单在本地完成规则命中预判（显式标注「规则预估」以区别权威解释，遇不透明规则集诚实提示），并并行调用真实实时 DNS 查询接口，待控制面补齐解释接口后平滑切换且零 404 报错噪音。

### 3.3 防乱序并发与键盘/无障碍协议

- **单调序列号防乱序**：每次异步域名诊断必须绑定单调递增序号或取消令牌（C++ `std::atomic<uint64_t> diag_seq`、Web `AbortController`、Kotlin `LaunchedEffect`、Swift `Task` 取消），过期响应一律丢弃，严禁旧域名的慢回包覆盖新输入结果。
- **完整键盘与无障碍协议**：支持 `↑` / `↓` 环形移动选中项、`Enter` 执行高亮项或主动触发诊断、`Esc` 立即关闭并归还焦点；Web/移动弹出层锁定内部滚动（`overscroll-behavior: contain`），粗指针输入框字号不小于 `16px`。

## 4. 招牌设计三：精密遥测微可视化（Telemetry Micro-Visuals）

用极低像素开销、高信息密度的仪器微图表替代装饰性大图形，所有微可视化严格遵守零模糊阴影、零渐变填充、零空闲重绘原则。

### 4.1 双轨吞吐波形图（Dual-Track Sparkline + Peak Ceiling + Onset Marker）

- **单卡共享纵轴双轨绘制**：将分离的上传/下载窄图统一为共享同一校准 Y 轴的双轨吞吐波形（Desktop 概览 Row 1 合并为 `2fr` 宽幅双轨卡，与 `2fr` 状态主卡平衡布局）：
  - **RX（下载）**：实线主轨迹（`1.75–2.2px`）+ 低透明浅面积填充（`0.12–0.16` 透明度，禁用高饱和渐变与模糊发光描边）；
  - **TX（上传）**：对比色虚线轨迹（与 RX 同轴同尺，搭配图例 `●` 实点与 `--` 虚线标记，无色觉依赖即可区分）；
  - **峰值标尺（Peak Scale Ceiling）**：画布右上角以等宽数字标注当前窗口纵轴上限（如 `峰值 16.0 MB/s`），辅以极淡 `50%` 参考水平线，消除“空看波浪不知量级”的盲区。
- **事件刻度（Onset Marker）**：每当用户执行**切换出口节点、切换出站模式、策略组恢复自动选路或热重载配置**时，状态层在当前采样槽记录一条带紧凑标签的事件标记（如 `HK-01`、`全局`、`重载`），随 1Hz 采样窗向左推进并自然移出；波形图在对应横坐标绘制 `1px` 竖向虚线刻度与顶部防裁剪微标签，直观印证“切换动作后吞吐是否立即改善”。
- **平台实现约束**：
  - **Desktop（Slint 1.19）**：因 Slint `Path` 原生不支持 `stroke-dasharray`，由 C++ 侧 `build_dual_speed_wave_paths` 沿平滑曲线预分段输出真实虚线 SVG 路径；保留原单轨路径函数兼容既有测试。
  - **Android（Compose）**：抽离纯数学与预分配 `WaveScratchBuffers`，绘制循环内使用 `Path.rewind()` 做到 1Hz 零堆分配零 GC，移除旧版模糊外发光描边。
  - **Apple / Web**：分别通过 `Canvas` 与原生 `<svg>` 绘制双轨路径与事件刻度，并将事件刻度摘要同步暴露至无障碍朗读值。

### 4.2 策略组延迟光谱分布条（Latency Spectrum Bar）与相对延迟底纹

- **延迟光谱分布条 + P50 中位数**：
  - 按实测延迟将策略组内节点统计为五档比例（极快 `<80ms` 翡翠绿、良好 `80–179ms` 青绿/蓝、中等 `180–349ms` 琥珀、较慢 `>=350ms` 橙红、超时/不可用 玫瑰红，未探测为静默灰），并在策略组摘要栏与侧栏底部渲染一条 **`3px`（Desktop/Web）/ `3dp`（Android）/ `3pt`（Apple）** 连续圆角光谱条（侧栏迷你条可用 `2pt`），宽度变更 `0ms` 瞬切。
  - 在策略组可用率旁并列展示 **`P50 XX ms`** 等宽中位数延迟（比单点最快值更诚实反映全组健康度）。
- **节点相对延迟极淡底纹**：
  - 对组内健康节点卡片/行，从左侧绘制与 `latency / groupMaxHealthy` 成比例的扁平低透明底纹（深色 `0.06–0.085`、浅色 `0.05–0.06`，纯色无渐变无模糊），Web 端优先使用 `transform: scaleX(...)` 避免触发布局重排；超时与未测节点不铺底纹。
  - 硬性可读性红线：铺设底纹后节点主文本对比度必须维持 **`> 12:1`**，在不增加任何文字或徽标的前提下令快慢梯队一眼可辨。

## 6. 工程红线、预算与验收门禁

所有旗舰特性落地必须同时通过以下不可妥协的工程红线与四端独立验收门禁：

### 6.1 硬性工程红线

- **渲染与动效清零项**：`0` 处 `drop-shadow-blur`、`0` 处卡片/容器装饰性渐变或环境光晕、`0` 处布局属性逐帧动画、`0` 处空闲期常驻无限循环动画（含脉冲/呼吸/流光）、`0` 处 SwiftUI `.compositingGroup()` 滥用与 `UserDefaults` 持久化。
- **产品边界与合规项**：所有面向用户的可见文案、提示与错误反馈中 `0` 底层实现术语、`0` 内部文件路径、`0` 外部竞品名称；Bearer 令牌严禁进入 URL 查询参数、诊断复制文本或日志。
- **依赖与体积预算**：
  - **零新增外部依赖**：Web 零新增 npm 依赖，内置控制台构建产物压缩总大小严格控制在 **`<= 62 KiB gzip`**（相对基线 `54.30 KiB` 增幅 `<= 8 KiB`）。
  - **单文件 `<= 500` 行硬上限**：所有新增与修改源码文件（`.slint` / `.hpp` / `.cpp` / `.kt` / `.swift` / `.ts`）严格不超过 `500` 行；临近上限的既有页面必须提取独立纯 UI 组件与纯逻辑/国际化模块，严禁超限硬塞。
  - **桌面构建与渲染纪律**：Desktop Slint 保持完整 Release 优化（`-O3` / `/O2`）、`COMPILATION_UNITS 16` 与 Skia 硬件加速渲染，严禁以牺牲优化级别或回退软渲染掩盖性能问题。

### 6.2 四端独立验收门禁

每一平台在合并前均须独立通过以下三道门禁（由独立复审方核验，零 P0 / P1 / P2 遗留）：

1. **自动化单测门禁**：覆盖 4 档主题映射与持久化迁移、WCAG AA 对比度/极性映射、策略组 `P50` 与五档光谱统计、双轨波形与事件刻度移位/淘汰、命令面板模糊筛选与域名诊断防乱序解析。
2. **多主题多断点真渲染视觉验收**：
   - **Desktop（Slint）**：硬件渲染实拍覆盖 `1280×760`（零滚动核验）与 `780×560`（紧凑折叠），涵盖「曜石仪表」「暖纸日光」「精密琥珀」三主题与命令面板实景；
   - **Android（Compose）**：Preview/实机渲染覆盖手机竖屏、`674dp` 折叠屏、平板宽屏、`200%` 系统字体缩放与三主题（含系统栏图标极性）；
   - **Apple（SwiftUI）**：macOS 14 主窗与 `MenuBarPopover`、iOS 17 `375pt` 紧凑屏与 iPad 分栏，三主题 + 增强对比度 + 减弱动态效果；
   - **Web（Lit 3）**：桌面宽屏与移动视口（`<= 860px`），三主题 + `prefers-reduced-motion` + `theme-color` / `color-scheme` 核验与内置包体积校验。
3. **跨端红线扫描**：通过源码行数门禁脚本、无障碍聚焦与键盘操作走查、控制面鉴权与脱敏检查。
