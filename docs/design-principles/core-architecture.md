# 核心架构设计原则

本文沉淀 Nexus 在组件组织、生命周期、协议分层与平台抽象方面的核心工程原则，指导模块划分与演进边界。

## 1. 类型注册与构造分离

- **单一类型标识贯通配置与运行**：每个入站、出站、L3 端点、DNS 传输与证书提供者由唯一类型标识关联其配置解码与运行时构造，避免解析清单与运行工厂各自漂移；重复类型注册必须显式报错。
- **角色与流量组件分离**：`client` 与 `server` 共享同一套入站、出站、端点与路由基础设施，部署角色仅约束装配策略。
- **显式依赖图与环检测**：出站链（`detour`）和具名解析器（`domain-resolver`）按有向依赖图拓扑启动，并在校验期诊断缺失依赖与循环引用，启动顺序不取决于配置文件书写顺序。
- **能力组合优于庞大基类**：入站按最小生命周期与能力边界划分，不强求所有入站都监听 TCP；出站按流、数据报、L3 包端口及多路复用能力分别对接路由，不将 L3 流量硬塞进字节流模型。
- **编译期装配与明确诊断**：通过特性开关在完整实现与裁剪桩之间选择，关闭某特性时保留清晰配置拒绝信息；使用显式模块装配，杜绝跨 C++ Modules 的全局静态初始化顺序依赖。

## 2. 分阶段生命周期与作用域回收

- **候选与生效状态隔离**：配置加载与热重载严格区分「解析校验 → 准备候选 → 原子发布/激活 → 失败回滚 → 优雅停机」阶段。候选校验或资源准备失败时，已发布配置与活跃连接不受影响。
- **RAII 与异步取消作用域**：每个子组件绑定明确的所有者与取消作用域；启动中途失败时按逆序回收已创建资源，避免半初始化泄漏。
- **存量连接保活**：发布新代次配置后，新连接使用新路由与凭据快照，存量连接继续持有旧代次不可变视图直至自然结束或达到排空期限。
- **有界资源许可**：连接数、并发流、管道、内存与后台任务配额统一由只移动 RAII 许可管理，成功、取消与错误路径共享释放语义；配额不足通过 `std::expected` 显式上报。

## 3. 协议握手与公共转发解耦

- **职责四分**：接收/建立底层承载、协议握手与认证、路由选择出口、公共数据转发彼此独立；协议层不重复实现整套读写泵与关闭状态机。
- **带标签的握手结果**：协议握手返回结构化结果，明确区分 TCP 双向流、固定目标 UDP、多目标 UDP、按会话 UDP 或长期任务，并显式携带初始远端载荷、回执响应与首次 flush 要求，保持发送顺序严格可证。
- **流量语义保真**：字节流、消息流与数据报在接口层区分目标地址、来源地址与会话身份；UDP 必须保留零长度数据报语义，绝不将其误判为 EOF。
- **统一流量上下文拆分**：以稳定流量标识为核心，将嗅探结果、DNS 解析结果、路由结果与匹配缓存拆分为阶段性结构，明确各阶段读写权限。

## 4. TUN 栈与平台窄边界

- **设备与协议栈解耦**：操作系统 TUN/utun/Wintun 适配与用户态 TCP/IP 状态机通过清晰包接口隔离，内置内存包设备以支持无特权单元测试与压测。
- **L3 与 L4 双路径**：当出站原生支持 L3 包转发且规则条件已完备时，支持直接包路径跳过 L3→L4→L3 重组；信息不足时显式退回完整 L4 判定。
- **窄平台 Facade**：不定义庞杂的“大一统平台接口”，而是按设备打开、出口保护、接口/路由监控、连接归属与系统 DNS 拆分为独立窄边界，逐项标明句柄所有权、所需权限、回调线程与可用状态。
- **TLS 配置与连接状态分离**：TLS 引擎/指纹 profile 不可变共享，每条连接独立持有握手与密钥状态，密码原语统一收口在 BoringSSL `libcrypto`。
