# 协议工程边界与出站策略组设计原则

本文总结 Nexus 在现代代理协议互通细节、HTTP 客户端资源管理以及智能出站选路状态机上的核心工程原则。

## 1. 代理协议线规与互通细节

- **Shadowsocks 2022（SIP022）**：
  - 请求端发送 `1..=900` 字节随机 padding，严格核验请求 salt 回显、±30s 时钟窗与按密钥隔离的抗重放表；
  - 区分定长响应头与首段数据记录，兼容允许空首段载荷的规范对端实现，同时保持重放与时间窗校验不放松。
- **Snell 分步握手防死锁**：
  - 部分服务端会将响应头与 salt 推迟到收到首包并写出回程数据时才发送；出站采用拆分式启动（拨号期仅发请求并返回已加密写器，将响应头解析推迟至首次 `read()`），从根源避免握手表观死锁；
  - 保持单一明确版本与有限重放缓存，不引入弱算法自动降级。
- **Hysteria 2 / QUIC / HTTP/3**：
  - 握手完成后立即主动建立并常驻 HTTP/3 三条关键单向流（control + QPACK encoder/decoder），并持续消费对端单向流与补充流控信用，防止触发 `H3_CLOSED_CRITICAL_STREAM`；
  - 对双侧 QUIC/HTTP3/接收缓冲窗口施加共享内存预算，并在纯 UDP 对端异常消失时保证槽位与 FD 及时回收。
- **AnyTLS 子流与数据报完整性**：
  - 同一 TLS 连接内按子流独立执行有序路由准入，单条子流被拒或重置不影响兄弟 TCP/UoT 子流；
  - 单次 UDP 数据报写入在流写锁内连续完整发出，不跨无关 padding frame 拆分，精简冗余客户端元数据以降低特征暴露。
- **MASQUE `CONNECT-IP`（RFC 9484）虚拟 L3 端点**：
  - 与 TUN/内存链路间预留 Capsule/Context ID 前置 headroom 减少拷贝；
  - `AddressAssign` 动态更新隧道地址集合时，显式失效/中断依赖旧源 IP 的 UDP NAT 映射，防止旧五元组长期静默黑洞；
  - 将 QUIC MTU 与初始包大小按协议开销联动对齐，支持 Datagram 失败回退 Capsule；
  - 在隧道内执行 TTL/HopLimit 递减与受限 ICMPv4/ICMPv6 错误回报，同时对 IPv4 源路由选项、IPv6 危险扩展头坚持 fail-closed 拒绝。
- **物理 UDP 绑定与源地址作用域**：
  - 支持显式 `udp-bind-port` 与源地址绑定，冲突时显式失败而不静默切换临时端口或开启复用；
  - IPv6 link-local 目标的 scope 必须纳入 endpoint 身份、授权与序列化契约；
  - 逻辑域名目标与解析后的实际数值目标分别保留，避免包装层重复解析。
- **直接内联 TLS 入站**：
  - TLS / ShadowTLS / REALITY 握手直接在接收路径内完成，不通过 `127.0.0.1` 回环转发，完整保留真实客户端源地址供规则引擎使用，并避免双倍 socket 与 FD 开销。
- **uTLS 单真源与能力诚实原则**：
  - 浏览器指纹的枚举、版本别名与外部订阅归一化收敛在单一真源（`utility.tls_fingerprint`），线特征完全由声明式规格表（`tls.browser_profiles`）驱动；
  - ClientHello 仅通告自研 TLS 状态机真实实现的能力，版本跟进通过离线审计工具（`utls-dump` + `scripts/audit-utls.py`）显式区分可立即改表同步的 `DATA DRIFT` 与须先补齐状态机的 `CAPABILITY GAP`，绝不靠拼假扩展凑 JA3/JA4。

## 2. 具名 HTTP 客户端连接池原则

- **响应体持有传输租约**：连接池 epoch / transport lease 的释放延后到响应体关闭完成，而非仅在响应头返回时释放；配置变更或连接重置时优雅退休旧 transport，不影响在途读取。
- **安全受限的协议竞速与回退**：HTTP/3 与 HTTP/2 竞速或 Alt-Svc 回退时，及时取消并关闭落败方响应；仅对满足幂等性或未发送证明的请求允许回退，按 authority 维护的失败记录必须有容量上限、过期时间并绑定 DNS/配置代次。

## 3. 出站策略组健康探测与防抖选路

为防止网络瞬时抖动引起节点反复横跳断流，自动选路（`url-test` / `fallback`）采用多维协同状态机：

1. **严格状态码与轻量探测**：支持配置预期 HTTP 状态码（如严格 `204`，拒绝 `200`/`403`/`502` 或截断响应并汇报 `last-status`）及 HTTP/2 `PING` 探测，且所有探活受独立截止时间约束。
2. **EWMA 延迟平滑**：采用指数加权移动平均平滑近期样本，防止单次丢包尖峰或后台大流量将健康节点误判下线。
3. **断路器冷却（Circuit Breaker）**：连续探测失败达到阈值后打开断路器进入冷却期，暂停将该节点纳入首选，避免业务反复撞击失效节点。
4. **滞后切换（Hysteresis）与最小间隔**：仅当候选节点显著优于当前节点且当前节点持续劣化、并满足最小切换间隔时才执行切换，杜绝相近延迟节点频繁抖动。
5. **诚实健康信号与手动覆盖隔离**：
   - 节点“可用”严格以真实穿过代理的端到端探活成功为准，不以“进程存活”替代网络连通；
   - 支持 `url-test` 临时手动覆盖（跨探活保持锁定、不污染持久化状态）及 `--auto` 一键恢复自动选优；
   - 探测在途若发生手动切组或配置换代，按代次/目标身份丢弃过时探活结果，防止串台。
