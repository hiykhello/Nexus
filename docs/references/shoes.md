## 协议处理与转发分离

`src/tcp/tcp_handler.rs` 用 `TcpServerSetupResult` 区分 TCP 转发、固定目标 UDP、多目标 UDP、按会话 UDP 与长期任务，并显式携带初始远端数据、成功响应和首次 flush 要求。

优点是握手结果描述后续所需工作，公共转发器承担数据移动，协议无需重复实现整套转发生命周期。Nexus 可用有标签的结果类型表达处理路径，以 `expected` 报告失败，用 facade 承载具体流/数据报能力。目标地址、初始数据及响应的发送顺序必须保持明确。

`src/async_stream.rs` 区分字节流、消息、目标地址、来源地址与会话标识，特别为 UDP 允许零长度数据报而非一律视为 EOF。Nexus 应提取这些语义边界，不将一切流量压成字节流接口。

## 双向转发的细节

`src/copy_bidirectional.rs` 的环形缓冲允许在剩余空间中继续读取，不需要每次移动剩余字节；先尽可能读取再写入，可减少某些按 write 次数分帧的协议开销。

该实现跟踪首次 flush、未完成 flush 和 ping，有限制的单轮字节配额，并接入 Tokio 协作预算，防止始终就绪的大流长期占据执行机会。两方向独立完成和半关闭，关闭阶段有超时，活跃读取方向没有被简单加上相同的固定寿命。

Nexus 提取原则：缓冲、flush、协议记录和半关闭均属于转发语义；每轮应有公平性预算。代码中的 16 KiB 缓冲、1 MiB 配额和关闭超时属于参考值，不是 Nexus 默认值。

## 可证明条件下切换加速路径

`AsyncStream::plain_tcp` 的契约要求后续 I/O 已成为裸 socket 操作，没有残留缓冲或包装副作用。`copy_bidirectional.rs` 在两方向缓冲、flush、ping 等条件满足后，才允许从普通路径切换到 splice。

Linux `src/splice.rs` 使用非阻塞管道及 `splice(2)`，通过资源许可限制管道数量。资源紧张或已识别的不支持错误走普通拷贝路径，处理管道内尚未发送数据，仍保留字节计数、半关闭与协作让出。

优点是优化资源耗尽不会天然变成连接必须失败的原因。Nexus 应定义可加速能力与转换屏障，不能仅看到两个原生 FD 就绕过 TLS、协议 framing、限速、计数或已有缓冲。

## 规则编译与索引

| 机制 | 源码 | 优点及 Nexus 可提取点 |
| --- | --- | --- |
| 小集合与大集合采用不同结构 | `src/rules/domain.rs` 的 `Names` | 快照中至多 16 项使用紧凑列表，较大集合使用 hash 索引；阈值应实测，不一律哈希化 |
| 规范化尽量借用原字符串 | 同文件 `normalize` | 只有需要大小写转换时才分配；查询规范化必须和规则编译保持一致 |
| 后缀按标签边界查询 | `Names::matches` | 枚举域名标签后缀并查集合，避免错误匹配字符后缀 |
| 合并 IP / 端口区间 | `src/rules/ip.rs`、`src/rules/compile.rs` | 编译时排序、合并，运行时查紧凑区间；明确 IPv4-mapped IPv6 语义 |
| 多关键字与正则预编译 | `compile_keywords`、`compile_regex` | 用专用匹配结构替代逐字符串处理，并限制编译与运行缓存成本 |
| Match / Miss / Unknown | `src/rules/mod.rs` 的 `Outcome` | 信息不足不是不匹配，组合与取反保留未知状态 |
| 源复用与预算 | `Compiler::sources`、`source`、`charge`；`src/rule_set` | 共享不可变谓词，对解码、编译临时占用和保留索引分别计量 |

全局策略仍有顺序。叶子集合索引提高成员查询效率，不意味着任意顺序的策略链都变成常数时间，不能为了合并索引改变首个命中语义。

## 缓存的适用条件

`src/client_proxy_selector.rs` 以规范化目标地址及端口为键，缓存规则索引或阻断结果；小规则数量时可不启用。读取使用 `peek` 避免更新顺序所需的写锁，但因此命中不会刷新 LRU 次序，不能称为严格按访问更新的 LRU。

源码明确 DNS 依赖与嗅探决策绕过该缓存。对 Nexus 而言，是否可缓存必须由规则依赖和失效策略决定：未来如使用来源、用户、进程、入口或其他上下文，不能沿用仅目标地址的键。缓存规则选择与缓存健康检查后的具体出口也要分别设计。

## 生命周期与资源预算

`src/process.rs` 区分加载校验、准备候选、激活、失败恢复与停止，`src/control/runtime.rs` 组织 generation 及控制命令。测试目录还覆盖重载期间旧连接、取消和候选失败行为。

可提取点是将候选状态与已发布状态分开，新连接使用新配置，存量连接所需对象保持有效。热重载目前尚未成为 Nexus 已实现或已冻结的能力，这里只保留未来设计参考。

`src/resources.rs` 用许可对象追踪连接、流和 QUIC 内存等预算，析构归还占用，调整限制时保留已存在的 reservation。优点是失败、取消和成功路径共享资源归还机制。Nexus 可以采用只移动 RAII 许可，并通过 `expected` 表达配额不足；不要照搬全局锁和固定限值。

## 包存储与事件唤醒

`src/ip_stack/packet.rs` 将存储所有权与可见范围分离，包头移除通过范围视图完成；当很小的载荷会长期持有大块存储时，主动紧凑复制。池同时限制对象数和可缓存容量。

这提示 Nexus：减少复制与减少驻留内存需要共同考虑，零拷贝并非任何载荷长度、排队时间下都更好。

`src/ip_stack/wake.rs` 合并唤醒通知，并将清除 pending 与消费共享工作的位置写入接口约定；`driver.rs` 用有界队列连接命令、包处理和用户任务。Nexus 应以确定性竞争测试验证无丢失唤醒，不能只凭吞吐测试认定同步正确。

## 对自研范围的区别

shoes 的 `src/ip_stack/mod.rs` 使用 smoltcp；`Cargo.toml` 固定了 smoltcp 与 rustls 等 fork 的提交。本次没有审计其全部密码学与传递依赖。因此不将 shoes 描述为完整 TCP/IP、TLS 都从零自写，也不据此证明它符合 Nexus 的 libcrypto 与 libssl 依赖边界。

其 Rust trait、`Box<dyn ...>`、Tokio poll 与运行时结构，转换为 Nexus 的 concept、ngcpp/proxy、Corosio 及明确所有权设计；不将 Rust 语法直接翻译为 C++ 架构。

## 性能证据方法也值得借鉴
